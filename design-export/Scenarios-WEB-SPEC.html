Scenarios /app/scenarios · десктоп — пиксель-в-пиксель

Сценарий — это повторяющийся или условный контент в вашем голосе по схеме КОГДА (триггер) → ЕСЛИ (условие) → СГЕНЕРИРОВАТЬ (пост/ответ) С ИНСТРУКЦИЕЙ поверх голоса. Это фундаментальный инструмент Pennedly, а не узкая фича: на нём строятся промо-кампании, регулярные рубрики, сезонные посты и любые свои автоматизации. Первый и главный шаблон — «Акция» (промо-кампания: просим что-то в комментах → присылаем отклик в ответ). Документ покрывает четыре экрана — Список, Выбор шаблона, редактор «Акция» и редактор «Свой» — одним проходом: живые фреймы (реальные DS-компоненты, светлая И тёмная темы), пронумерованная анатомия, все состояния, маппинг Web↔Mobile, локализация в 8 языков и чек-лист. Плейсхолдеры — кейс Сони (ежедневный мини-разбор по дате рождения), но фича generic.

Состояния одним взглядом. Четыре экрана. Список: список · пусто · загрузка (скелетоны) · ошибка. Выбор шаблона: Акция (готов) · Свой (готов) · Рубрика/Сезонное (скоро). Редактор «Акция»: новый/пусто · заполнен · превью-загрузка · превью-готово · сохранение · ошибка валидации · удаление-confirm. Редактор «Свой»: триггер/условие/действие/инструкция. Все сценарии OFF по умолчанию — включаются явно, кнопкой «Сохранить и включить» или тумблером в списке.
Куда встаёт таб «Сценарии». В группе Voice & automation, перед Autopilot, tester-gated. Логика: Scenarios = намерение (что и когда генерировать), Autopilot = исполнитель (общий мастер-рубильник постинга и авто-ответов). Сценарии задают повторяющийся контент; Autopilot решает, исполнять ли его автоматически. Иконка nav — петля-повтор (IcRepeat), не молния.

1Идентификация экрана

Маршрут, назначение, ширина, раскладка сверху вниз: sidebar | main(topbar + scroll(content)). Контент зависит от экрана: список карточек · сетка шаблонов · редактор (форма + липкий предпросмотр).

Маршрут/app/scenarios (список) · /app/scenarios/new (выбор шаблона) · /app/scenarios/:id (редактор). Пункт Scenarios в группе Voice & automation, перед Autopilot, tester-gated.
ТипПолный app-shell: <window.Sidebar active="scenarios"/>. Каркас 1:1 из Studio/Autopilot.
Назначение / тонПовторяющийся и условный контент в голосе автора. OFF по умолчанию; «вы у руля». Фундаментальный инструмент, не узкая фича.
Ширина контентаwide = --content-wide 960px. Топбар выровнен через .topbar-inner.topbar--wide.
ТопбарЗаголовок «Scenarios» + статус-pill: .status-pill--success «N активны» с живой точкой, если есть включённые сценарии; нейтральный «Все выключены» иначе. + действия: тема + Settings.
МодельКОГДА (trigger) → ЕСЛИ (condition, optional) → СГЕНЕРИРОВАТЬ (action) С ИНСТРУКЦИЕЙ поверх голоса. Шаблон — пресет этой схемы.
ШаблоныАкция (готов) · Свой (готов, advanced) · Рубрика / Сезонное (скоро). Каждый = каркас «когда→если→сгенерировать».
ИконографияСценарий — петля-повтор; Акция — подарок; Свой — слайдеры; Рубрика — колонки; Сезонное — ветка; авто-ответ — чат-бабл. Молний нет.
Фазы (state)loading (skeleton) · ready · empty · error (для списка и сохранения).
Backend-правдаВсе часы — UTC на сервере, показываются/выбираются в локальной TZ зрителя. OFF для всех по умолчанию. Worker исполняет включённые сценарии в рамках Autopilot-политики.

2Модель «Сценарий»

Каждый сценарий — это одно правило по схеме из четырёх частей. Шаблон лишь предзаполняет их понятными словами. Эта же схема показывается компактной строкой-.flowline на карточках и в шапке редакторов.

ЧастьЧто задаётПримеры значений
КОГДА triggerЧто запускает сценарий.Ежедневно · Раз в N дней · По времени (HH:00) · На новый комментарий · На упоминание
ЕСЛИ condition · optionalДоп. фильтр — сценарий срабатывает только если выполнено.Без условия · только подписчики · есть дата в тексте · тон позитивный · только будни
СГЕНЕРИРОВАТЬ actionЧто Pennedly создаёт.Пост · Ответ в комментариях · Тред
С ИНСТРУКЦИЕЙ instructionСпецифика поверх голоса — то, чего нет в общем Voice.«одна карта дня, 2–3 предложения, совет на день»
Шаблон «Акция» = пресет: КОГДА «ежедневно/раз в N дней» → ЕСЛИ «есть нужный ответ в комменте (+ подписка/лайк опц.)» → СГЕНЕРИРОВАТЬ «ответ-отклик» С ИНСТРУКЦИЕЙ как отвечать. Автор не видит сырую схему — он заполняет понятные поля «что просим / что даём».

3Экран 1 — Список сценариев

Заголовок «Scenarios» + кнопка «Новый сценарий». Ниже — список карточек. Каждая карточка: иконка-шаблон, название, бейдж шаблона, тумблер вкл/выкл, краткое описание триггера, «след. запуск» и «последний запуск», кнопка «Открыть». Полный экран — светлая и тёмная темы:

3.1 — Карточка сценария .sc-card

Включённый сценарий — иконка с success-тинтом, статус «Включён», заполненные «след. запуск/последний запуск». Выключенный — приглушён (opacity .78), «след. запуск» = «— на паузе».

Элемент / классОписание
.sc-card / --on / --offsurface; border; radius-lg; shadow-sm; padding 17/19. Hover → border темнее + shadow-md. Off → opacity .78.
.sc-card-icon40×40 (radius-md). Иконка шаблона. On → success-тинт.
.sc-card-name + .tpl-badgeНазвание (h3) + бейдж шаблона: Акция (accent-tint, подарок) · Свой (нейтральный, слайдеры) · Рубрика · Сезонное.
.sc-card-descКраткое описание механики/триггера одной строкой («Просим дату рождения → присылаем разбор в ответ»).
.sc-card-toggleСтатус «Включён/Выключен» + .switch. Тумблер вкл/выкл прямо в списке (toast на флипе).
.sc-card-foot · .sc-run ×2«след. запуск» (Завтра, 9:00 / «— на паузе») + «последний запуск» (Сегодня, 9:02 / «ещё не запускался»). tabular-nums, в локальной TZ.
.sc-card-actions«Открыть» (.btn--secondary.btn--sm) → редактор сценария.

3.2 — Пусто / Загрузка / Ошибка

СписокПустоЗагрузкаОшибка

Пусто — объяснение модели + четыре подсказки-шаблона + «Создать сценарий». Загрузка — скелетоны, повторяющие раскладку карточек. Ошибка — inline-баннер с «Повторить».

StateЧто рендерится
Пусто.sc-empty: mark-петля + «Пока нет сценариев» + объяснение «когда→если→сгенерировать» + чипы-шаблоны (Акция/Рубрика/Сезонное/Свой) + «Создать сценарий».
Загрузка.sc-skel-card ×3 — shimmer 1.4s, повторяет раскладку (иконка + тексты + тумблер + футер). aria-hidden.
Ошибка.sc-error — danger-tint баннер «Не удалось загрузить сценарии» + «Повторить». Работа в безопасности.

4Экран 2 — Выбор шаблона

Открывается по «Новый сценарий». Сетка карточек 2×2: Акция и Свой доступны; Рубрика и Сезонное помечены «скоро» (приглушены, не кликабельны). Каждая карточка — иконка, название, короткое пояснение и CTA «Выбрать».

ШаблонСостояниеПояснение
Акция 🎁готовПромо-кампания: просим что-то в комментах → присылаем отклик в ответ. Розыгрыши, лид-магниты, мини-разборы.
Свойготов · advancedПолный контроль над схемой когда/если/сгенерировать/инструкция. Для нестандартного.
РубрикаскороРегулярный формат по расписанию — «карта дня», «совет недели».
СезонноескороПривязка к датам/сезонам — праздники, годовщины, начало сезона.
Почему «Свой» доступен сразу, а Рубрика/Сезонное — позже. «Свой» — это прямой доступ к базовой схеме, он покрывает любые кейсы уже сейчас. Рубрика и Сезонное — это удобные предзаполненные пресеты той же схемы; они появятся, когда отработаем UX на «Акции».

5Экран 3 — Редактор «Акция» главный экран

Двухколоночный: слева форма (что за акция · когда запускать · как отвечать), справа липкий живой предпросмотр (собранный призыв-CTA + пример поста + пример отклика). На телефоне предпросмотр уходит под форму. Кнопки: Сохранить · Сохранить и включить · Удалить.

5.1 — Анатомия + живой предпросмотр

Элемент / классОписание
.sc-editorgrid; minmax(0,1fr) 380px; gap 22. ≤880px → 1 колонка, превью под формой (.sc-preview теряет sticky).
Форма · «Что за акция»Название · «Что просим написать в комментах» (плейсхолдер «свою дату рождения») · «Что даём взамен» («короткий мини-разбор прямо в комментах») · тумблеры «Требовать подписку» / «Требовать лайк».
Форма · «Когда запускать»Сегмент «Ежедневно (первым постом дня)» / «Раз в N дней»; во втором режиме — поле N + подсказка. Время в локальной TZ (UTC+1).
Форма · «Как отвечать»Многострочное поле — инструкция поверх голоса для каждого ответа в комментах.
.sc-preview · .sc-prev-ctaСобранный призыв — Pennedly формирует CTA из «что просим» + «что даём» (+ подписка/лайк). accent-tint.
.mockpost + .mockreplyПример поста (мок Threads: avatar/handle/текст/stats) + пример отклика: коммент с датой → авто-ответ бота (тег чат-бабл «авто-ответ»).
.sc-actionbar«Сохранить» (secondary) · «Сохранить и включить» (primary, ✓) · spacer · «Удалить» (ghost, есть только у существующего).

5.2 — Все состояния

Новый/пустоЗаполненПревью-загрузкаПревью-готовоРаз в N днейСохранениеОшибкаУдаление-confirm

Новый/пусто — поля пустые с плейсхолдерами, превью — пустое приглашение, «Удалить» скрыта. Заполнен/превью-готово показан выше (§5.1).

Превью пересобирается при изменении полей: пока считает — скелетон в панели превью; режим «Раз в N дней» — поле N в расписании.

Сохранение — кнопки со спиннером, заблокированы. Ошибка валидации — обязательное поле подсвечено + danger-баннер; удаление — inline-confirm «Удалить этот сценарий?» (Отмена / Удалить).

StateЧто рендерится
Новый / пустоПоля пустые (placeholders); превью = .prev-empty «Предпросмотр появится здесь»; «Удалить» скрыта.
Заполнен · превью-готовоВсе поля заполнены; .sc-prev-cta + .mockpost + .mockreply собраны; «Обновить» в шапке превью.
Превью-загрузка.prev-loading — shimmer-плейсхолдеры на месте CTA и поста.
Раз в N днейВторой сегмент активен; .sc-everyn с полем N («Каждые 3 дня — первым постом дня»).
СохранениеОбе save-кнопки со .spinner, aria-disabled.
Ошибка валидации.sc-field--err на «что просим» + danger-hint; .sc-error баннер «Не удалось сохранить».
Удаление-confirm.sc-delete-confirm inline: «Удалить этот сценарий? Действие необратимо.» + Отмена / Удалить (danger).

6Экран 4 — Редактор «Свой» advanced

Проще, чем «Акция»: один список из четырёх полей, прямо по схеме — КОГДА (триггер) · ЕСЛИ (условие, опц.) · СГЕНЕРИРОВАТЬ (действие) · С ИНСТРУКЦИЕЙ (поверх голоса). Справа — тот же липкий предпросмотр (для действия «Пост» — один мок-пост без механики откликов).

ПолеКонтролОписание

«Свой» — это «Акция» без обёртки. Те же четыре части модели, но автор задаёт их напрямую через селекты, а не через дружелюбные поля «что просим / что даём». Предпросмотр зависит от выбранного действия: «Пост» → мок-пост; «Ответ в комментариях» → механика коммент→ответ как в «Акции».

Это десктоп-спека. Полная телефонная раскладка — в Scenarios-MOBILE-SPEC.html. На десктопе ширина --content-wide 960; редактор — две колонки (форма + липкий предпросмотр). Брейкпоинты вниз: 880px (.sc-editor → 1 колонка, превью под формой) · 640px (tpl-grid 1 кол., card-foot стопкой, segment/action-bar full-width).

Десктоп ↔ телефон одним взглядом

Десктоп ( > 880 )

  • Фикс. сайдбар; колонка 960; статус-pill в топбаре.
  • Список: карточки full-width; футер в ряд (runs слева, «Открыть» справа).
  • Выбор шаблона: сетка 2×2.
  • Редактор: 2 колонки — форма + липкий предпросмотр (380px).
  • Удаление — inline-confirm в action-bar.

Телефон ( ≤ 600 )

  • Нет сайдбара/таб-бара; гамбургер → drawer; свободный нижний край.
  • Список: карточки full-width; футер стопкой; «Открыть» full-width; tap-target ≥44px.
  • Выбор шаблона: карточки в 1 колонку.
  • Редактор: форма, затем превью (не липкое); сегмент и кнопки full-width; inputs 16px.
  • «Новый сценарий» — основная кнопка в шапке; на узком уходит под заголовок.
Полный телефонный проход — отдельная спецификация Scenarios-MOBILE-SPEC.html (фреймы телефона 390px, bottom-sheet для confirm, 360px-проверка).

8Точные значения · backend-контракт

Эндпоинт / полеОписание
GET …/scenariosСписок: id, name, template (promo/custom/rubric/seasonal), enabled, trigger_summary, next_run_at (nullable когда off), last_run_at (nullable).
POST/PATCH/DELETE …/scenarios/:idСоздание/правка/удаление. PATCH …/enabled — тумблер из списка.
Модель сценарияtrigger (daily/every_n_days+n/at_time+hour/on_comment/on_mention) · condition (nullable) · action (post/reply/thread) · instruction (text).
«Акция» (promo) поляask (что просим) · reward (что даём) · require_follow (bool) · require_like (bool) · reply_instruction (text) · schedule (daily / every_n_days+n).
POST …/scenarios/previewВозвращает собранный cta + мок post (+ мок reply для action=reply). Дебаунс на изменение полей; пока считает — превью-скелетон.

Local ↔ UTC · значения

  • Все часы — UTC server-side, показываются/выбираются в локальной TZ зрителя; даты «след./последний запуск» — через локализованный форматтер (fmtDateTime, §3.10 shell).
  • OFF по умолчанию для каждого сценария. next_run_at = null когда выключен → «— на паузе».
  • «Сохранить» оставляет OFF; «Сохранить и включить» ставит enabled=true. Тумблер в списке — мгновенный, с toast.
  • Исполнение идёт под общей Autopilot-политикой (лимиты, проверки качества, лог, undo).

10Чек-лист реализации

  • Полный app-shell; активный пункт = Scenarios в группе Voice & automation, перед Autopilot, tester-gated; топбар «Scenarios» + статус-pill (success «N активны» + точка / нейтральный «Все выключены»); ширина --content-wide 960.
  • Иконография: сценарий — петля-повтор; Акция — подарок; Свой — слайдеры; Рубрика — колонки; Сезонное — ветка; авто-ответ — чат-бабл; молний нет.
  • Список: карточка = иконка-шаблон · название · бейдж шаблона · тумблер вкл/выкл · описание триггера · «след. запуск» · «последний запуск» · «Открыть»; off → приглушён + «— на паузе».
  • Состояния списка: список · пусто (объяснение модели + чипы-шаблоны + «Создать») · загрузка (скелетоны по раскладке) · ошибка (баннер + «Повторить»).
  • Выбор шаблона: Акция + Свой доступны; Рубрика + Сезонное «скоро» (приглушены, не кликабельны); каждая карточка — иконка, название, пояснение, CTA.
  • Редактор «Акция»: поля Название · Что просим · Что даём · тумблеры подписка/лайк · расписание (Ежедневно / Раз в N дней + N) · «Как отвечать» (многострочно); липкий живой предпросмотр (CTA + мок-пост + мок-отклик); кнопки Сохранить / Сохранить и включить / Удалить.
  • Состояния «Акции»: новый/пусто (превью пустой, без «Удалить») · заполнен · превью-загрузка (скелетон) · превью-готово · Раз в N дней · сохранение (спиннеры) · ошибка валидации (поле + баннер) · удаление-confirm (inline).
  • Редактор «Свой»: КОГДА (триггер) · ЕСЛИ (условие, опц.) · СГЕНЕРИРОВАТЬ (действие) · С ИНСТРУКЦИЕЙ; проще «Акции»; превью зависит от действия.
  • OFF по умолчанию для всех; «Сохранить» оставляет off, «Сохранить и включить» включает; тумблер в списке мгновенный (toast); next_run = null когда off.
  • Local↔UTC + локализованные даты; превью через дебаунс-эндпоинт; исполнение под Autopilot-политикой.
  • Корректно в светлой и тёмной теме; только семантические токены; копи выживает в 8 локалях; проверено на 360px; редактор collapse на ≤880 (превью под формой).
