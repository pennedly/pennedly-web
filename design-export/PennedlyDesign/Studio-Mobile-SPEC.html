Pennedly · Mobile spec · per-screen

Studio /app — phone

Studio is the biggest screen in the app, and on a phone the desktop content doesn’t fit — rows overlap and clip. This spec lays it out cleanly at 390px (sanity-checked at 360) with no overlap, using the decided mobile shell: a single slim top bar with a hamburger that opens a left navigation drawer. There is no bottom tab bar, so the bottom edge is free for content. Same tokens, states, flows and copy as the desktop spec — only the layout adapts below 600px. Every frame is the real component layer rendered at 390px, light and dark.

pennedly-mobile.css studio-app.jsx studio-parts.jsx shell-parts.jsx ds/tokens.css
What does not change. The brief → generate → review → approve → publish flow, the 500-char limit, the four status filters (Ready / Drafts / Published / Rejected), per-status card footers, tweak-in-your-voice, on-demand translation into the 8 UI locales, the confirm-before-publish step, and reply-drafts being read-only here — all identical to desktop. Mobile is a layout pass; the only structural change is the app shell (tab bar → hamburger drawer), which is shared by every screen.

1Screen identity

Studio is a full app-shell screen. On desktop it renders the 248px sidebar + a 960px content column. On a phone the sidebar collapses behind the hamburger, the nav lives in a left drawer, and the column goes edge-to-edge with a 14px gutter. Nothing is pinned to the bottom — the feed scrolls all the way to the device edge.

2The phone layout

The whole screen in context, light and dark. The top bar carries the hamburger, the title, the voice-state pill and the theme toggle; the filter row sticks directly under it; the feed runs to the free bottom edge.

3shellShell: top bar + drawer

The shell is shared by every screen (see DS · App shell & nav). It is one slim 52px bar; tapping the hamburger slides the drawer in from the left over a scrim. Studio-specific shell values:

SlotStudio value
HamburgerFar left, 40px box in the 52px bar (≥44 hit area). Opens .m-drawer.
Title“Studio” (text-h3). Truncates with ellipsis before the pill on long locales.
Status pillstatus-pill--success “Voice active”, or --warning “Voice not set up” in first-run.
Top-bar actionTheme toggle only (40px). The account is not in the bar — it lives at the foot of the drawer.
Drawer contentsBrand header, the full grouped nav (Workspace / Insight / Voice & automation) with live badges, active row = Studio, and the account control pinned to the foot (opens the account switcher).
Sticky filterThe filter bar (.m-filterbar) sticks at top:0 inside the scroll, i.e. directly under the top bar.
Tester gatingReplies · Mentions · Autopilot rows are tester-gated (shown here; hidden for non-testers — the groups simply shrink).
Drawer rules. Width min(82%, 312px), full-height, slides from the left over a blurred scrim (tap scrim or ✕ to dismiss). It reuses the shared nav-row styling; the active row gets a left accent rail. The account control at the foot opens the same account sheet used elsewhere — switch account, connect another, Settings, Log out. Nothing about navigation is invented here; the drawer simply re-homes the desktop sidebar.

4fixComposer — the mobile fix

On desktop the composer’s avatar, chips, draft-count and Generate share one row. Squeezed into a phone that row breaks. The mobile composer is a clean vertical stack.

Before

Chips shrink into a cramped column, “Generate” floats right with dead space between, the placeholder clips, and the avatar steals width.

After

Avatar dropped to reclaim width. Full-width textarea (placeholder fully visible). Chips in a horizontally scrollable row at full size. A full-width footer: draft-count select + Generate (grows, 44px).

Rules. Textarea min-height 58px, auto-grows. Chip row is overflow-x:auto; flex-wrap:nowrap with a right-edge mask fade; chips are flex:0 0 auto (never crushed). Footer select is 16px text (no iOS zoom), Generate is disabled until the brief is non-empty. Busy state swaps the whole body for the nib animation + “Drafting N posts in your voice”.

8First-run · publish sheet · toast

First-run replaces composer+feed with the welcome hero and flips the voice pill to warning. The publish confirm becomes a bottom sheet (stacked full-width actions, primary on top). Toasts pin to the bottom edge — there is no tab bar to clear — with Undo.

10Web ↔ mobile

Desktop ( > 900 )

  • Fixed 248px sidebar; account control at its foot opens upward.
  • 960px centered column; topbar aligned to it.
  • Composer: one row — avatar + chips + count + Generate.
  • Card foot: meta left, ⋯ + one primary right, single line.
  • Filter bar: 4 tabs in a row; labels always shown.
  • Publish: centered modal dialog.

Phone ( ≤ 600 )

  • No sidebar, no tab bar — one top bar; hamburger → left nav drawer + account.
  • Edge-to-edge column, 14px gutter; free bottom edge.
  • Composer: vertical stack — textarea / scrolling chips / footer.
  • Card foot: two-tier — meta line, then grow-primary + 44px ⋯.
  • Filter bar: horizontally scrollable, labels kept.
  • Publish: bottom sheet, stacked full-width actions.

11Localization & 360px

All Studio strings localize into 8 locales; DE/RU/UK run ~30–40% longer than EN. Nothing assumes English label widths: the Generate label and per-status primaries wrap to a second line rather than clip or push the ⋯ off-screen; chips, suggestions and filters scroll horizontally; the title truncates before the pill; nav labels in the drawer wrap. Never bake a label into an image.

360px behavior. At the narrow end the same rules hold with no new breakpoint — the gutter stays 14px, the composer/cards just get ~30px narrower. The chip row, suggestion row and filter bar already scroll, so they absorb the loss. The only visible change: long primary labels are slightly more likely to wrap to two lines (still ≥44px, still readable). The drawer stays min(82%, 312px), so on 360 it’s 82% (≈295px) and the scrim shows a sliver of the screen behind it.

12Checklist

  • Below 600px there is no sidebar and no tab bar — one 52px top bar with a hamburger far-left.
  • Hamburger opens the left drawer; drawer holds the full grouped nav (active = Studio) + the account at its foot.
  • Bottom edge is free — content/feed scrolls to the device edge; toast pins to the bottom, not above a bar.
  • Composer is a vertical stack; chips scroll horizontally; placeholder never clips.
  • Generate is full-width-grow, 44px, disabled on empty brief; footer select is 16px text.
  • Every card foot is two-tier; exactly one labelled primary; the ⋯ is 44×44 and holds all secondary actions.
  • Sub-states fit the phone: editing (16px textarea + meter), tweak (input + scrolling suggestions), revising (skeleton), translated (Show original), reply = read-only.
  • Primary labels wrap to a 2nd line on long locales — never clipped or shrunk; sanity-checked at 360px.
  • Filter bar scrolls and sticks under the top bar; counts correct.
  • Loading = 3 skeletons; empty is per-filter; error banner has Retry; all reachable via state.
  • Publish confirm is a bottom sheet; actions stacked full-width; primary on top.
  • Correct in light and dark; no hardcoded colour.
