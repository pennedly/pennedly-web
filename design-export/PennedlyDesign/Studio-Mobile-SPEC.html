Studio /app — phone

How the largest screen in the app behaves on a phone. Same content, states, flows and tokens as the desktop spec — only the layout changes below 600px. This is the canonical reference for the shared mobile shell, the composer fix, and the card-foot pattern; Feed and Replies reuse both. Every frame is the real component layer rendered at 390px, light and dark.

pennedly-mobile.css studio-app.jsx studio-parts.jsx shell-parts.jsx ds/tokens.css
What does not change. The five Studio tweaks (account, state, drafts, dark, density), the brief → generate → review → approve → publish flow, the 500-char limit, per-status footers, the confirm-before-publish dialog, the 8 translation locales — all identical to desktop. Mobile is a layout pass only.

1Screen identity

Studio is a full app-shell screen. On desktop it renders the sidebar + a 960px wide content column. On a phone the sidebar is replaced by the mobile shell (top bar + bottom tab bar + “More” drawer) and the column goes edge-to-edge with a 14px gutter.

Phone width100% − 14px gutters. No max-width; the column fills the device.
Top→bottom (phone)Status bar (OS) → top bar → [ composer → filter tabs → feed ] OR first-run hero → bottom tab bar. Overlays: publish sheet, toasts, More/account sheets.

4fixComposer — the mobile fix

On desktop the composer’s chips, draft-count and Generate share one row. Squeezed into a phone that row breaks. The mobile composer is a clean vertical stack.

Before

Chips shrink into a cramped left column, “Generate” floats to the right with dead space between, the placeholder title clips, and the avatar steals width.

After

Avatar dropped to reclaim width. Full-width textarea (placeholder fully visible). Chips in a horizontally scrollable row at full size. A full-width footer: draft-count select + Generate (grows, 44px).

Rules. Textarea min-height 58px, auto-grows. Chip row is overflow-x:auto; flex-wrap:nowrap with a right-edge mask fade; chips are flex:0 0 auto. Footer select is 16px text (no iOS zoom), Generate is disabled until the brief is non-empty. Busy state swaps the whole body for the nib animation + “Drafting N posts in your voice”.

9Web ↔ mobile

Desktop ( > 900 )

  • Fixed 248px sidebar; account menu at the foot opens upward.
  • 960px centered column; topbar aligned to it.
  • Composer: one row — chips + count + Generate.
  • Card foot: meta left, ⋯ + one primary right, single line.
  • Filter bar: 4 equal tabs; labels hidden only below 560.
  • Publish: centered modal dialog.

Phone ( ≤ 600 )

  • No sidebar; top bar + bottom tab bar + “More” / account sheets.
  • Edge-to-edge column, 14px gutter.
  • Composer: vertical stack — textarea / scrolling chips / footer.
  • Card foot: two-tier — meta line, then grow-primary + 44px icons.
  • Filter bar: horizontally scrollable, labels kept.
  • Publish: bottom sheet, stacked full-width actions.

10Localization

All Studio strings localize into 8 locales; DE/RU/UK run long. On a phone: the Generate label and per-status primaries wrap rather than clip; chips and filters scroll; the title truncates before the pill; the tab label “Studio” is short in every locale but “Mentions”/“Replies” may truncate (icon stays). Never bake a label into an image.

11Checklist

  • Below 600px the sidebar is gone; top bar (52) + tab bar (58 + safe-area) present.
  • Composer is a vertical stack; chips scroll horizontally; placeholder never clips.
  • Generate is full-width-grow, 44px, disabled on empty brief; footer select is 16px text.
  • Every card foot is two-tier; exactly one labelled primary; ⋯ and secondaries are 44×44.
  • Primary labels wrap to a 2nd line on long locales — never clipped or shrunk.
  • Filter bar scrolls and sticks under the top bar; counts correct.
  • Loading = 3 skeletons; empty is per-tab; error banner has Retry; all reachable via state.
  • Publish confirm is a bottom sheet; actions stacked full-width; primary on top.
  • Toast sits above the tab bar; Undo reachable.
  • Correct in light and dark; no hardcoded colour.
