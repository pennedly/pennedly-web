Replies /app/replies — phone

Read a comment, draft a reply in your voice, edit, approve, publish — all inside the card. Same workflow, statuses and translation as the desktop spec; only the layout changes below 600px. The draft state packs three actions (Regenerate · Edit · Approve), so this is the second proof of the shared two-tier foot. Frames are the real component layer at 390px, light and dark.

pennedly-mobile.css replies-app.jsx replies-card.jsx shell-parts.jsx ds/tokens.css
What does not change. The new → generating → draft → approved → replied lifecycle, skip/restore, the 500-char reply limit, comment- and reply-translation, the threaded reply block, and loading/empty/error states are all identical to desktop. Mobile is a layout pass only.

4fixComment-card foot — the fix

Before

The draft state lines up Regenerate · Edit · Approve as three equal buttons. Squeezed onto a phone they shrink below a comfortable tap size and the labels start to clip.

After

One primary per status grows to fill the row at 44px; the rest collapse to 44×44 icon buttons. Draft → Regenerate + Edit icons, Approve grows.

Primary + collapsed actions per status:

6Edit & translate

9Web ↔ mobile

Desktop ( > 900 )

  • 960px column; post-selector rail.
  • Draft foot: Regenerate · Edit · Approve as three buttons in a row.
  • Reply thread indented; edit inline.

Phone ( ≤ 600 )

  • Edge-to-edge; post grouping is a sticky header.
  • Draft foot: Regenerate + Edit icons (44px) + Approve grow-primary.
  • Reply thread keeps the left rule; edit textarea is 16px.

10Localization

Comments arrive in any language (translate inline); the reply UI localizes into 8 locales. On a phone: status tags (“drafted in your voice”, “approved · ready to publish”) wrap under the “You” line; the primary (“Publish reply” / “Generate reply”) wraps rather than clips; the translate toggles wrap. Author names and handles truncate with ellipsis.

11Checklist

  • Draft foot = Regenerate + Edit at 44×44 + Approve grow-primary; nothing under 44px.
  • Each status maps to exactly one primary per the table; labels wrap, never clip.
  • Reply thread keeps the left rule; replied block is success-tinted.
  • Edit textarea is 16px with the accent ring; char meter present; Cancel + Save.
  • Comment + reply translate toggles work and wrap.
  • ✕ remove stays a reachable target on the head.
  • Generating shows the skeleton reply + nib note; loading/empty/error reachable.
  • Tab present for testers; bar collapses to 3 for non-testers.
  • Correct in light and dark; no hardcoded colour.
