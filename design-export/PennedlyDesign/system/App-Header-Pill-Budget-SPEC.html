Bar pill — the length contract

132px was a budget for a sentence, and no sentence budget survives eight locales plus an unbounded counter. The fix is not a smaller budget — it is a different shape. A bar pill is a glyph and a number; it carries no translated words at all, so its width stops being a function of language. The ceiling drops from 132px to 81px and holds in every locale at every counter, forever. ← placement spec

1Why trimming fails

Your 58/120 failure rate is not a translation-quality problem. It is arithmetic: the pill has ~93px of text room, and the shape count + verb phrase needs a verb phrase. Even English "6 need a reply" is 136px once the counter reaches three digits. Every trim you pick today is a bet that no account ever crosses 99.

2The rule

A bar pill is one glyph and one number. It contains no translated words.
The glyph carries the noun. The number carries the payload. The full localized sentence lives in aria-label and in the desktop tooltip, so nothing is lost — it is simply not rendered in a 335px row. A pill with no number to show is a glyph alone. A pill with neither is not a pill and does not appear.

The reason this works — and the reason it is not information loss — is the slot order the placement spec already shipped. The pill sits immediately before the title, so pill and title are read as one phrase:

"128 need a reply" was restating the screen the user is already on. The screen name is 10px to the right, at 19px/600, in their language. The pill only ever had to supply the number and the alarm level — which is exactly what a coloured glyph and a numeral do.

What this buys, in numbers. Widest possible pill drops 132 → 81px. Typical pill 58px. The docked title's slot at 375px grows from 93px → 137px worst case, 167px typical — so titles that truncate today ("Відповіді", "Erwähnungen", "Übersicht") render whole. And the CI assertion becomes trivial: pill content must match /^(\d{1,2}\+?|\d{1,2}\/\d{1,2}|[+−]\d{1,3}%)?$/ — a regex, not a font measurement in 8 locales.
Rejected — shrink type to 11px and keep prose. Buys ~15%; uk still overflows on 6 of 10 pills, and 11px sits below the app's smallest shipped size. It also fails again the first time a counter gains a digit, which is the failure mode you already have.
Rejected — per-locale short strings ("6 unans.", "6 offen"). Abbreviated Cyrillic and German are unreadable, the abbreviations need review in 8 languages on every copy change, and the shape still scales with the counter. It converts a structural problem into permanent translation debt.

3Three categories, one test

The ten pills are not one kind of thing. Sort them first, then apply the shape rule to whatever survives.

CategoryTestRenders asRationale
A · Acted-on state Does a number in it change, and does a change mean the user should do something? Bar pill — glyph + number The only category worth a permanently-visible, scroll-independent slot. "6 need a reply", "4 to review", "4 active", "2 conflicts", "4/6 on".
B · Freshness metadata Is it about when the data was fetched rather than what is in it? Never a pill. Toolbar row, or hero meta line (§7) Ambient. Nobody scrolls up to check it, so it does not need the sticky slot — which is the entire justification for being in the bar. This generalises §6 from two strings to all of them.
C · Static screen labels Is the string identical on every visit, for every account, forever? No pill at all. Hero subtitle or body copy A pill's visual grammar promises liveness. A constant in a live-status chip is a lie the user learns to ignore — and it costs the most width of any category ("Grounded in your portfolio": 257px in uk).
The one-line test, for anyone adding a pill later: "Can I write it as a glyph and a number, and would a change in that number make the user act?" Yes → bar pill. No → it is copy, and copy belongs in the hero or the toolbar, where it has a full row and never truncates.

max-width: 88px is a guard, not a truncation point. Content is bounded by construction — the abbreviation rules in §5 make 81px the arithmetic maximum, so the guard sits 7px clear of the widest possible pill and should never engage. That headroom is deliberate: it absorbs font-metric drift (a CI fallback face, a different Geist subset) without clipping. If it engages, a pill is rendering a word: that is a bug, and the CI regex in §11 catches it before layout does.

5Counters — 1, 2 and 3 digits

Abbreviation threshold: literal to 99, 99+ at 100 and above. Never 999+, never 1.2k. Three glyphs is the cap, so the widest counter pill is 66px, permanently.

The threshold is not arbitrary. Past ~99 these counters stop being quantities and become "a lot" — a user with 128 unanswered comments and one with 340 take the same action, and neither counts them. Capping at two digits keeps the number in the range where it changes behaviour, and it is what makes a fixed budget survivable rather than a bet on your users staying small.

8.1 · Glyph assignment

Every glyph is an existing export from system/studio-icons.jsx, cited by name below — do not substitute a same-named icon from another set, since the 14px distinctness argument depends on these exact paths. Exactly one glyph is new and must be added to that file before this ships: IcToggle. All are drawn on the shared 24 viewBox, currentColor, no fills except the two dots.

One permitted override. The set's shared <Svg> wrapper hard-codes stroke-width="1.8", tuned for its 18px default. At 14px that reads optically lighter than the rest of the bar, so the pill sets stroke-width: 2 in CSS (a presentation attribute, so the stylesheet wins without touching the components). Round caps and joins are inherited unchanged.

10Phone vs desktop

The pill ships on the phone. There is no md: gate, on any screen. Remove the existing one on /app/advisor — which is moot anyway, since that pill is refused outright (§8).

The precedent for hiding it below md was a 135px prose pill against 93px of room; the pill was hidden because it did not fit, not because the phone did not want it. At 50–66px it fits with 157px left for the title — more than the phone has today without a pill under the old geometry. And the phone is where the pill matters most: it is the only place a user cannot see the sidebar's badge counts, so the bar is their sole ambient signal that something needs attention.

11Checklist

  • One shared <HeaderPill glyph tone count label> component; label is required and goes only to aria-label + title, never to the DOM text.
  • Component throws in dev if its rendered text contains a non-[0-9+/%−] character.
  • CI assertion, all 8 locales: /^(\d{1,2}\+?|\d{1,2}\/\d{1,2}|[+−]\d{1,3}%)?$/.test(pill.textContent.trim()) — replaces per-locale width measurement.
  • CI assertion: pill.offsetWidth ≤ 88 on every screen, en + de + uk, counters forced to 1 / 42 / 128 / 99/99.
  • Counter formatter: n > 99 ? "99+" : String(n). Ratio operands clamped to 99 each. No k/M abbreviations anywhere.
  • font-variant-numeric: tabular-nums on the pill — verify the shipped Geist subset includes tnum.
  • IcToggle added to system/studio-icons.jsx and exported; every other pill glyph references an existing name from that file (§8.1) — no inlined one-off paths.
  • Pill glyphs render at 14×14 with stroke-width: 2 via CSS, not by editing the shared <Svg> wrapper.
  • Three refusals deleted from the string catalogue: acc.adv_pill, agent.pill, mr.pill — remove the keys in all 8 locales, do not leave them orphaned.
  • scenarios.all_off and replies.all_handled deleted; both become states of their counter pill.
  • Freshness strings removed from every bar. Toolbar row on feed / mentions / routines / voice; hero meta line on overview / stats.
  • Hero meta line added: margin-top:8px; font-size:13px; color:var(--color-text-subtle); display:flex; flex-wrap:wrap; gap:4px 8px; opacity:calc(1 - var(--hdr-reveal)).
  • md: visibility gate removed from the advisor pill; no screen gates the pill by breakpoint.
  • Interactive pills (voice_not_set) are <button> with a 44×44 hit area; static pills are <span role="status" aria-live="polite">.
  • Regression: pill getBoundingClientRect().left === 70 (phone) / 24 (desktop) at scrollTop 0 and 200, every screen.
  • Regression: bar offsetHeight === 52 / 60 with the counter at 1, 42 and 128.
  • Verified dark + light, en/de/uk, 360 / 375 / 768 / 1280.
