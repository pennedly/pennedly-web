Compact bar — pill placement

The docking header shipped with the title slot before the pill and flex: 1 1 auto, so at rest the invisible title still reserved its width and shoved the pill into the middle of an empty bar — or onto a second row. Fix: swap the slot order. Nothing animates, nothing reflows, no new styling. ← parent spec

2The resolution

The compact bar's leading slot — the exact x-position the old bar title used to start at — belongs to the status pill, permanently. The docked title fades in to the right of the pill, into space that is empty at rest anyway. Nothing ever moves horizontally: at rest, mid-dock and docked, the hamburger, the pill and the action icons are at identical coordinates. Only the title changes opacity + 6px translateY on the existing --hdr-reveal 0→1 ramp.

This is the brief's option (a) with the motion cost driven to zero. Reserving width was never the requirement — not reflowing was. Putting the growing element last achieves that without reserving anything: the title slot is flex: 1 1 auto; min-width: 0, so its box already spans the leftover space at every reveal value; only its ink appears.

Reading order when docked: ☰ · ⬤ Все разобрано · Ответы · ⚙︎. Status-before-name is deliberate — the pill is the volatile thing the user scrolled up to check, the title is the anchor they already know. It also means the pill's position is locale-independent and screen-independent: on every screen in the app the pill starts at the same x.
Rejected — pill moves on dock. Sliding the pill right by the title's measured width couples a 60–120px horizontal translation to 32px of scroll (a 3:1 amplification). It needs per-locale width measurement, it re-runs on every font swap and every live pill text change ("6 ждут ответа" → "Все разобрано" would jump the title), and it makes the one element carrying live state the one element that never sits still.
Rejected — pill lives in the hero and appears in the bar only when docked. Two instances of one live value, crossfading; at reveal 0.5 both read at 50% opacity, which is precisely the "unreadable at some scroll position" the constraints forbid.
The one composition change this forces: a pill only fits the leading slot if it is short-form. Anything longer than 132px at 12px/500 (~14 Cyrillic characters) is not a bar pill — it is a freshness line and lives in the screen's persistent toolbar row instead. See §6. This affects exactly two strings: Mentions' "Обновляется ежечасно" and Feed's "Обновлено только что".

3Slot order & box model

#SlotFlexNotes
1Hamburgerflex:0 0 32px<768px only. Absent ≥768px — every downstream slot shifts left by 42px (32 + 10 gap), which is the existing breakpoint behaviour.
2Status pillflex:0 0 auto, max-width:132pxMoved here from position 3. Never shrinks, never truncates, never reacts to --hdr-reveal. Omitted entirely on screens with no pill — slot 3 then starts at the pill's x.
3Docked titleflex:1 1 auto; min-width:0Moved here from position 2. Ellipsis-truncates. Opacity + translateY only. Box is full-width at all reveal values, so revealing it reflows nothing.
4Action iconsflex:0 0 auto; margin-left:autoTheme, settings. margin-left:auto pins them right independently of slot 3's content, so an empty title never lets them drift left.

Row-level: flex-wrap: nowrap is mandatory and is what makes the 106px height structurally impossible — the bar is a fixed height:52px / 60px box with a single non-wrapping row.

5Long-locale stress — 360px

360px (Galaxy S8/S20) is the narrowest supported width. Budget: 360 − 28 padding − 32 burger − 10 − 132 pill max − 10 − 70 icons = 78px minimum title width — enough for the longest docked title in any locale to read at least 6–8 characters before the ellipsis, and enough for every actual title (Ответы 62px, Лента 48px, Обзор 55px) to fit whole.

They are also categorically different from Replies' pills: they are ambient metadata about the data set, not a state the user acts on. They move to the screen's persistent toolbar row — which is full-width, scroll-independent, and already exists on both screens.
