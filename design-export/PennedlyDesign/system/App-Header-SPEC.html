Unified App Header

Fixes the duplicate-title bug (compact top bar + hero <h1> showing the same text at once, on every authenticated screen). One shared header component, one rule, applied app-wide.

1The rule

Page identity (title + optional subtitle) renders once — as an in-flow hero at the top of the scrollable content. The sticky top bar never shows identity text at rest. As the hero scrolls up and out from under the bar, the bar docks the exact same title string — so at any scroll position exactly one instance of the title is ever visible. Functional chrome (hamburger, status pill, theme/settings icons, and any persistent toolbar row like a sort bar or a range‑stepper) always lives below/in the bar and is scroll‑independent — it never disappears and never duplicates.
This is one mechanism at every viewport width — desktop and phone are not two separate fixes. The only breakpoint-gated piece is the hamburger icon itself (hidden ≥768px, where the persistent sidebar nav takes over) — that already exists today and is unrelated to this bug. The collapse distance, the reveal formula, the docked-title typography and the hero typography are identical numbers whether the viewport is 360px or 1440px; only horizontal padding and the compact bar's 52→60px height step (both already existing, pre-this-fix values) scale with the existing breakpoint.

Why this over the two obvious shortcuts: deleting the hero would silently drop real subtitle content (Calendar's account line, an audit's specific name) that the brief says must keep a home; deleting the compact title would leave the bar looking broken once the hero scrolls away with nothing to anchor the user. Docking is the one move that keeps both jobs — bar owns wayfinding at all times, hero owns identity at rest — without ever showing the word twice.

2Anatomy

Order (top → bottom).hdr-compact (sticky) → scrollable content starts with .hdr-hero (title + subtitle) → optional .hdr-toolbar (sort bar / segmented control / range‑stepper — unchanged from what each screen has today) → page content.
.hdr-compactSticky, top:0. Holds: hamburger (mobile only) → optional status pill (always opacity 1, leading slot) → title slot (opacity/translate driven by scroll, see §4) → action icons (theme, settings — always opacity 1, margin-left:auto). Pill before title — see Pill Placement §3.
.hdr-heroIn‑flow, first thing in scrollable content. <h1> + optional <p> subtitle. Fades out (opacity only) as the bar's docked title fades in — never truncates, wraps instead.
.hdr-toolbarWhatever functional row that screen already has (Feed's sort bar, Calendar's range‑stepper, a filter bar). Not part of the collapse — stays in‑flow exactly where it is today. This spec only touches the title, not this row.

5States to support

  • At-rest (scrollTop 0): hero fully visible; compact bar shows hamburger + pill (if any, at the leading edge) + actions only. The title slot follows the pill and is invisible — its box spans the leftover width, but it reserves nothing ahead of the pill.
  • Collapsed (scrollTop ≥ 32px): hero at opacity 0 (scrolled out of view in normal flow anyway); compact title fully docked.
  • Mid-scroll: linear crossfade, no jump, no double-render — never both at full opacity simultaneously.
  • With status pill: pill present in both states at the leading edge, identical x at every reveal value, unaffected by reveal.
  • Without status pill: the title slot starts at the pill's x; no layout change elsewhere.
  • With hero subtitle: subtitle fades with the hero, has no docked equivalent — it is supplementary, not identity, so it is allowed to simply scroll away.
  • With a persistent toolbar row: unaffected by reveal, stays exactly where it is today.
  • 360–390px width, long locale (ru/de): compact title ellipsis-truncates before ever pushing into the pill or action icons; hero title wraps to 2 lines instead of truncating.
  • Audit detail: hero renders the specific audit's title verbatim; compact bar docks that same string (single source — never a separate hardcoded section label).

7Implementation checklist

  • One shared header component (.hdr-compact + .hdr-hero) used by all 12 screens — no per-screen forks.
  • Compact bar title text is always identical to the hero's <h1> text — bound to one source, never a second hardcoded string.
  • Reveal driven by scrollTop of the screen's own scroll container, clamped 0–1 over 32px, written to --hdr-reveal.
  • Compact title: opacity + 6px translateY only; hero: opacity only. No layout shift, no width change, no reflow of pill/icons — and flex-wrap:nowrap on the bar so the pill can never drop to a second row.
  • Status pill and action icons never react to scroll; hamburger/back nav never disappears.
  • Toolbar rows (sort bar, range-stepper, filters) untouched — still in-flow, still exactly where they are today.
  • 360–390px: compact title ellipsis-truncates; hero wraps; verified in ru/de (longest locales).
  • prefers-reduced-motion: reveal snaps at 16px scrollTop, opacity-only.
  • Audit detail binds hero + docked title to the specific audit's title, not a generic "Audits" label.
