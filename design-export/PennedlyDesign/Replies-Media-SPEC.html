Pennedly · Spec · Replies — reply composer media

Reply media /app/replies — image now, richer soon

Each comment card answers a comment with an inline reply draft. Today the reply is text-only; this spec extends the answer box with a compact media affordance — deliberately lighter than the post composer, because a reply is a quick, contextual answer that lives inside a comment card. A single “Add image” chip joins the existing action row (Regenerate / Edit / Approve / Send) — no second toolbar — and one thumbnail renders inside the reply block, above the send action, so the comment never scrolls away. Video / carousel / GIF are drawn as the intended end-state but shown gated (“pending API verification”), never as working. No audio. Every state for the web reply column and phone 390px, light and dark.

What stays the same. The comment head, comment body + translate, the threaded reply block (drafted in your voice), and the action row (Generate / Regenerate / Edit / Approve / Publish) are unchanged. The image chip slots into that same row; the thumbnail sits inside the reply block. Tokens, motion and the calm/editorial language carry over; mobile keeps ≥16px inputs and ≥44px targets.

0Where the affordance goes

One compact chip in the existing action row; when an image is attached, a single thumbnail renders inside the reply block — above the send action, so the comment being answered stays visible. No extra toolbar, no heavy composer.

＊New icons needed

The affordance reuses the existing set (IcX, IcCheck, IcChevDown, IcClock for the “soon” tag, IcTweak, IcPencil, IcNib). Only IcImage is genuinely new for Replies; IcVideo / IcGif are shared with the Studio compose spec, and Carousel reuses the existing IcLayers. “ALT” is a text label, not an icon.

Usage. IcImage — the live “Add image” chip + thumb placeholder. IcVideo / IcGif / IcLayers — the gated rows only. The gated Soon tag reuses IcClock. No new tokens.

1Text-only → the affordance

Today’s reply is text-only. The extension adds a single Image chip to the action row plus a gated More (with a subtle accent dot) — integrated, not a second toolbar.

2Image — the live type

An “Add image” chip → picker → one thumbnail with remove (×) and an ALT affordance (empty vs filled). Scoped to a single image — a reply is a quick answer. States: empty · uploading % · attached · alt-filled · error (JPEG/PNG/WebP, ≤8 MB).

— alt-text sheet

A small per-image sheet to add an accessibility description. Empty trigger on the thumb (“ALT”); once set, the chip turns success-green with a check.

3Gated: video / carousel / GIF

These are designed but not live — we must confirm Threads accepts them in a reply before enabling. The UI draws the intended end-state while making it obvious they aren’t working yet: a More reveal listing them with a “Soon” tag + a “verifying support” note, or inline disabled chips with the same note. On phone, the attach becomes a full-width sheet — Photo is live, the rest gated.

Never presented as working. The gated types are always disabled with a “Soon” tag and a plain note: “Image works in replies today; video, carousel & GIF arrive once we confirm Threads accepts them in a reply.” The chip never silently fails.

＊Motion, a11y & guardrails

Motion & a11y

  • Upload progress rings stop animating under prefers-reduced-motion: reduce; the % stays.
  • Every attached image exposes an ALT affordance; empty vs filled (success + check) is obvious.
  • Controls (remove, ALT, image chip) carry aria-label; gated rows are disabled (not just dimmed).

Guardrails

  • Single image is the only live reply media — video/carousel/GIF are visibly gated, never working.
  • No audio attach anywhere.
  • Compact: one chip + one thumb; the comment context is never pushed off-screen.
  • The existing generate / approve / send flow is unchanged.

✓Checklist

  • Image chip lives in the existing action row — no second toolbar; the reply flow (generate / approve / send) is unchanged.
  • One thumbnail renders inside the reply block, above the send action; the comment stays visible.
  • Image states: empty · uploading % · attached · alt-filled · error (JPEG/PNG/WebP, ≤8 MB); scoped to a single image.
  • Per-image remove (×) and ALT (empty trigger → filled success+check) via a small sheet.
  • Video / carousel / GIF are drawn but GATED — disabled + “Soon” tag + “verifying support” note (More reveal or inline chips).
  • Phone: action row keeps 44px targets; the picker is a full-width sheet (Photo live, rest gated); thumb is a comfortable tap target with easy remove.
  • No audio attach anywhere.
  • Rendered for the web column AND phone 390px, light AND dark; mobile inputs ≥16px.
  • New icon (image) flagged for icons.tsx; video/gif shared with compose, carousel reuses IcLayers, “soon” reuses IcClock; no new tokens.
  • Reduced-motion honored; the affordance stays compact and never regresses the reply flow.
