Pennedly · Mobile spec · per-screen

Calendar /app/calendar — phone

The place a creator sees and moves their upcoming timeline — manually scheduled drafts plus a projection of recurring autopilot posts, on the selected account. A 7-column week grid is too tight at 390px, so the phone’s single view is an Agenda: a vertical list grouped by day, with a toolbar on top for navigation. Each row is a chip in three honest variants — manual (solid, pencil), autopilot projection (ghost/dashed, clock, “text written at post time”), and failed (danger, with a reason + Retry). Tapping a row opens a bottom sheet (full-width 44px buttons, primary on top). Moving a post on a phone is done through Edit time — no drag. The Studio scheduling control (Publish now | Schedule) folds to a sheet too. Frames are the real component layer at 390px, light and dark. Calm calendar / clock / pencil iconography; no lightning bolt anywhere. Hours are UTC server-side, shown in the viewer’s local timezone (UTC+N).

What does not change. The data is the backend’s: manually scheduled drafts (source:'manual', with text) and the projected autopilot rules (source:'autopilot', text:null until post time). Statuses are scheduled / projected / failed. The Calendar only shows and moves — creation lives in the Studio, recurrence in Autopilot. Mobile is a layout pass over the same agenda: the centred modal becomes a bottom sheet, everything else is width. Hours are UTC server-side, shown in the viewer’s local timezone.
New screen, built on our tokens. No third-party calendar library — the agenda, chips and sheets are all calendar.css on ds/tokens.css. The Autopilot screen is untouched; a projection’s sheet only links out to it. Calendar / clock / pencil icons only — no bolt.

4Toolbar

A page header sits under the top bar: the Calendar title (text-h1, w600) with a subtitle, a secondary “+ Schedule a post” button, and a navigation row with a ‹ › range stepper, the current range label, a Today button and the UTC+1 chip.

Rules. On a phone the navigation row goes full-width and sits above the title-and-button row, so ‹ ›, and Today land in thumb reach. ‹ › and Today are ≥44px tap targets via padding even though they read 32px tall. The range label is tabular-nums, min-width: 8.5rem, centered so day-count changes don’t shift the steppers. The UTC+1 chip sits at the end of the nav row (margin-left: auto).

5newAgenda (default)

The body is a vertical list grouped by day. Each day-group has a header (“Today · Wed, Jun 17” + a count) and stacked rows. A row = the phone chip: a left time column (time + source glyph), the source label, and a 2-line snippet, with a status dot. Three variants, same honest coding as desktop: manual (solid, pencil, accent), projection (dashed/ghost, clock, italic “Drafted at post time”), failed (danger). Past rows dim to 50%.

Rules. Rows are sorted by time within a day. Manual rows carry the real snippet; projection rows show the italic placeholder (text is written at post time). Failed rows tint danger and surface a Retry in the sheet. The whole row is the tap target (≥44px) → opens the detail bottom-sheet.

6fixDetail bottom-sheet

Tapping a row opens a bottom sheet (our pattern: slide up from the bottom, rounded top, full-width 44px buttons, primary on top). Three variants mirror the desktop modal.

Before

A centred modal sized for a desktop column leaves the actions mid-screen and out of thumb reach on a phone.

After

A bottom sheet within thumb reach: the local time + UTC line, the text (or ghost placeholder), then stacked full-width actions — primary on top.

Rules. Manual → Edit time (primary) · Publish now · Unschedule · Delete. Projection → read-only; the only action is “Manage schedule” → Autopilot. Failed → a reason block + Retry (primary) · Delete. Moving a post is done through “Edit time” (a date + local-hour picker), never drag.

7newStudio scheduling

Part of the same feature: the Studio publish step. On a phone the publish dialog is a bottom sheet with a Publish now | Schedule segmented control. In Schedule mode it reveals full-width Date + Time fields (16px text, anti-zoom; local, with a “= HH:00 UTC” hint), a text preview + character count, and the primary button becomes “Schedule for Wed, Jun 18 · 09:00”. After scheduling, the draft card gets a “Scheduled · <date>” badge and moves to the Studio’s Scheduled filter.

Rules. Fields are 16px / ≥44px (iOS anti-zoom). Minimum offset is now + 5 min. The toast “Scheduled for <…>” carries an Undo. The badge and the Scheduled filter mirror the desktop Studio integration (Calendar-SPEC §4).

10Web ↔ mobile · Localization

Desktop ( > 880 )

  • Fixed sidebar; 960px column; range stepper + UTC label in the topbar.
  • Same agenda idiom, centered ~840px column; detail = centered modal.
  • Move — via “Edit time”.

Phone ( ≤ 600 )

  • No sidebar/tab bar; hamburger → drawer (Calendar active); free bottom edge.
  • Agenda — day-grouped list.
  • Detail = bottom sheet (full-width buttons, primary on top).
  • Move = Edit time (date + local-hour picker), no drag.

All copy localizes into 8 locales (en/ru/uk/de/es/fr/it/pt); RU/DE run ~30–40% longer. Day-group headers, source labels, sheet actions, the empty state and the Studio scheduling control all wrap (never clip). Day names/dates and times render in the viewer’s local timezone via a localized formatter.

360px behavior. No new breakpoint — gutters stay 14px; the toolbar wraps to two rows (nav row, then title + button); agenda rows keep their 2-line snippet and ≥44px height; sheet buttons stay full-width. Long RU/DE day-group headers (“Сегодня · ср, 17 июн”) wrap to a second line rather than clip. The drawer stays min(82%, 312px) → ≈295px at 360.

11Checklist

  • Below 600px: no sidebar, no tab bar — one top bar with a hamburger far-left, “Calendar”, the UTC+1 label and a theme toggle; bottom edge free.
  • Hamburger opens the drawer (active = Calendar, calendar glyph, in the Workspace group right after Studio) + account at its foot.
  • Calendar / clock / pencil iconography; manual = pencil, projection = clock; no bolt anywhere.
  • Toolbar: title + “+ Schedule a post”, and a nav row (‹ › range stepper, range label, Today, UTC+1 chip); on phone the nav row sits full-width above the title-button row.
  • Agenda (default, single view): day-groups with header + count; rows sorted by time; three chip variants (manual solid / projection ghost-dashed / failed danger); past rows dim; ≥44px tap → sheet.
  • Detail bottom sheet: local time + UTC line; manual (Edit time / Publish now / Unschedule / Delete) · projection (read-only + “Manage schedule” → Autopilot) · failed (reason + Retry); full-width buttons, primary on top.
  • Move = Edit time (date + local-hour picker); no drag anywhere.
  • Studio sheet: Publish now | Schedule; Schedule reveals Date + Time (16px / ≥44px, “= HH:00 UTC”, ≥ +5 min) + preview + count; primary “Schedule for <…>”; toast w/ Undo; draft gets “Scheduled · <date>” badge + Scheduled filter.
  • Empty = “Nothing scheduled yet” (+ autopilot note + CTA); Loading = skeleton mirroring the agenda; correct in light and dark; no hardcoded colour.
  • All copy survives the longest of 8 locales — never clipped; sanity-checked at 360px; times in the viewer’s local timezone.
