Calendar /app/calendar — пиксель-в-пиксель

Полная спецификация нового экрана Calendar — места, где автор видит и двигает весь предстоящий таймлайн. Десктоп использует тот же агенда-идиом, что и телефон — вертикальную ленту, сгруппированную по дням, — просто шире и комфортнее: один центрированный столбец (≈840px), а не плотная сетка во всю ширину. Никаких 7-колоночных недель и месячных таблиц. Ментальная модель из трёх частей: Студия — создать пост и выбрать когда; Календарь — видеть и переносить всё запланированное; Автопилот — повторяющаяся автоматика на фоне. Лента сводит и запланированные вручную черновики (плотные строки), и проекцию повторяющихся постов автопилота (призрачные пунктирные строки). Тон Pennedly — «партнёр по черновикам», «ты остаёшься у руля». Документ покрывает десктоп одним проходом: живые фреймы (реальные DS-компоненты на новом calendar.css, светлая И тёмная темы, на ширине экрана), пронумерованная анатомия, все состояния, интеграция планирования в Студию, маппинг Web↔Mobile (теперь это один идиом), локализация в 8 языков и чек-лист. Иконография — спокойные календарь / часы / карандаш; никаких молний. Время хранится в UTC, показывается в локальной TZ зрителя + ярлык «UTC+N».

calendar.css calendar-app.jsx calendar-parts.jsx calendar-data.jsx studio-parts.jsx shell-parts.jsx ds/tokens.css ds/components.css
Десктоп переделан на агенда-идиом. Прежний вид сеткой неделя/месяц удалён полностью — плотная календарная сетка неудобна. Десктоп теперь = агенда-лента по дням, идентичная мобильной (единственное отличие — деталь = модалка по центру вместо bottom-sheet). Сторонних календарных библиотек нет; всё на calendar.css поверх ds/tokens.css. Экран Автопилота не трогаем — из детали проекции лишь ссылка «Manage schedule» туда.
Состояния одним взглядом. Два твика (?demo=1): dark и state. state = Default (лента из нескольких дней: ручные + проекция + один failed, «сегодня» с now-маркером, прошедшие дни приглушены) · Empty («Nothing scheduled yet») · Loading (skeleton, повторяющий ленту) · Detail (модалка по центру: ручной / проекция / failed). Все — в светлой и тёмной теме.

2.3 — Строка-запись .cal-row ×3 типа

Строка несёт: время («13:00») + UTC-подсказку, иконку источника в бейдже (ручной = карандаш; автопилот = часы), лейбл источника, короткий сниппет (2 строки, clamp) и статус-точку. Три визуальных типа кодируют источник и состояние:

ТипКлассВид · смысл
Manual.cal-row--manualПлотный accent-tint фон, карандаш в бейдже, accent-время, лейбл «Manual draft». «Ручной черновик, одобрен и в очереди» (status:'scheduled'). Текст есть.
Projected.cal-row--projКонтурный/призрачный — прозрачный фон, пунктирная рамка, часы, время muted, текст курсивом «Text is written automatically at post time», лейбл «Autopilot · <rule>». «Предсказано правилом, текст ещё не написан» (status:'projected', text:null). Grip скрыт.
Failed.cal-row--failedDanger-акцент (фон + рамка + время + бейдж). «Не удалось опубликовать» (status:'failed'). В детали — причина + Retry.
модификатор.cal-row--pastПрошедшая запись: opacity .55 (любой тип). Hover слегка проявляет.
части.cal-row-time / -ico / -src / -text / -dot / -gripВремя+UTC, бейдж-иконка 30, лейбл, сниппет (clamp 2), статус-точка, grip (проявляется на hover — аффорданс захвата).
Почему проекция — призрак. Повторяющийся пост автопилота на будущую дату ещё не имеет текста (он генерируется в момент выхода). Пунктир + курсив-плейсхолдер честно говорят: «это предсказание правила, а не готовый черновик». Кликом — read-only деталь со ссылкой в Автопилот.

2.4 — Деталь — модалка по центру .cal-modal click a row

Клик по записи открывает модальное окно по центру экрана — не поповер у строки. Подложка (.overlay): fixed inset-0, bg mix(ink-950 55%), небольшой backdrop-blur, содержимое центрируется, padding 24; закрытие — клик по подложке и Esc (блокируется на время запроса). Панель — общий .dialog: max-width 420, ширина 100%, border, bg surface, padding 24, shadow-lg, анимация входа dialog-in. Три варианта по источнику/статусу:

Элемент / классОписание

.cal-modal-srcСтрока источника: иконка (карандаш 13 у ручного, часы 13 у проекции) + ярлык, caption/w600/muted, margin-top 12.

ВариантСодержимое · действия
РучнойТег-иконка карандаш · полный текст · время крупно + UTC-строка. Действия: Unschedule (ghost) · Publish now (вторичная sm, иконка send) · Edit time (primary sm, иконка clock) — режим правки заменяет текст на .cal-modal-fields и кнопки на Cancel / Save (Save блокируется, если время ближе чем сейчас + 5 минут).
ПроекцияТег-иконка часы · read-only · ghost-текст «Text is written automatically at post time» · правило (rule_name). Единственное действие — вторичная Manage schedule со ссылкой на /app/autopilot (иконка external).

4studio Интеграция в Студию — контрол планирования

Планирование — часть той же фичи, поэтому специфицируется здесь. На шаге публикации черновика (диалог публикации в Студии) появляется сегмент-переключатель «Publish now | Schedule». В режиме Schedule: поле даты (date-picker) + поле времени (часы:минуты, локально, подсказка «= HH:00 UTC»), превью текста и счётчик символов; минимальный отступ от «сейчас» ≥ +5 мин. Главная кнопка меняется на «Schedule for Wed, Jun 18 · 09:00».

Элемент / классОписание
.sched-segСегмент Publish now (send) / Schedule (clock) наверху диалога. Дефолт — Publish now.
.sched-fieldsSchedule-режим: grid 2 cols — Date (date-picker) + Time (local HH:MM). .sched-hint «= 08:00 UTC · at least 5 min from now».
.sched-previewПревью текста черновика + .sp-count счётчик символов (напр. «248 / 500»).
главная кнопкаPublish-режим → «Publish now» (primary). Schedule-режим → «Schedule for <Wed, Jun 18 · 09:00>» (primary, часы).

5Один идиом · Web ↔ Mobile

Теперь это один идиом — агенда-лента по дням — на обоих. Десктоп = центрированный широкий столбец (деталь = popover); мобайл = full-width (деталь = bottom-sheet). Никакой сетки неделя/месяц. Брейкпоинты: 880px (shell → icon-rail) · 600px (телефонный слой pennedly-mobile.css + calendar.css .mcal-*). Полный телефонный проход — Calendar-Mobile-SPEC.html.

Десктоп ( > 880 )

  • Фикс. сайдбар; центрированная агенда-лента (≈840px), а не на всю ширину.
  • День-группы со sticky-заголовками; строки стопкой по времени; now-маркер.
  • Range-навигатор (‹ диапазон ›) + TZ + «+ Schedule a post» над лентой.
  • Деталь — центрированная модалка.
  • Перенос — через «Edit time».

Телефон ( ≤ 600 )

  • Нет сайдбара/таб-бара; гамбургер → drawer; свободный нижний край.
  • Та же агенда-лента, full-width; компактная неделя-полоска сверху для навигации.
  • (Month — лишь компактная пип-сетка-опция для обзора; тап по дню → agenda дня.)
  • Деталь — bottom-sheet (full-width 44px кнопки, primary сверху).
  • Перенос — через «Edit time» (drag&drop на телефоне не используется).
Единственные отличия десктоп↔мобайл: ширина (центрированный столбец vs full-width) и форма детали (модалка по центру vs bottom-sheet). Структура записи, три типа (manual/proj/failed), группировка по дням, статусы и привязка к аккаунту — идентичны.

6Точные значения · backend-контракт

Эндпоинт / полеОписание
GET …/calendar?from&to&accountОкно записей для выбранного аккаунта: ручные запланированные черновики + вычисленная проекция правил автопилота на диапазон. Возвращает entries[].
Запись (entry){ id, source ('manual'|'autopilot'), scheduled_at (ISO-UTC), local_time, text (сниппет; у autopilot-проекции null → «will be generated»), status ('scheduled'|'projected'|'failed'), rule_name? (для autopilot), account }
PATCH …/scheduled/:idПеренос ручного поста (Edit time): новый scheduled_at (UTC). Только source:'manual'.
POST …/scheduled/:id/publishPublish now из детали. DELETE = unschedule (вернуть в черновики) / delete.
POST …/scheduled/:id/retryRetry для status:'failed'.
Studio publishPOST …/drafts/:id/schedule { scheduled_at UTC } — из диалога Студии (режим Schedule). Минимум now + 5 min.

Local ↔ UTC · источники

  • Время — UTC server-side (scheduled_at), показывается/выбирается в локальной TZ зрителя; ярлык «UTC+N» в навигаторе. Конверсия через браузерную TZ, ничего не персистится на конверсии.
  • Проекция автопилота — вычисляется из правил (post_hour UTC + jitter), read-only на календаре; текст null (пишется в момент выхода). Правка — только в Автопилоте.
  • Ручной запланированный — полноценная запись с текстом; двигается/публикуется/снимается прямо с ленты.
  • Failed — попытка публикации не удалась; в детали причина + Retry.
  • Привязка к выбранному аккаунту (мульти-аккаунт, как остальные экраны).

8Чек-лист реализации

  • Полный app-shell; активный пункт = Calendar (Workspace, рядом со Студией, иконка-календарь); навигатор «Calendar» + ярлык «UTC+N» + «+ Schedule a post»; центрированная агенда-лента ≈840px (не на всю ширину).
  • Один идиом — агенда-лента по дням; никаких сеток неделя/месяц.
  • Иконография — календарь / часы / карандаш; ручной = карандаш, проекция = часы; молний нет нигде.
  • День-группа: sticky-заголовок (число + день недели + дата + «Today», прошедшие дни приглушены) → строки по времени; в «сегодня» — ненавязчивый now-маркер.
  • Строка ×3: manual (плотный, карандаш) · projected (пунктир/призрак, часы, текст «пишется при выходе», grip скрыт) · failed (danger); время + UTC + статус-точка; past = dim.
  • Range-навигатор (‹ диапазон › + Today + легенда) над лентой — переключатель периода, не сетка.
  • Деталь-модалка по центру: ручной (Unschedule / Publish now / Edit time, с режимом правки времени) · проекция (read-only + «Manage schedule» → Автопилот) · failed (причина + Unschedule / Retry).
  • Студия: сегмент «Publish now | Schedule»; Schedule = Date + Time (local, «= HH:00 UTC», ≥ +5 мин) + превью + счётчик; главная кнопка «Schedule for <…>»; тост с Undo; бейдж «Scheduled · <date>» + вкладка «Scheduled».
  • Время UTC server-side, показ в локальной TZ + offset-label; проекция read-only; привязка к выбранному аккаунту.
  • Состояния Default/Detail(×3)/Drag/Empty/Loading; loading-скелет повторяет ленту.
  • Корректно в светлой и тёмной теме; только семантические токены; копи выживает в 8 локалях; парный телефонный документ — Calendar-Mobile-SPEC.html.
Конец спецификации. Один идиом (агенда-лента) на десктопе и телефоне; новый CSS — calendar.css + общий shell + интеграция в studio-parts.jsx. Парный телефонный документ — Calendar-Mobile-SPEC.html.
