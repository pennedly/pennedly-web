Style rules /app/style-rules — phone

Where you control how generated text reads: a catalog of built-in anti-“AI-tell” rules (toggle on/off, default on) plus your own custom style rules. Rules apply at generation time to strip machine tells and enforce your style. On a phone the work is the rules list, the per-rule controls, and the live before→after demo. This spec stacks everything to one column — each rule a row with a right-aligned toggle and a small “applies to” control, the demo stacked before-above-after — fitting cleanly at 390px (sanity-checked at 360). Same tokens, catalog and behaviour as the desktop; only the layout changes below 600px, on the decided shell (hamburger + drawer, no tab bar, free bottom edge). Frames are the real component layer at 390px, light and dark.

pennedly-mobile.css stylerules-app.jsx stylerules-parts.jsx shell-parts.jsx ds/tokens.css
What does not change. The built-in catalog is a fixed set you toggle on/off (default on); you can add custom rules. Each rule has an applies-to (posts / replies / both, default both) and applies at generation time. Built-in titles + descriptions are localized UI; the rule’s prompt body stays as authored. One rule (Human punctuation) also drives a deterministic typographic pass — its before→after demo is real. No invented rule types, scoring, or per-rule analytics. Mobile is a layout pass; the only structural change is the shared app shell.

4fixRule row — the fix

Each rule is one row. The desktop puts the toggle on the left and the applies-to as a chip on the right of the title. On a phone the title/description need the full width, so the controls reorganise.

Before

Toggle left, title + a right-floated chip, description below — on a phone a long title collides with the chip and the toggle steals width from the text.

After

The text owns the row: title + description wrap full-width, with the on/off toggle right-aligned at the top. The applies-to (Both / Posts / Replies) is a small segmented control on its own line under the description.

On vs off. An off rule goes surface-2 with muted text and the toggle grey/left; an on rule is surface-white with the accent toggle. The applies-to control stays interactive in both. Title + description wrap to as many lines as a locale needs — the toggle never moves.

5Your rules (custom)

Your own rules come first. Each is a row: the rule text, an applies-to control, edit/remove icons, and the on/off toggle. An add-a-rule field sits at the foot (16px input + applies-to + Add). Editing swaps the row for a full-width editor.

6Built-ins by category

The fixed anti-AI-tell catalog (~17 rules) groups by category — Punctuation, Diction, Structure, Cadence, Formatting, Tone. Group headers stay visible (with an on/total count); the rules stack beneath each.

7Before → after demo

The punctuation rule also runs a deterministic typographic pass, so it carries a live before→after demo. On a phone it stacks: a labelled “Before” block above an “After” block, full-width — never two columns.

Stacked, labelled. “Before” is danger-tinted (the tell), “After” success-tinted (the fix). When the rule is off, “After” equals “Before” (nothing is stripped). The sample text is mono so the punctuation change (em-dashes → commas, guillemets → straight quotes) is legible.

10Web ↔ mobile

Desktop ( > 900 )

  • Fixed sidebar; reading column; toggle left, applies-to chip by the title.
  • Demo can sit before / after inline.
  • Categories as grouped lists.

Phone ( ≤ 600 )

  • No sidebar/tab bar; hamburger → drawer + account; free bottom edge.
  • Text owns the row; toggle right-aligned; applies-to a segmented control below.
  • Demo stacks Before above After; categories keep visible headers.

11Localization & 360px

Rule titles, descriptions, category names, the applies-to labels (Both / Posts / Replies) and add/edit copy all localize into 8 locales; DE/RU/UK run ~30–40% longer. On a phone: titles and descriptions wrap to as many lines as needed and never push the toggle off-screen (the toggle is flex-fixed, right-aligned); the applies-to segmented control sits on its own line so its longer labels don’t crowd the toggle; category headers wrap. The custom-rule input + add button stay full-width. The before→after sample is content (mono), not chrome.

360px behavior. No new breakpoint — the gutter stays 14px; rows get ~30px narrower so titles/descriptions rewrap; the applies-to control and toggle keep their sizes. The add-a-rule “Add” button drops below the applies-to control on the narrowest locales. The drawer stays min(82%, 312px) → 82% (≈295px) at 360.

12Checklist

  • Below 600px there is no sidebar and no tab bar — one 52px top bar with a hamburger far-left.
  • Hamburger opens the left drawer (active = Style rules) + account; bottom edge free.
  • “Your rules” (custom) section comes first, above the built-ins.
  • Each rule is a row: title + description (full-width, wraps) + right-aligned on/off toggle + a small applies-to (Both / Posts / Replies) control.
  • Off vs on is clear: off = surface-2 + muted + grey toggle; on = white + accent toggle.
  • Built-ins group by category with always-visible headers + on/total counts; default on.
  • The before→after demo stacks Before above After, full-width, labelled, mono — never two columns.
  • Adding/editing a custom rule uses a full-width 16px editor (no iOS zoom).
  • Loading = skeleton heads + rows; error banner has Retry.
  • Titles/descriptions wrap on long locales — never pushing the toggle off-screen; sanity-checked at 360px.
  • Correct in light and dark; no hardcoded colour.
