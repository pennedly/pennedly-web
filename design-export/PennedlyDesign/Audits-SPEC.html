Audits /app/audits · /app/audits/[id]

Дотошная спецификация еженедельного коуча Audits (ключевое отличие Pennedly) — и общего app-shell, который Audits переиспользует 1:1 из Studio (<window.Sidebar active="audits"/> + топбар + переключатель аккаунтов). Раз в неделю коуч Pennedly разбирает аккаунт и предлагает точечные правки голоса/стратегии в role-book; пользователь одобряет или отклоняет каждую правку, а эффект-трекер потом измеряет, как это сказалось на вовлечённости. Документ покрывает ОБА вида: список аудитов (/app/audits) и детальную страницу одного аудита (/app/audits/[id]). Ниже задокументированы АБСОЛЮТНО все состояния: shell (аккаунт-меню откр/закр), список (loading / ready / empty) с карточками needs-review/reviewed, детальная (loading / ready) с шапкой, нарративом коуча и карточками-правками во всех статусах (pending / applied / rejected), diff-вьюер, заметки, autopilot-часы, чип измеренного эффекта, тосты-подтверждения, тема и адаптив web↔mobile. Все значения взяты из реального дизайна, без «примерно».

App-shell — общий, 1:1 как в Studio. Audits НЕ собирает каркас заново: рендерится <window.Sidebar active="audits"/> из shell-parts.jsx, а классы .app/.sidebar/.main/.topbar/.account приходят из studio.css + shell.css. Отличия shell от Studio — активный пункт навигации = Audits в группе Insight (nav-item--active, aria-current="page", badge = 1) и заголовок топбара «Audits». §2.1–2.4 документируют shell так же дотошно, как в Studio-SPEC.
Расхождения с брифом — здесь задокументирован РЕАЛЬНЫЙ дизайн. В коде (а не в брифе):
  • Ширина — reading 720, не wide 960. Топбар использует .topbar-inner без --wide, а .content — без --wide. Обе колонки выровнены по --content-reading 720 (узкая «читательская» колонка — подходит коучу-нарративу). Это единственный из инсайт-экранов на reading-ширине.
  • Error-состояния НЕТ. Твик state = только Live / Loading / Empty. ErrorBanner и Retry в этом экране отсутствуют (как в Stats). Не документируйте error-ветку.
  • Список ↔ деталь — это локальный view-стейт (list/detail), не настоящая смена URL. Клик по строке → openAudit → view="detail" + скролл вверх; «All audits» → view="list". Отдельного твика list/detail нет.
  • «Rolled back» эффект-чипа НЕТ. EffectChip рендерится только при status==="applied" и даёт три исхода: «measuring effect…» (нет числа) · «+N% {label}» (up) · «−N% {label}» (down). В данных остался один rolledback-элемент (c5, −4%) — это легаси-хвост: его бейдж падает в фолбэк «Applied» (STATUS[status] || STATUS.applied), эффект-чип не выводится, нижняя мета пустая. См. §4.6.
  • Решение — append-only, без undo. Approve → «Applied» немедленно (эффект измерят позже), Reject → «Rejected». Оба дают тост-подтверждение БЕЗ Undo. Решённые правки — read-only (нет rollback/reconsider).
  • Per-change есть заметка (Add a note / Edit / Save note, ⌘↵/Esc) и diff-вьюер (View change ↔ Hide change). autopilot_config-правка показывает предложенные часы постинга в локальной TZ.
  • Брейкпоинт Audits — только 560px (скрывается шеврон строки, футер правки переносится). Сайдбар сворачивается в rail на 880 (shell).
Состояния одним взглядом. Экран управляется двумя твиками (audits-app.jsx → AUDIT_TWEAK_DEFAULTS): dark (false) и state («Live»). При монтировании и при state="Loading" фаза = loading ~850ms → ready; state="Empty" делает live=[] → EmptyState. Данные — из AUDITS (5 аудитов). reviewCount (для топбар-пилюли) = сумма правок в статусе undecided по всем аудитам. На строке «N to review» = undecided этого аудита; «{decided} of {total} decided» = applied+rejected из total. Тосты живут 4200ms.

1Идентификация (два маршрута)

Маршруты, назначение, ширина reading 720, раскладка сверху вниз отдельно для списка и для детальной.

МаршрутыСписок /app/audits + деталь /app/audits/[id]. В коде — один компонент AuditsApp с локальным view (list/detail) и openId.
ТипПолный app-shell: рендерится <window.Sidebar active="audits"/>. Каркас 1:1 переиспользован из Studio.
НазначениеЕженедельный коуч: Pennedly разбирает слабые по вовлечённости посты и предлагает точечные правки голоса/стратегии в role-book. Пользователь одобряет/отклоняет каждую; эффект измеряется позже. Решение append-only — однократно, немедленно, без отката.
Корневой контейнер.app → display:flex; height:100%; overflow:hidden; bg --color-bg; color --color-text. Без data-density.
Ширина контентаreading = --content-reading 720px. Колонка .content (без --wide) центрируется; топбар выровнен по той же ширине через .topbar-inner (тоже без --wide).
ТопбарЗаголовок «Audits» + .status-pill: --accent «{reviewCount} to review» (когда есть undecided) / --success «All reviewed» (когда 0) + действия: тема + Settings.
Фазы (state)loading (page-intro + SkeletonList) · ready (список или деталь) · empty (EmptyState «No audits yet»). Error-фазы нет. Управляется твиком state; в реальном приложении — loading на fetch.
First-run / densityОтсутствуют.
ЛокализацияEnd-user копи локализуется: intro, лейблы строк, статус-бейджи, нарратив, кнопки/лейблы правок, подпись и нота autopilot-часов, empty-копи, тосты. Контент аудитов и числа — сэмплы. autopilot-часы хранятся в UTC, рендерятся в локальной TZ (localHours + utcLabel).
Backend-правдаAPPEND-ONLY: правка решается один раз, немедленно, без отката/пересмотра — поэтому НЕТ undo / rollback / reconsider нигде. autopilot_config-часы хранятся в UTC. Время — в локальной TZ зрителя.

деталь4.6 — EffectChip + легаси «rolledback»

  • measuring — status="applied", effect=null (только что одобрено): «measuring effect…» (subtle, IcClock). Так выглядит свежеодобренная правка.
  • up — effect не начинается с «-»: «{effect} {label}» success + IcArrowUp. Напр. c3 «+31% engagement», b2 «+19% replies».
  • down — effect начинается с «-»: danger + IcArrowDown.
Легаси «rolledback» (правка c5). В данных остался элемент со status="rolledback" и effect="-4%". UI не имеет rolledback-аффорданса: ChangeStatusBadge падает в фолбэк STATUS.applied → бейдж «Applied»; EffectChip возвращает null (рендерится только при точном status==="applied"); в cc-foot ни одна из веток (undecided/rejected/applied) не совпадает → нижняя мета пустая, кнопок нет. Итог: c5 выглядит как «Applied»-карточка без чипа эффекта и без меты. Это известный хвост (rework удалил rollback из UI, но не из сид-данных). Не воспроизводите «rolled back» как отдельное состояние — его в дизайне нет.
