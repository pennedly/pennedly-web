Pennedly  /  Design System

Ink on paper

The Pennedly
design system.

A small, coherent token set built from one idea — a near-black ink mark on warm off-white paper — so the entire product looks like it belongs to the Drafting Line app icon. Calm, craft-like, confident. Monochrome, with a single quiet ink-blue accent.

North star

Off-white paper #ededed, near-black ink #171717, deepest ink #0a0a0a, generous ~22% rounding. Every surface, type ramp and component below derives from these. Toggle the theme in the top-right — nothing was duplicated to make dark mode work.

Foundations

Color

One hue only: a warm-neutral ink. The ink scale is the raw material; the semantic roles are what components actually reference, and they flip in dark mode so component code stays the same.

Ink scale

Semantic roles

These are the tokens you reach for — bg-surface, text-text, border-border. Shown in the current theme.

The one accent & status

A single restrained accent — Ink Blue #2f4cc4 (light) / #9aacff (dark) — for links, focus, selection and selected nav. It never fills a primary button; the primary action stays ink. Status colors are desaturated so they sit quietly next to the ink.

Contrast: body text, muted text and every solid role pairing meet WCAG AA (≥4.5:1) in both themes. text-subtle is reserved for placeholders & captions and still clears AA on its intended surfaces.

Foundations

Typography

Geist throughout — the same geometric, quietly-engineered letterform family as the icon's monogram potential. Geist Mono for code & token values. A seven-step scale; each step carries its own line-height, weight and tracking as Tailwind 4 modifier tokens.

Radius & elevation

Rounding is generous to echo the icon's soft ~22% corner. Buttons & inputs use md; cards lg; modals the most icon-like 2xl. Elevation is soft, low and inky — calm, never floaty; in dark mode borders do most of the separating.

Mobile

The app on a phone

The desktop redesign is done. This section is the shared rule set for the phone experience — the parts that are true on every /app screen. Nothing about the identity changes: same ink-on-paper, same semantic tokens, same light and dark, same eight locales, same states and flows. Only the layout adapts. Every phone below is the real component layer (mobile/pennedly-mobile.css) on the real tokens, shown at a 390px reference width in both themes.

Per-screen detail lives in the specs. This page sets the cross-screen rules. Each screen then has its own pixel-level mobile spec: Studio, Feed, Replies are the canonical reference set; the remaining screens follow the same patterns.

Mobile

App shell & navigation

On desktop the shell is a fixed left sidebar. On a phone it splits into three thumb-reachable pieces: a slim top bar (screen identity + a couple of contextual actions), a bottom tab bar (the daily destinations), and a “More” drawer (everything else, plus account and settings). This is the native phone pattern and keeps the most-used routes under the thumb.

Top bar

SlotBehavior
LeftScreen title (text-h3, truncates with ellipsis) — or the brand mark + “Pennedly” on top-level/public screens. A back chevron prepends on drill-in screens (e.g. an Audit detail).
Center (optional)A screen-specific status-pill may sit beside the title (Studio shows the voice state). If width is tight on a long locale, the pill drops into the content area instead of crowding the bar.
RightUp to two utility icon buttons (e.g. theme, search) at 40px + the account avatar (32px → opens the account sheet). Frosted background, sticky.

Bottom tab bar

Four core Workspace destinations plus More. The active tab is ink (not accent — matching the shipped sidebar’s active treatment); inactive tabs are subtle. Unread/queue counts ride the icon as a small accent bubble.

“More” drawer & account sheet

Mobile

Components on mobile

Shared components get phone layouts here once, so every screen inherits the same behavior. Two of these are direct fixes for problems seen on a real iPhone.

Card action rows — the canonical fix

Before · desktop row squeezed

The foot (“Auto-replies / Growth / Open in Threads / ⋯”) is one horizontal row. On a phone it crams: “Open in Threads” wraps to two lines, the ⋯ runs off the edge, taps land on the wrong control.

After · two-tier foot

A meta line that wraps freely, then one action row: at most one labelled primary (grows, 44px, wraps not clips) plus 44×44 icon buttons for secondary actions and the ⋯ overflow. Anything beyond moves into ⋯.

This one pattern is reused by every card-bearing screen — Studio drafts, Feed posts, Replies comments — so the whole app feels consistent. Below: the same foot across all three (full cards in each screen’s spec).

Composer — the canonical fix

Before · chips collapse

Chips + draft-count + “Generate” share one desktop row. On a phone the chips shrink into a cramped left column, “Generate” floats to the side, dead space opens up, and the placeholder title clips.

After · clean vertical stack

Full-width textarea (placeholder fully visible), a horizontally scrollable chip row (chips keep full size, never crush), then a full-width action footer: draft-count select + Generate (grows). Nothing floats, no dead space.

Filters, dialogs, toasts & forms

Mobile

Localization on a phone

Eight UI locales ship, and German, Russian and Ukrainian routinely run 30–40% longer than English. Phone widths are unforgiving, so the layout must never assume English label lengths. The rules:

Do
  • Let primary buttons wrap to a second line (height:auto; min-height:44px; white-space:normal) rather than clip.
  • Keep chips and filters in scrolling rows so long labels never crush.
  • Truncate names and handles with ellipsis; never let them push actions off-screen.
  • Let tab labels truncate, falling back to icon-only tabs when a locale is extreme.
Don’t
  • Pin any width to an English string length.
  • Bake text into an image — every label stays live text for the translator.
  • Force a single-line foot; collapse to the two-tier pattern instead.
  • Use em-dashes in copy, or shrink type below the ramp to “make it fit”.

Below, the same Studio surfaces rendered with German strings — the primary action wraps, chips scroll, and the tab labels truncate, all without breaking the grid.

Apply it

Foundations & usage rules

Quick rules

Spacing: everything on the 4px grid; lean on gap-* in flex/grid, not margins. Radius: md for controls, lg for cards, 2xl for modals — match the size of the thing to the softness of its corner. Elevation: sm for resting cards, md for popovers/menus, lg only for overlays; in dark mode let borders carry separation. Focus: one rule everywhere — a 2px ink-blue ring at 2px offset (already global in globals.css); never remove it. Motion: 120/180/240ms with the standard easing; gate anything decorative behind prefers-reduced-motion. Iconography: line icons, ~1.8px stroke, round caps & joins, drawn on a 24px grid — the same calm, single-weight stroke as the pen mark; no filled or duotone icons.

Do
  • Reference semantic tokens (bg-surface, text-text) so dark mode is automatic.
  • Keep primary actions ink; spend the ink-blue accent sparingly on links & focus.
  • Use the ink scale for raw needs (dividers, fills) only when no role fits.
  • Let whitespace and hairlines do the work — this is a calm, papery UI.
Don’t
  • Hard-code hex values or invent one-off grays — every color has a token.
  • Add a second accent or any gradient; the identity is monochrome ink.
  • Stack heavy shadows or tighten radii below sm — it breaks the soft feel.
  • Duplicate styles with dark: when a semantic token already flips.

Apply it

Rollout plan

Apply across the codebase in order — tokens first, then swap component class strings surface by surface. Each step is independently shippable.

Replace app/globals.css
Drop in the file from §globals.css. It already @import "tailwindcss" and defines every token + the .dark flip. Delete the old --background/--foreground pair — the new --color-bg/--color-text supersede them.
Wire the theme class
Ensure your theme provider toggles class="dark" on <html> (most likely already does). No tailwind.config.js needed — config is CSS-first.
Adopt primitives: Button, then Input/Field
Swap these two first — they appear on every screen. Paste the recipe strings into your existing components; remove any dark: color duplicates as you go.
Surfaces: Card, Badge, Table, Nav
Convert shells next so pages visually settle onto paper. Replace ad-hoc grays with bg-surface/bg-surface-2/border-border.
Overlays: Dialog, Toast, Switch
Lower-frequency, higher-polish. Apply rounded-2xl + shadow-lg to dialogs and the entrance easing to mounts.
Sweep for stragglers
Grep for raw hex (#), shadow-[, and leftover dark: color utilities; replace with tokens. Verify AA on any custom text/background pairing.
The drop-in files live at the project root: globals.css (ship this) plus this living reference. Toggle the theme above and read each component in both modes before you sign off.
