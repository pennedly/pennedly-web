Stats /app/stats — пиксель-в-пиксель

Полная, дотошная спецификация экрана Stats — агрегатной аналитики аккаунта за выбранный период. Со времени прошлой синхронизации образца экран изменился по трём реальным решениям продукта: главный график стал линией с заливкой (area-line) вместо столбцов; «Лучшее время для постов» стало тепловой картой вместо двух столбчатых диаграмм; появилась настоящая кнопка «Обновить» с отметкой «обновлено N назад». Пустое состояние `.stats-empty` отменено — вместо него прогрессивный экран первого запуска (см. First-Run-SPEC.html). Документ покрывает и десктоп, и телефон как один проход. Ниже — живые фреймы (реальные DS-компоненты, светлая И тёмная темы), пронумерованная анатомия с таблицами значений, все шесть периодов, маппинг Web↔Mobile, локализация в 8 языков и финальный чек-лист. Числа — сэмплы; формы — реальные.

stats-app.jsx stats-parts.jsx stats-data.jsx stats.css stats-firstrun.css shell-parts.jsx studio.css ds/tokens.css ds/components.css ↻ area-line trend ↻ heatmap best-times + refresh control
Живые фреймы — это реальный системный слой. Документ подключает ds/tokens.css + ds/components.css + stats.css + stats-firstrun.css и рендерит компоненты как в продукте на ширине --content-wide 960. Каждый фрейм пинит свои токены: светлый — из :root, тёмный — через класс dark, поэтому темы живут рядом, не затрагивая саму страницу-документ. App-shell (.sidebar/.topbar/.account) — общий из Studio, активный пункт = Stats в группе Insight; ниже он показан мини-демо топбара, полная анатомия каркаса — в Studio-SPEC.
Синхронизация образца — три реальных изменения продукта.
  • Главный график — area-line, не столбцы (коммит 3f2f849). Непрерывная ось времени с заполнением пропусков (каждый бакет присутствует; пустые не создают дыр в линии) + пунктирная линия среднего, подписанная «сред.» + разреженные подписи по оси (~8, не по одной на бакет). Заголовок панели — «Средние просмотры на пост».
  • «Лучшее время для постов» — тепловая карта, не два столбчатых графика (коммит 904dfca). Одна сетка: 7 строк (дни недели) × 6 колонок (укрупнённые слоты часа публикации). Легенда с полюсами «меньше» / «больше»; ячейки без постов — отдельное визуальное состояние «постов не было», не нулевой цвет шкалы. Цвета ячеек — токены --color-heat-1…4 (свой набор в тёмной теме), не хардкод.
  • Кнопка «Обновить» + «обновлено N назад» — рабочая функция, не украшение. Заменяет статичную пилюлю «Updated daily»: реальный повторный запрос с крутящейся иконкой, после которого подпись сбрасывается на «обновлено только что».
  • `.stats-empty` отменён — вместо него экран первого запуска. Прогрессивная страница (см. First-Run-SPEC.html): всегда показывает настоящие 4 карточки (даже маленькие/нулевые) + тёплая подсказка вместо стены «приходите через две недели». Селектор периода во время загрузки и на первом запуске — скрыт, а не показан неактивным.
  • Порядок панелей подтверждён и не меняется: период → сводные числа → «Подписчики» → «Средние просмотры на пост» → «Лучшие посты» → «Лучшее время для постов» → «Распределение по эффективности».
Состояния одним взглядом. Экран управляется тремя твиками (?demo=1): dark (false), period («7d»), state («Live» / «Loading» / «First-run»). Смена периода или state="Loading" уводит фазу в loading ~700ms → ready, и в обоих случаях прячет селектор периода (не просто отключает). state="First-run" рисует прогрессивную страницу и тоже прячет селектор. Колонка контента — --content-wide 960; топбар выровнен по той же ширине (.topbar-inner.topbar--wide). Форматирование чисел — sfmt() (K/M).

1Идентификация экрана

Маршрут, назначение, ширина, раскладка сверху вниз: sidebar | main(topbar + scroll(content: head(intro + период) + summary + follower-growth + trend + top-posts + best-times + spread)). Read-only — никаких мутаций контента, кроме «Обновить».

Маршрут/app/stats. Пункт навигации Stats в группе Insight (без badge, не tester-gated). Демо-режим: /app/stats?demo=1 с панелью Tweaks.
ТипПолный app-shell: рендерится <window.Sidebar active="stats"/>. Каркас 1:1 переиспользован из Studio.
НазначениеКак аккаунт выступает в агрегате за период: headline-числа, что сработало (Top posts), когда постить (тепловая карта) и насколько вирально (Performance spread). Только просмотр + ручное обновление.
Ширина контентаwide = --content-wide 960px. Колонка .content.content--wide центрируется; топбар выровнен по той же ширине (.topbar-inner.topbar--wide).
ТопбарЗаголовок «Stats» + .stats-refresh: кнопка «Обновить» + подпись «обновлено N назад» (§2.1) + действия: тема + Settings.
Секции (top→bottom).stats-head (h1 + подзаголовок + .range-seg) → .stats-grid (4 SummaryCard) → Подписчики → Средние просмотры на пост (area-line) → Лучшие посты → Лучшее время для постов (тепловая карта) → Распределение по эффективности. На первом запуске и во время загрузки селектор периода скрыт.
Фазы (state)loading (скелет, повторяющий раскладку, селектор скрыт) · ready · first-run (прогрессивная страница, см. First-Run-SPEC.html, селектор скрыт). Error-фазы нет.
Период6 фиксированных опций = backend-enum 1:1: Today · Yesterday · 7 days · Month · 3 months · All time. По умолчанию 7 days.
ЛокализацияEnd-user копи локализуется (8 языков: en/ru/uk/de/es/fr/it/pt): заголовок, лейблы периода/карточек, текст дельт, «сред.», «× your average», легенда тепловой карты, названия тиров, копи первого запуска, «обновлено N назад». Числа — сэмплы из insights, формат локали.
Backend-правдаОпции периода — РОВНО backend-enum (без кастом-диапазонов). Дельты — против предыдущего равного периода; у All time предшественника нет (prev=null → «no prior period»). Бакеты/гранулярность — от backend; время — в локальной TZ зрителя. «Обновить» — реальный повторный запрос тех же данных. Графики нарисованы вручную на CSS/SVG (без библиотек).

2.5 — Тренд-график .spanel / .linechart area-line · перестроен

NEW2.6 — Follower growth .spanel / .fchart FollowerChart

Панель роста подписчиков. Шапка: слева caption «FOLLOWERS» (+ тихий саб «Since you connected»), справа — текущее число (крупное, tabular) + прирост за всё окно (+N success / −N danger). Ниже — линия (accent 2.2px, скруглённая) с лёгкой accent-заливкой и точкой на последнем значении. Важно: ось min–max, а НЕ от нуля — счётчики подписчиков большие, а суточный прирост мал; нулевая база схлопнула бы линию в плоскую. Блок независим от селектора периода — всегда показывает всю историю с момента подключения. Collecting (меньше 2 дней данных): пунктирная плитка с чарт-глифом + «Collecting your follower data» + саб про то, что Threads отдаёт только сегодняшнее число.

NEW2.8 — Лучшее время для постов .spanel / .heatgrid тепловая карта · перестроена

Панель «Best times to post» / cap «Average views per post by publish time · <period>». Раньше — два отдельных мини-графика (By hour, By day of week); теперь — одна тепловая карта: строки = дни недели (Mon→Sun, полная неделя всегда), колонки = 6 укрупнённых слотов часа публикации в локальном времени зрителя. Яркость ячейки = средние просмотры/пост для этого дня×часа, по шкале из 4 уровней токенов --color-heat-1…4. Легенда с полюсами «меньше» / «больше» под шапкой панели. Лучшая ячейка (среди слотов с ≥ 2 постами — чтобы один удачный пост не «короновал» комбинацию) обведена и названа в чипе «Лучшее · {день} {час}». Пустые ячейки (0 постов) — отдельное дэшед-состояние «постов не было», не самый тусклый цвет шкалы. Скрыт целиком для Today/Yesterday.

.heat-cell.is-bestОбводка box-shadow:0 0 0 2px text — единственная выделенная ячейка сетки.
.heat-cell.is-empty«Постов не было»: прозрачный фон + пунктирная рамка, не самый тусклый уровень шкалы (чтобы «мало» и «совсем не публиковал» не выглядели одинаково).
Правило лучшей ячейки. Лучшая = ячейка с максимальным avg views/post среди ячеек с ≥ 2 постами. Если ни у одной нет 2 постов — берётся абсолютный максимум среди непустых. Уровни шкалы 1–4 — квартили по непустым ячейкам окна, не абсолютные пороги; тёмная тема получает свой набор значений тех же четырёх токенов, не просто затемнённый light-набор.

2.9 — Performance spread .spanel / .distlist DistributionBars

Панель «Performance spread» / cap «<N> posts vs your baseline · <period>». Четыре тира — Viral (3×+) · Good (1.5–3×) · Average (0.7–1.5×) · Weak (ниже 0.7×) — каждый строка: цвет-точка + название + faint саб + count + percent + тонкий бар пропорции.

Элемент / классОписание

.dist-track / .dist-filltrack 8px (radius-full, bg surface-2, border); fill = count/maxCount·100%, цвет = класс тира.
Цвета тировviral = success; good = accent; average = mix(text 30%, surface); weak = mix(text 15%, surface).

2.10 — Первый запуск / Loading .stats-empty отменён

.stats-empty («Not enough data yet» стеной на весь экран) удалён из дизайна. На его месте — прогрессивная страница первого запуска, задокументированная целиком в First-Run-SPEC.html: всегда рендерятся настоящие 4 сводные карточки (даже маленькие или нулевые), а под ними тёплая подсказка .stats-nudge вместо стены; follower growth и performance spread показывают честные «собираем данные» / «считаем» состояния вместо нулевых графиков. 3.3 — График: few vs many · gap-fill

few (≤ 8 бакетов)

  • Линия и заливка занимают всю ширину панели (SVG viewBox 0–100).
  • Подписи = дни недели (7 days) — все видны.
  • Пунктирная средняя по всем непустым бакетам, подписана «сред.».

many (> 8 бакетов)

  • Линия по-прежнему заполняет ширину — точек на ней просто больше (Month ≈ 30 дневных).
  • Пустые дни — линия проваливается к нулю с приглушённой точкой (.line-gap-dot), не разрывается.
  • Подписи разрежены до ~8 и выходят за ячейку, как и раньше.
Пустого графика как состояния нет. При нехватке данных весь экран уходит в прогрессивную первый-запуск страницу — отдельный «пустой график» не рисуется.

7Чек-лист реализации

  • Полный app-shell; активный пункт = Stats (Insight, без badge); топбар «Stats» + «Обновить» + «обновлено N назад» + тема + Settings.
  • Колонка контента — --content-wide 960; топбар выровнен через .topbar-inner.topbar--wide.
  • «Обновить» — реальный повторный запрос (крутящаяся иконка ~700мс), после которого подпись сбрасывается на «только что»; подпись растёт сама (мин → часы) между обновлениями.
  • Период — сегмент из 6 фиксированных опций 1:1 с backend; дефолт 7 days; скрыт целиком (не задизейблен) во время загрузки и на первом запуске.
  • Сводка — 4 карточки (Posts / Views / Likes / Comments), каждое число text-h1, sub + дельта vs предыдущего периода; All time → «no prior period».
  • Тренд — area-line, не столбцы: непрерывная линия+заливка, gap-fill (пустые = провал к нулю с приглушённой точкой, не дыра); пунктирная средняя по непустым, подписана «сред.»; подписи оси разрежены до ~8.
  • Лучшее время — одна тепловая карта (7 дней × 6 слотов часа), не два столбчатых графика; легенда «меньше»/«больше»; цвета — токены --color-heat-1…4 (свой набор в тёмной теме); пустые ячейки — отдельное дэшед-состояние, не самый тусклый цвет шкалы; лучшая ячейка (≥2 поста) обведена + чип «Лучшее · …»; скрыта для Today/Yesterday.
  • Top posts: топ-5 по просмотрам, ранг + сниппет (2 строки) + мета (date · views/likes/comments) + вердикт «N× your average» (success ≥1.5× / plain ≥0.7× / muted ниже); строка ведёт в Threads.
  • Performance spread: 4 тира (Viral/Good/Average/Weak) с цветами viral=success, good=accent, average/weak = ink-микс; count + % + бар.
  • .stats-empty нигде не возвращён; вместо него первый запуск (реальные 4 карточки + .stats-nudge) — см. First-Run-SPEC.html. Состояния: Live / Loading / First-run; error-состояния нет; loading-скелет повторяет итоговую раскладку.
  • Корректно в светлой и тёмной теме; ни одного hardcoded-цвета (только семантические токены, включая heat-1…4).
  • Копи расширяется в 8 локалях без клиппинга; проверено на 360px; подписи графика и «обновлено N назад» — живой текст.
  • Порядок панелей: период → сводка → Подписчики → Средние просмотры на пост → Лучшие посты → Лучшее время для постов → Распределение по эффективности.
