Engagement · /app/stats panel

A new Engagement chart panel for the Stats dashboard — the sibling of the existing Follower-growth chart and styled from the same line. It shows how the account's engagement evolves over time (a per-day time series of the selected metric) plus the account-wide lifetime totals. The series switches between Views (headline) · Likes · Replies · Reposts · Quotes; an optional range control swaps the window (30d / 90d / 1y). Every state is here — loading, thin-data, populated, error — in light and dark, on the real component layer. The frames below are live: hover the chart to see the per-point tooltip.

engagement.css stats.css stats-followers.css ds/tokens.css ds/components.css
Same chrome, same line as the Follower panel. The outer card is the existing .spanel; the chart reuses the Follower line's exact treatment — a 2.2px accent stroke, a soft accent area, and a dot on the latest point. It sits in the Stats panel stack right after Follower growth. This document pins its tokens the same way the Stats spec does: light from :root, dark via the .dark class, so both themes live side by side.
One deliberate difference: this axis is 0-based. Follower growth is min–max scaled because it is a cumulative count (small daily change against a big number). Engagement is a per-day metric — a quiet day belongs on the floor. So the engagement line starts from 0 with a faint floor rule. This is what keeps the honest cases readable: the Views series is real and backfilled (from 2024-04-13), but per-day Likes / Replies / Reposts / Quotes are sparse for older days — only recent days carry them. A mostly-zero-then-real series reads as empty, then real — never a fake plateau. The lifetime tiles are the reliable account-wide figures.

1What this panel is

A read-only analytics panel on the Stats screen. It answers two questions at once: how is engagement trending (the time series) and how much has this account earned in total (the lifetime tiles).

PlacementA panel in the Stats stack on /app/stats, directly after Follower growth. Full content width (--content-wide 960 on desktop).
PurposeShow how the account's engagement evolves over time for one selected metric, plus account-wide lifetime totals. Read-only — no mutations.
MetricsViews (default / headline) · Likes · Replies · Reposts · Quotes. One series shown at a time; the selector switches it.
Range30d · 90d · 1y (default 90d). Independent of the Stats period selector — this panel owns its own window. The series is gap-filled / continuous (empty days are 0).
Lifetime tilesFour account-wide totals — Likes · Replies · Reposts · Quotes — from the latest snapshot. Reliable even when the per-day series is sparse. Null when the account has no snapshot yet.
Statesloading (skeleton, no reflow) · thin-data (fresh account, history still building) · populated · error (couldn't load + Retry).
HonestyViews = real, backfilled from 2024-04-13. Likes/Replies/Reposts/Quotes per-day = recent-only (older days truly 0). The 0-based axis renders that gracefully; the lifetime tiles carry the real account-wide numbers.

NEW2.3 — Time series + tooltip .echart-plot

The line. Same visual language as the Follower chart — accent 2.2px line, soft accent area, dot on the latest point — but 0-based with a faint floor rule, a per-point hover tooltip (day + value), and sparse x-axis labels. The headline above it shows the selected metric's window total + its trend vs the previous equal window.

Element / classDescription
.echart-hlHeadline: .ehl-label (metric name) + .ehl-num (--text-h1, window total) left; .ehl-delta (up=success / down=danger / flat) + .ehl-sub «vs previous …» right.
.echart-plot / .echart-svgheight 150 (phone 132). SVG viewBox 0 0 100 100; preserveAspectRatio:none; line is non-scaling-stroke.
.echart-line / .echart-areaLine stroke accent 2.2; round; area fill mix(accent 12%) to the floor. 0-based Y.
.echart-floorFaint dashed rule on the 0 baseline — mix(text 14%). Makes the floor read as a real axis.
.echart-dotLatest-point dot: 9×9 accent + mix(accent 18%) ring.
.echart-bands / .echart-bandEqual-width invisible hover bands; the hovered band lights a cursor line, a hover dot, and the tooltip.
.echart-tipTooltip: .echart-tip-day (weekday + date) + .echart-tip-val (formatted value). bg text; color bg; shadow-md.
.echart-xaxis / .echart-xlabel~5 sparse date labels, absolutely placed; first/last clamp to the edges so they never clip.
0-based, not min–max. A per-day metric belongs on a 0 floor — that is the whole point of the honesty rule. When the older half of a Likes/Replies series is genuinely 0, the line lies flat on the floor and then rises out of it; it never invents a plateau. Compare the Follower line, which is min–max precisely because it is a count that should never touch 0.

3States

All four required states. Loading mirrors the populated layout so nothing reflows; thin-data is an honest «still building» treatment, never a fake flat line; error offers a Retry.

loadingthin-datapopulated ●error

3.1 — Loading (skeleton, no reflow)

A skeleton that mirrors the ready layout exactly: header line, metric-tab placeholder, headline block, the chart rectangle, and the four lifetime tiles. Same heights as the real panel, so the moment data lands nothing jumps.

3.2 — Thin data (fresh account)

The series accrues from connect-time, so a fresh account has only a handful of points. We do not draw a long fake flat line. Instead: the few real points are plotted honestly at the left, the un-collected stretch is hatched (reads as «not yet», not «zero»), and a footnote says how many days exist and that it's building daily. The lifetime tiles show «—» until the first snapshot lands.

Element / classDescription
.echart-thindashed border; radius-md; bg mix(surface-2 45%) at the chart's height — no reflow vs populated.
.echart-thin-gridHatched fill over the whole plot — the «history still building» texture.
.echart-thin-svgThe few real points as a short accent line + dots, anchored left over the real days only.
.echart-thin-noteFootnote strip: <chart> glyph + «N days of history so far — building daily.»

3.3 — Error + Retry

When the endpoint fails, the chart + tiles area is replaced by a compact error tile: a danger-tinted glyph, «Couldn't load engagement», a one-line reason, and a Retry button. The header (caption + range) stays so the panel keeps its place in the stack.

Element / classDescription
.echart-errorflex-column; center; dashed border; radius-md.
.echart-error-mark42×42, bg mix(danger 12%); border mix(danger 28%); color danger, <alert> glyph.
.echart-retrySecondary button: <refresh> + «Retry» — bg surface; border; hover surface-2.

4The five metrics

Each metric over 90d. Views is a full, real, backfilled series. Likes / Replies / Reposts / Quotes are recent-only — the older two-thirds of the window are genuinely 0, so the line rests on the floor and then climbs. The headline shows the window total; when the previous window had no data the trend reads «no prior window» rather than a fake percentage.

5Layout · Web ↔ Mobile

Same panel, two widths. Full mobile pass — Engagement-Mobile-SPEC.html.

Desktop ( > 760 )

  • Header: caption left, range control right, on one line.
  • Metric selector fills the panel width; all 5 tabs visible.
  • Headline value left, trend right; chart at 150px.
  • Lifetime tiles in a 4-up row.

Phone ( ≤ 600 )

  • Range control wraps under the caption if tight.
  • Metric selector scrolls horizontally (icons keep tabs compact); ≥44px hit.
  • Chart at 132px; tooltip on tap/drag; labels stay sparse.
  • Lifetime tiles drop to 2-up.

  • Range is a client window over points[] — 30d / 90d / 1y, default 90d (contract default 120). The panel owns this window independently of the Stats period selector.
  • Headline trend = current window total vs the previous equal window. If the previous window has no data (sparse metric) → «no prior window».
  • Charts are hand-rolled CSS/SVG — no chart library — matching the Follower line.
