Pennedly · Спецификация · Новый верхний экран

Дашборд аккаунта /app · портфельный home

Новый верхний экран Pennedly — не доработка read-only Overview, а отдельный home поверх всего портфеля. Продукт стал мульти-сетевым портфельным: Аккаунт (логин) → Бренд (единица голоса) → Профиль (соц-аккаунт в одной сети). Дашборд — ОДИН компонент, параметризованный числом брендов: при одном бренде (дефолт почти у всех) карточки = профили, клик ведёт прямо в Студию; при 2+ брендах те же карточки становятся брендами со сводной статистикой, и между аккаунтом и профилем появляется ещё один уровень — без отдельного экрана. Сверху — советник аккаунта (тот же помощник, scope = весь портфель) первым классом, портфельная статистика, плоский переключатель профилей и переменный breadcrumb. Всё на токенах ДС (светлая + тёмная); текст русский, раскладка держит 8 локалей (эталон длины — немецкий) по правилам 1–2.

+ AccountDashboard + BrandCard + AccountAdvisor + FlatProfileSwitcher + Breadcrumb account.css ds/tokens.css import-banner.css
Критерий приёмки — раскладка (правила 1–2).
  • Правило 1. Однострочные элементы — значения метрик/итогов, счётчики, бейджи, чипы, @никнеймы, названия брендов, метки кнопок, короткие подписи — никогда не переносятся и не толкают соседа вниз. Это заложено в дизайн (короткие метки, запас контейнеров, меньше колонок на узком), а не патчится постфактум; крайний предохранитель — усечение многоточием, не разрыв строки. Доказано в §13 на узком окне десктопа, а 320px — в мобильной спецификации.
  • Правило 2. Текст русский, контейнеры рассчитаны на самую длинную локаль (немецкий, ~1.3–1.5× к ru). Немецкая длина показана и держит правило 1 (§13; переключатель локали в живом дашборде §3).
Один продукт с кокпитом профиля, но другой экран. Та же ДС, та же метрика, те же значки сети и хром карточек, что в кокпите профиля — но другая композиция и новый язык формы: Аккаунт = заполненный квадрат, Бренд = контурный квадрат, Профиль = круг. Форма кодирует уровень иерархии с первого взгляда. Пустой аккаунт (ни одного профиля) сюда не попадает — гейт ведёт в /app/onboarding, как сегодня.

1Идентификация экрана

Верхний home аккаунта. Порядок сверху вниз: sidebar(аккаунт) | main(topbar(breadcrumb + переключатель) → шапка+портфель → «Требует тебя» → советник → карточки). Read-only, кроме Retry на сбое синка и быстрых полей советника.

Маршрут/app — верхний уровень входа после логина. Всегда «Аккаунт», не один профиль. Профиль ≥ 1 обязателен (иначе онбординг).
ТипApp-shell уровня аккаунта. Сайдбар — глобальная навигация аккаунта (Дашборд / [Бренды] / Советник / Настройки) + логин-переключатель. Это не профильное меню (Студия/Ответы/Статистика живут на уровне профиля и не меняются).
НазначениеДать масштаб портфеля одним взглядом, вердикт советника по всему аккаунту и вход в любой профиль/бренд в один клик.
Ширинаwide = --content-wide 960. Сайдбар 232 + колонка контента.
Режимы (карточки)one_profile · single_brand → карточки профилей; multi_brand → карточки брендов. Один компонент, см. §2.
Фазыloading (скелет) · ready. По профилю: synced / importing / error. Пусто (0 профилей) → /app/onboarding, на экране не рисуется.

2ядроАдаптивная модель — один компонент, не три клика

Три уровня данных, но интерфейс показывает только то, что реально есть. Бренд существует у каждого (минимум один, создаётся при регистрации), но становится видимым уровнем навигации лишь с 2+ брендами. Пока бренд один — он невидим, и карточки дашборда = профили этого бренда напрямую.

всегда@
Уровень 3
Профиль

Соц-аккаунт в одной сети (сегодня Threads). Круг + значок сети. Свой дашборд/помощник/настройки — остаётся как есть.

Как один компонент даёт оба режима. Сетка, хром, метрики и стиль — одни и те же; меняется только сущность карточки. 1 бренд → карточка = профиль, клик → Студия (бренд не виден вообще). 2+ брендов → карточка = бренд (сводная статистика + стек профилей + сети), клик → дашборд бренда, который раскрывает профили. Появление второго бренда не выглядит как другой экран — просто между аккаунтом и профилем встаёт уровень.

4newСайдбар аккаунта + логин-переключатель

Глобальная навигация уровня аккаунта — общая по всему логину, отдельная от профильного меню. Пункт Бренды появляется только при 2+ брендах (как и сам уровень). В подвале — логин-переключатель (email + тариф): он меняет сам логин/тенант, а не профиль внутри него (это делает плоский переключатель из §5).

4.1 — Логин-переключатель (меню вверх)

Шапка = текущий логин (email + тариф). Список других логинов того же человека, «Добавить аккаунт», затем настройки аккаунта и выход. Это тенант-переключатель — не профили.

5Breadcrumb + плоский переключатель профилей

Два обязательных элемента навигации, не зависящих от числа брендов.

5.1 — Breadcrumb с переменным числом сегментов

Один компонент, столько сегментов, сколько реально есть: «Аккаунт» (этот экран), «Аккаунт / профиль» (1 бренд), «Аккаунт / Бренд / профиль» (2+ брендов). Не два разных дизайна — одна логика, формы марок кодируют уровень.

5.2 — Плоский быстрый переключатель профилей

Прямое продолжение сегодняшнего AccountSwitcher: один клик к любому профилю с любого экрана, независимо от бренда. С появлением брендов переключение профилей не становится медленнее — в режиме 2+ профили просто сгруппированы подписями брендов, но это по-прежнему один плоский список. Статус-точка справа = синхронизирован / импорт / сбой.

6Шапка аккаунта + портфельная статистика

Совмещены в верхней полосе: слева — идентичность аккаунта (марка, имя, тариф, масштаб «N профилей [в M брендах] · сети»), справа — итоги по всему портфелю (Подписчики +Δ · Просмотры 7д · Посты нед · Ответы [accent]). При 1 бренде это и есть вся статистика — отдельной «по брендам» не существует. На узком итоги переносятся под идентичность (см. §13), метки — одно слово, деталь в подписи (правило 1).

7опционально — предложеноТонкая полоса «Требует тебя»

Предложение: тонкий агрегат дел по всему аккаунту над карточками — не герой-очередь профильного кокпита, а одна строка чипов (сбой синка · ответы · черновики · аудиты) со ссылкой «Разобрать всё». Даёт портфельное «что требуется» одним взглядом, не дублируя полную очередь, которая живёт внутри профиля. Чип сбоя синка — в danger-тоне.

8new · heroСоветник аккаунта

Первый класс на экране. Форма: карточка-сводка, а не голый мини-чат — на дашборде нужен взгляд, а не приглашение печатать. Тот же компонент, что профильный советник (/app/advisor), но scope = весь портфель: вердикт + короткий разбор, привязанные data-чипы (grounding), строка «на основе…», и быстрый ввод, открывающий полный чат. Справа — рельса рекомендаций поверх брендов/профилей, каждая ведёт в нужный экран. Кнопка «Открыть советника» — в полный чат.

9Карточки — режим «1 бренд» (профили)

Дефолт почти у всех. Карточка профиля: круглый аватар + значок сети + @никнейм + сеть, метрики (Подписчики +Δ · Просмотры 7д · Посты нед · Ответы), строка синка и quick-links. Клик → дашборд профиля (Студия). Метка метрики = одно слово, число — tabular nowrap (правило 1).

9.1 — Статусы профиля: importing / sync-error

Профиль в первичной загрузке показывает Phase-0 баннер импорта вместо метрик; сбой синка — приглушённые метрики + «● Сбой синка» и Retry на месте. Сбой также поднимает чип в полосе «Требует тебя».

10Карточки — режим «2+ брендов» (бренды)

Появляется со вторым брендом. Карточка бренда: контурно-квадратная марка + значки сетей + имя бренда + «N профилей · тип», стек аватаров профилей, сводные метрики по его профилям и строка состояния («Все синхронизированы» / «N импортируется» / «N сбой синка»). Клик → дашборд бренда. Кнопка «Профили» раскрывает профили внутри карточки.

10.1 — Раскрытие бренда: статусы профиля внутри

Развёрнутый бренд показывает свои профили строками — и importing, и sync-error видны прямо здесь (тот же статус, что на прямой карточке профиля в режиме 1 бренда). Доказывает требование «покажи статус и на карточке профиля, и внутри развёрнутого бренда».

11Добавить бренд

Заметная карточка-CTA в той же сетке (пунктир, accent). Это единственное действие, делающее бренд-уровень видимым: до первого клика по ней пользователь брендов не видит вовсе. После создания второго бренда карточки дашборда переключаются с профилей на бренды.

13правила 1–2Проверка раскладки

Доказательство критерия. Тот же дашборд в жёстких условиях: узкое окно (контейнер 720 и 600px — сайдбар сворачивается, итоги и карточки переходят в один ряд) и немецкая длина (самая длинная локаль). 15Локализация · i18n

Весь текст ключевой (nav.*, advisor.*, switcher.*, card.*) в 8 локалях: en · ru · uk · de · es · fr · it · pt. ru — ревью, de — эталон длины. Контейнеры рассчитаны на самую длинную локаль; числа tabular; @никнейм всегда LTR; плюрали («N профилей», «N брендов») через ICU локали.

Ключenru (ревью)de (длиннее)
Плюрализация. Масштаб «N профилей в M брендах» считает обе плюрали по правилам локали (ru: профиль/профиля/профилей, бренде/брендах). Длинные подписи усекаются на своей строке — выравнивание соседей не сбивается (правило 1).

16Web ↔ Mobile

Брейкпоинты: 1080 (итоги портфеля переносятся под идентичность) · 920 (советник в один столбец) · 880 (сайдбар → верхний рейл/drawer) · 720 (карточки 1-в-ряд) · 600 (телефон). Полный телефонный проход: Account-Dashboard-Mobile-SPEC.html.

Десктоп ( > 880 )

  • Фикс. сайдбар аккаунта, Дашборд активен; breadcrumb + переключатель в топбаре.
  • Шапка с итогами в строку; советник 2-колоночный; карточки 2-в-ряд.
  • Логин-переключатель = меню-вверх в подвале сайдбара.

Телефон ( ≤ 600 )

  • Без сайдбара; брендмарк + breadcrumb сверху; кнопка аккаунта внизу → нижний лист.
  • Плоский переключатель = полноширинная кнопка/лист; итоги 2×2; советник в столбик.
  • Карточки в столбик; раскрытие бренда — те же строки профилей; Retry на месте.

17Чек-лист

  • Правило 1: ни один однострочный элемент (метрики, итоги, счётчики, бейджи, @никнеймы, имена брендов, метки кнопок) не переносится и не толкает соседа — на узком десктопе, мобильном и 320px. Не влезает → усечение, не разрыв.
  • Правило 2: текст русский; контейнеры держат немецкую длину (§13, локаль de в §3) без нарушения правила 1.
  • Один компонент, два режима: 1 бренд → карточки профилей (клик → Студия); 2+ → карточки брендов (клик → дашборд бренда). Та же сетка/хром; бренд-уровень невиден до 2-го бренда.
  • Сайдбар уровня аккаунта (Дашборд / [Бренды при 2+] / Советник / Настройки) + логин-переключатель внизу; это не профильное меню.
  • Плоский переключатель профилей — один клик к любому профилю независимо от бренда; breadcrumb с переменным числом сегментов (Аккаунт / [Бренд] / профиль).
  • Советник аккаунта первым классом: вердикт + привязанные чипы + рекомендации поверх портфеля + вход в полный чат (scope = аккаунт).
  • Портфельная статистика совмещена с шапкой; суммирует только synced; «+N импортируется».
  • Карточка «Добавить бренд» в той же сетке — единственный вход к бренд-уровню.
  • Статусы importing / sync-error видны и на карточке профиля, и внутри развёрнутого бренда; Retry на месте.
  • Значок сети на каждом профиле (Threads сегодня, нейтральный бейдж под LinkedIn).
  • Светлая + тёмная на токенах; ?demo=1 Tweaks: режим · состояние · локаль · тема (§3). Пустой аккаунт → онбординг, здесь не рисуется.
