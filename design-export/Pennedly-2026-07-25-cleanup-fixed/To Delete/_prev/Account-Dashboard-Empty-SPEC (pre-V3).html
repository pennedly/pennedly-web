Дашборд аккаунта — пустые состояния /app/account · 0 живых профилей

Не новый экран, а новые состояния существующего дашборда аккаунта. Сегодня рабочий кабинет требует хотя бы один живой профиль: при нуле подключённых профилей шелл жёстко редиректит в полноэкранный мастер подключения, и весь хром (сайдбар, идентичность, переключатель) исчезает. Пользователь, отключивший последний профиль — или у которого молча протух токен, — попадает в мастер нового пользователя и чувствует себя разлогиненным, хотя сессия и все данные целы. Мы делаем дашборд, который существует ПОВЕРХ профилей — для всех, КРОМЕ брэнд-нью пользователя: у брэнд-нью (0 профилей когда-либо) ещё ничего нет, поэтому ему показывается полноэкранный первый вход с пикером сетей (см. Connect-Network-Picker-SPEC). Всем остальным — полный хром в дашборде: «все отключены», «смешанное», плюс скелет загрузки и ErrorBanner. «Подключить другой» и «Переподключить» открывают тот же пикер сетей (Threads live · LinkedIn «скоро»). Всё на токенах ДС (светлая + тёмная), общий шелл, статус-пилюли и дисциплина §3.8; текст русский, раскладка держит 8 локалей (эталон длины — немецкий).

+ ACCE.stateShell + networkPicker + disconnectedCard + reassure + errorBanner account.css account-empty.css ds/tokens.css
Критерий приёмки. Во всех in-dashboard состояниях (все отключены · смешанное · загрузка · ошибка) сохраняется полный хром — сайдбар с меню аккаунта, логин-переключатель в подвале и топбар. Отключивший последний профиль больше не выкидывается в мастер; брэнд-нью получает полноэкранный первый вход (пикер), а не мастер. Никаких фейковых метрик и пустых карточек. Однострочные элементы не переносятся (Rule 1); контейнеры держат немецкую длину (Rule 2).

1Идентификация + сдвиг поведения

Экран тот же, что Account-Dashboard-SPEC — меняется только то, что происходит без живых профилей. Раньше это был гейт в онбординг; теперь это состояния самого дашборда.

Было

0 профилей → редирект в /app/onboarding. Полноэкранный мастер, хром скрыт. Отключивший последний профиль ощущает себя разлогиненным, хотя данные целы.

Стало

Отключился последний профиль → дашборд с полным хромом. Сайдбар + меню + топбар на месте; отключённые профили с «Переподключить». Брэнд-нью (0 когда-либо) → полноэкранный пикер сетей.

Маршрут/app/account — верхний уровень входа после логина. Существует поверх профилей, не требует ни одного живого.
Хром (всегда)Сайдбар уровня аккаунта (Дашборд / Советник / Настройки) + логин-переключатель в подвале; топбар с breadcrumb «Аккаунт». Идентичны базовому дашборду.
СостоянияПервый вход (0 профилей когда-либо) → полный экран, пикер сетей (отд. спека). В дашборде: all_disc (были, все отключены) · mixed (≥1 живой + ≥1 отключён) · loading · error.
ДействияConnect / Подключить другой / Reconnect открывают общий пикер сетей (Threads live · LinkedIn «скоро»). Threads → существующий OAuth-флоу (кнопка → редирект); Reconnect — тот же флоу на известный @handle. Не новый экран.
Вне охватаУдаление аккаунта, биллинг, настройки профиля, бренд-уровень (2+). Здесь не рисуются.

3pickerПодключение · пикер сетей

Брэнд-нью пользователь (0 профилей когда-либо) сюда не попадает — ему показывается полноэкранный первый вход с пикером сетей (Threads live · LinkedIn «скоро»); он вынесен в Connect-Network-Picker-SPEC. В дашборде тот же пикер открывают «Подключить другой» (§4) и «Переподключить» (карточка §6) как поповер. Threads → OAuth; Reconnect нацелен на известный @handle, данные целы.

4состояние 2 · heroВсе отключены

Профили были, но сейчас все отключены (токен протух или пользователь отключил их). Тот же хром. Это главный анти-«я потерял рабочий кабинет» момент: сверху — баннер уверенности («данные, настройки, голос и история сохранены — переподключение всё вернёт»), затем идентичность аккаунта без фейковых итогов, и каждый ранее подключённый профиль — карточкой с пилюлей status-pill--warning «Отключён» и явной кнопкой «Переподключить», плюс вторичная «Подключить другой аккаунт» (открывает пикер сетей).

5состояние 3Смешанное

≥1 живой + ≥1 отключён. Нормальный заполненный дашборд (шапка + итоги + «Требует тебя» + советник + карточки), но отключённые профили рисуются с пилюлей «Отключён» и inline «Переподключить» вместо живых метрик — мёртвый профиль виден и восстановим, а не спрятан. Здесь рядом: synced, отключён (@mara.studio), сбой синка (@mara.co, danger — отличается от «Отключён») и importing.

6Карточка «Отключён» — анатомия

Переиспользуемый блок (и в §4, и inline в §5). Аватар приглушён (идентичность крепкая, активность выключена), @никнейм + имя чёткие. Пилюля status-pill--warning «Отключён» + «Данные сохранены», строка disconnected_at и primary «Переподключить». Тон — warning, не danger: это восстановимое состояние, отличное от сбоя синка.

7Загрузка · скелет

Стандартный скелет — повторяет раскладку дашборда (шапка → советник → карточки), общий с базовым экраном. Появляется, пока GET /api/me/account в полёте.

8§3.8Ошибка · ErrorBanner

Общий инлайн-ErrorBanner (window.ErrorBanner, §3.8) в контентной области — хром сохраняется. Danger-марка, «Не удалось загрузить аккаунт», подкопия «данные в безопасности» и Retry. Тот же класс .error-banner, что в Feed / Replies / Mentions.

9Данные · контракт

Тот же запрос, что базовый дашборд: GET /api/me/account. Бэкенд отдаёт и отключённые профили с disconnected_at; клиент решает состояние по числу живых и отключённых профилей.

КлючПоляКуда идёт
profiles[]…, sync_status (synced|importing|error), connection (live|disconnected), disconnected_atЖивые → обычные карточки; disconnected → карточка «Отключён»
accountname, email, planИдентичность (сайдбар · шапка · логин)
totalsсуммируют только synced живые; при 0 живых — не рисуютсяИтоги (только в mixed)

Разрешение состояния (клиент)

  • live == 0 && ever_connected == false → полноэкранный первый вход (пикер сетей, не в дашборде — Picker).
  • live == 0 && disconnected > 0 → all_disc — баннер уверенности + карточки «Отключён».
  • live ≥ 1 && disconnected ≥ 1 → mixed — обычный дашборд; отключённые inline.
  • Запрос в полёте → loading; сбой запроса → error (Retry перезапускает).
  • Гейт в онбординг снят: live == 0 больше не редиректит — рисуется дашборд.

11Web ↔ Mobile

Те же состояния на телефоне: полный шелл сохраняется (гамбургер → drawer навигации аккаунта + логин; докнутая кнопка профилей). Полный проход — Account-Dashboard-Empty-Mobile-SPEC.html.

Десктоп ( > 880 )

  • Фикс. сайдбар аккаунта + топбар во всех состояниях.
  • Пустое состояние центрировано; карточки «Отключён» 2-в-ряд.
  • Слот переключателя: отключённый переключатель (all_disc) / обычный (mixed). «Подключить другой» / «Переподключить» → пикер сетей.

Телефон ( ≤ 600 )

  • Без сайдбара; гамбургер → drawer + логин остаются.
  • Пустое состояние и карточки «Отключён» в столбик; Reconnect на всю ширину.
  • Докнутая кнопка → лист профилей (в all_disc — с отключёнными).

12Чек-лист

first-connect · fullscreenall-disconnectedmixedloadingerrorru · delight · dark
  • Полный хром во всех in-dashboard состояниях: сайдбар + меню аккаунта + логин-переключатель + топбар. Отключивший последний профиль больше не редиректит в онбординг.
  • Первый вход (0 профилей когда-либо): полноэкранный пикер сетей (Threads live · LinkedIn «скоро») + «что дальше» — не в дашборде (см. Picker). Без фейковых метрик.
  • Все отключены: баннер уверенности (данные целы, reconnect всё вернёт) + идентичность без итогов + карточки с status-pill--warning «Отключён» + «Переподключить» + «Подключить другой аккаунт».
  • Смешанное: обычный дашборд; отключённые профили inline с пилюлей + «Переподключить» вместо метрик — видимы и восстановимы.
  • Отключён ≠ сбой синка: warning-тон + Reconnect против danger-тона + Retry; распознаются с первого взгляда.
  • Скелет загрузки повторяет раскладку; ErrorBanner (§3.8) с Retry, данные в безопасности.
  • Connect / «Подключить другой» / Reconnect открывают общий пикер сетей; LinkedIn — disabled «скоро» везде. Threads → OAuth; Reconnect → на известный @handle. Не новый экран.
  • Светлая + тёмная на токенах; Rule 1 (нет переносов) и Rule 2 (немецкая длина) держатся; 8 локалей.
