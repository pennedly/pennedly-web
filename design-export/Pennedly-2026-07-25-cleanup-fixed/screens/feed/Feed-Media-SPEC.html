Pennedly · Spec · My Feed — render post media

Post media /app/feed — every type & state

Published Threads posts can carry media authored in Pennedly or in the Threads app. This spec extends the existing My Feed card — it does not redesign it — by adding a single media block between the post text and the metrics row, inside card padding, full width. A post has exactly one block (one image, one carousel, one video…) — media never stacks; a text-only post shows no block (today’s look). Every type is rendered in all its states, on the real product layers (feed.css for web, pennedly-mobile.css for phone) over ds/tokens.css — for the web feed column and at 390px, in light and dark.

feed-media.css feed-card.jsx feed-parts.jsx feed.css pennedly-mobile.css ds/tokens.css
What stays the same. The header (avatar · name · @handle · time · viral badge), the post text, the metrics row (views / likes / comments / reposts) + growth, and the footer (auto-replies · Growth · Open on Threads · ⋯) are all unchanged. Media is purely additive — a new block slotted between text and metrics. Same tokens, same calm/editorial language: rounded corners, 1px borders, soft shadows, single-weight line icons, full light + dark.

0Where the media block goes

One slot, between the post text and the metrics row, inside the card’s padding and spanning its full width. It respects the card rhythm (≈14px above, metrics follow), never overpowers the post, and keeps the feed scannable. Exactly one block per post.

＊Auto-reply flag per-post

A small toggle pill in the card foot (left of the actions) marks whether Pennedly auto-replies to this post’s new comments — the per-post override that populates Autopilot’s “Selected” reply mode (see Autopilot). On = accent pill (bg-accent/12, accent border + text, IcReply); Off = neutral pill (bg-surface-2, muted, a hollow ring). It stays small and secondary — it never competes with the metrics row. Toggling fires a toast.

How A & B relate. Autopilot All → every post is on by default; Selected → only flagged posts are on; Off → none. This pill is how “Selected” is populated. The flag is a per-post override (auto_reply nullable; NULL = inherit the mode). Toast copy: “Auto-replies on/off for this post” + a sub line.

＊New icons needed

The media block reuses the existing set wherever possible (eye, heart, bubble, repost, chart, clock, external, globe, link, alert, check, more, reply, arrows). These few are genuinely new — add them to icons.tsx in the same 24-grid / 1.8-stroke family (play & pause are filled). The “GIF” chip is a text label, not an icon.

Usage. IcPlay — video + carousel video badge + audio play. IcPause — video scrubber + audio. IcVolume / IcMute — muted-autoplay chip + future audio mute. IcImage — image placeholder/fallback. IcExpand — tap-to-expand affordance. IcPoll — poll affordances. No other new tokens are introduced.

1Single image

Full width, rounded, aspect-aware. Tall images are capped at ~4:5 so one post never eats the feed; a subtle “tap to expand” chip invites the lightbox. States: loaded · loading skeleton · failed (muted placeholder + “image unavailable”).

— lightbox (tap to expand)

Tapping the image (or its expand chip) opens a full-bleed viewer over the feed: close · count · Open on Threads, the image centered, and the alt text carried into the caption. From a carousel it opens to the tapped item with ← → and Esc.

2Carousel

2–20 items, images and/or video mixed, horizontal + swipeable. Dot indicators with a small count badge (“1 / 4”) top-right; the first item is the preview; video items show a play badge. Mobile: edge-swipe. Web: arrows on hover + swipe.

3Video

Poster image + centered play badge + a small duration chip (“0:42”) bottom-right. Click-to-play inline (or open-in-Threads fallback); a muted-autoplay-in-view variant is shown too. States: poster · playing · autoplay (muted) · processing/unavailable fallback.

4GIF

Auto-looping, muted, lighter than a video frame — a small “GIF” chip and no duration chip. Honors reduced-motion (the loop pauses).

5Audio display only

Never composed in Pennedly — but external posts carry it, so the card renders it. A compact one-line player: play/pause · a slim waveform/progress bar · elapsed / total. States: idle · playing.

No audio attach. Audio appears in display only — there is no audio compose/attach anywhere in Pennedly.

6Link card

Pennedly generates the preview itself from OpenGraph (the Threads API returns only the raw URL). A horizontal card: thumbnail (left on web / top on mobile) + title (2 lines max) + domain; the whole card is a link with an external-link affordance. States: loaded · loading skeleton · preview unavailable.

Unavailable degrades cleanly. Because we generate previews ourselves and they can fail, the fallback shows no thumbnail — a tidy domain + raw-URL chip — so the card never looks broken.

7Poll

The question is the post text; below it, option rows with horizontal % bars, and a total. Read-only here — open shows current standings; closed emphasizes the winner.

8Quote / repost

An embedded inset mini-card of the quoted/reposted post: small avatar · @handle · time · truncated text (3 lines) · a small media thumbnail if it has one. Bordered + indented to read as nested. States: loaded · loading (second fetch → skeleton) · post unavailable (deleted/private).

9None (text only)

A plain text post shows no media block — today’s card, included here for contrast.

＊Motion & alt-text

Reduced motion

  • No autoplay: video autoplay-in-view and GIF loops are paused under prefers-reduced-motion: reduce — poster/first-frame shown with the play badge.
  • Skeleton shimmer (image / link / quote) stops; the static skeleton remains.
  • Carousel/track transitions drop to instant; dots/arrows still work.

Alt text

  • Every media frame carries an alt-text slot — real cards put it on img[alt] / aria-label; the spec surfaces it as the mono alt — ribbon.
  • The lightbox carries the same alt into its caption.
  • Decorative scrim chips are aria-hidden; the waveform is an img with a label; controls have aria-label.
Guardrails. Media never overpowers the card — it sits between text and metrics, respects card padding, caps tall images, and keeps the feed scannable. Audio is display-only. Link previews always include the “unavailable” fallback. One block per post — media never stacks.
