Pennedly · Спецификация · Новый экран (зона аккаунта)

История изменений — что Pennedly поменял за меня

Pennedly всё чаще меняет вещи за пользователя в один клик: Агент создаёт рутины и правила, проверка Голоса применяет фиксы, недельный аудит правит промпты. Раньше каждая поверхность держала свою мини-историю или не держала никакой. Этот экран — единая лента всех применённых изменений из всех источников, с человеческими деталями и (позже) откатом. Один ответ на вопрос «что Pennedly поменял за меня?». Это журнал доверия, а не инженерный лог: никакого JSON, детали всегда переведены в факты. Живые фреймы — реальные DS-компоненты, светлая И тёмная, десктоп и телефон.

Рутины, автоответы, правила голоса, посты, расписание — всё, что Агент собрал и применил по клику.
Фиксы полей, удаление пунктов, интро — что проверка Голоса поправила, со старой и новой версией.
Правки промптов из недельного аудита — суть изменения по-человечески.

Бэкенд уже в проде. Единый журнал пишет каждое применённое предложение из всех источников; API отдаёт записи постранично, свежие сверху. Каждая запись несёт: источник (Агент / Голос / Аудит, список растёт), тип внутри источника, подпись (одна человеческая строка), детали применённого, кто применил + когда, и статус отката. Экран рисуется строго под этот контракт.

1Идея и правда о данных

Каждая запись журнала — это применённое изменение из одной из поверхностей. Рисуем строго под поля контракта; ничего лишнего на экран.

ПолеЧто это · как показываем
источникОдна из трёх поверхностей (список будет расти): Агент, Голос, Аудит. Чип с иконкой, но один спокойный тон — без светофора.
типТип внутри источника: рутина / автоответы / правило голоса / запланированный пост / список тем; фикс поля / удаление пункта / интро; вид аудит-правки. Тихим текстом рядом с подписью.
подписьОдна человеческая строка («Посты про рыбалку», заголовок аудит-правки). Заголовок записи.
деталиВ раскрытии: параметры действия (Агент), «что поменялось» старая → новая версия (Голос/Аудит), ссылка «Открыть» на живой объект.
кто + когда«Применил Агент · сегодня, 14:02». В свёрнутой строке — короткое время, в раскрытии — полная строка.
статус откатаТри состояния: можно откатить · откат недоступен + почему · откачено {дата}. Сейчас у всех записей откат недоступен (фаза бэкенда впереди), но дизайн заложил все три.
Тон: журнал доверия, не лог инженера. Никакого JSON на экране; детали всегда переведены в человеческие факты. Источники различаются иконкой, но живут одной спокойной семьёй (один тон, один акцент). Тексты РУ по умолчанию, без длинных тире.

2Размещение и вход

Экран живёт в зоне аккаунта (/app/account/history), не новым пунктом основной навигации — она и так плотная. Две тихие точки входа ведут к нему.

Точка входаКак выглядит
Настройки аккаунтаСтрока-ссылка «История изменений» (.ch-entryrow, иконка-журнал + подпись + шеврон) в блоке настроек аккаунта. Основной вход.
Экран АгентаТихая ссылка «Что я применил за тебя» (.ch-quietlink) рядом с местом, где действия применяются, — из момента применения ведёт в общий журнал.
Крошки на экранеТопбар зоны аккаунта: крошка «Аккаунт › История изменений» + заголовок. Ширина --content-reading 720 (лента, не данные).
Фильтры по источнику — позже. В первой версии лента короткая, фильтры не рисуем. Место под них заложено: .ch-filterslot справа в тулбаре (рядом со счётчиком «N изменений»). Когда источников/записей станет много, туда встанут чипы-фильтры «Все · Агент · Голос · Аудит», не ломая раскладку.

3Анатомия записи

Строка-запись свёрнута по умолчанию; тап/клик раскрывает человеческие детали. Слева — свёрнутая строка, справа — она же раскрытая.

Элемент / классОписание
.ch-row-head (свёрнутая)Чип источника + подпись + тип (тихий текст) + время + шеврон. Вся строка — кнопка раскрытия; hover подсвечивает.
.ch-srcЧип «Агент» / «Голос» / «Аудит» — один спокойный тон, иконка своя (advisor / nib / audit), акцент только на глифе.
.ch-detail (раскрытие)Человеческие детали. Для Агента — параметры (.ch-params: иконка + факт). Для Голоса/Аудита — «что поменялось» (.ch-diff: «Было» нейтрально → «Стало» с акцентом).
.ch-meta«Применил {источник} · {дата, время}» + ссылка .ch-open «Открыть» на живой объект (рутина в Автопилоте, версия Голоса, аудит).
.ch-rollbackЗона отката в раскрытии: три состояния (ниже §6). Откат — деструктив: кнопка спокойная, действие через подтверждение.
.ch-daygroup / .ch-dayheadГруппировка по дням: «Сегодня» / «Вчера» / «3 июля». Записи дня — в одной карте, разделены хайрлайнами.

4Лента · смешанные источники

Полная лента: 10 записей (Агент нескольких типов, Голос, Аудит), свежие сверху, группировка по дням. Первая запись раскрыта для примера. Внизу — «Показать ещё» (пагинация). Светлая и тёмная.

4.1 — Пустое состояние

Журнал ещё пуст: объясняем, что тут появится, и даём мягкий ход к Агенту.

5Раскрытая запись · 3 источника

Три варианта деталей: Агент (параметры действия), Голос (что поменялось, старая → новая версия), Аудит (суть правки). У каждой — «кто + когда», ссылка «Открыть» и зона отолката.

6Откат · 3 состояния + диалог

Дизайн закладывает все три состояния отката, хотя фаза бэкенда впереди. Откат — деструктивное действие: кнопка спокойная, всегда через подтверждение.

СостояниеЧто рисуется
Можно откатить (будущее)Строка «Можно вернуть прежнее состояние» + спокойная кнопка «Откатить» (undo). Клик → диалог подтверждения.
Откат недоступен (сейчас у всех)Приглушённая строка + причина: «Откат появится позже» / «Изменение перекрыто более новым» / «Необратимое действие». Ссылка «Открыть» ведёт на текущий объект.
Откачено {дата}Строка записи приглушена, бейдж «Откачено 4 июля», в раскрытии «Вернулось прежнее состояние».
Диалог + busy«Откатить {подпись}? Вернётся прежнее состояние». «Отмена» / «Откатить» (деструктив). На откате — спиннер «Откатываю…».
Сейчас откат недоступен у всех записей. Фаза отката на бэкенде ещё впереди, поэтому в живой ленте зона отката рисуется состоянием «недоступен» с честной причиной. Состояния «можно откатить», «откачено» и диалог подтверждения — заложены на будущее и показаны здесь как целевой дизайн.

7Телефон

Референс 390px. Лента и раскрытие складываются в столбик: время уходит под подпись, ссылка «Открыть» — на всю ширину. Диалог подтверждения становится нижним листом (главная кнопка снизу-в-достижимости).

9Чек-лист реализации

  • Экран в зоне аккаунта (/app/account/history), не пункт основной навигации; вход из Настроек аккаунта + тихая ссылка с Агента.
  • Лента: смешанные источники, свежие сверху, группировка по дням («Сегодня / Вчера / дата»); ширина --content-reading.
  • Свёрнутая строка: чип источника (один спокойный тон, иконка своя, без светофора) + подпись + тип тихим текстом + время + шеврон.
  • Раскрытие: детали переведены в человеческие факты (без JSON) — параметры (Агент) или «что поменялось» старая → новая (Голос/Аудит); «кто + когда»; ссылка «Открыть» на живой объект.
  • Откат заложен на 3 состояния: можно откатить / недоступен + почему / откачено {дата}. Сейчас у всех «недоступен» (фаза бэкенда впереди).
  • Откат деструктивен: спокойная кнопка + диалог подтверждения «Откатить {подпись}? Вернётся прежнее состояние» + busy.
  • Пустое состояние: «Здесь появится всё, что Pennedly применит по твоему клику» + мягкий ход к Агенту.
  • Пагинация: «Показать ещё» внизу ленты.
  • Фильтры по источнику не рисуем в первой версии; место заложено (.ch-filterslot) и описано.
  • Телефон: строка складывается, «Открыть» full-width, диалог = нижний лист; проверено на 360px.
  • Обе темы, только семантические токены, один акцент; тон — журнал доверия, без длинных тире.
Конец спецификации. Новый слой: applied-changes.css. Опирается на зону аккаунта (Account-Settings, Account-Advisor) и словарь изменений (Audits, Voice). Токены: ds/tokens.css, ds/components.css.
