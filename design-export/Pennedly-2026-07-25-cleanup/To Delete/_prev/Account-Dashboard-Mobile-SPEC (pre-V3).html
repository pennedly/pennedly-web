Дашборд аккаунта /app · портфель на телефоне

Телефонный парный документ к десктопному дашборду аккаунта. Тот же ОДИН компонент, параметризованный числом брендов: при одном бренде (дефолт почти у всех) карточки = профили, тап ведёт прямо в Студию; при 2+ брендах те же карточки становятся брендами со сводной статистикой. Под большой палец: сверху — шапка аккаунта + портфель (итоги 2×2), тонкая полоса «Требует тебя», советник аккаунта (герой, scope = весь портфель) и сетка карточек в столбик. Два разных контрола аккаунта: гамбургер → drawer — глобальная навигация аккаунта (Дашборд / [Бренды при 2+] / Советник / Настройки) + логин-переключатель в подвале; докнутая кнопка внизу → лист — плоский переключатель профилей в один тап к любому профилю через любой бренд. Текст русский; раскладка держит 8 локалей (эталон длины — немецкий) по правилам 1–2; проверено до 320px.

account-mobile.css + AccountHeader + AccountAdvisor + BrandCard + FlatSwitcher sheet + AccountNav drawer pennedly-mobile.css
Критерий приёмки (правила 1–2). Однострочные элементы — значения метрик/итогов, счётчики, бейджи, чипы, @никнеймы, названия брендов, метки кнопок, вердикт советника — никогда не переносятся и не толкают соседа вниз. Это заложено в дизайн (короткие метки, запас контейнеров, один столбец, метрики 2×2), а не патчится постфактум; крайний предохранитель — усечение многоточием, не разрыв строки. Текст русский; контейнеры держат немецкую длину. Доказано в §13 на 390, 360 и 320px и на немецкой длине.
Один продукт с десктопом, другой форм-фактор. Те же токены, метрики, значки сети и язык формы марок: Аккаунт = заполненный квадрат, Бренд = контурный квадрат, Профиль = круг. На телефоне сайдбар аккаунта уходит в drawer, а плоский переключатель профилей — в докнутую кнопку → лист (продолжение сегодняшнего AccountSwitcher). Пустой аккаунт (0 профилей) сюда не попадает — гейт ведёт в /app/onboarding.

1Идентификация

Маршрут/app — верхний уровень входа после логина. Всегда «Аккаунт», не один профиль. Профиль ≥ 1 обязателен (иначе /app/onboarding).
Сверху внизСтатус-бар → топ-бар (гамбургер · «Дашборд» · пилюля «N профилей» · тема) → шапка+портфель → «Требует тебя» → советник → карточки → свободный низ. Доку — кнопка профилей над нижним краем.
Контролы аккаунтаДва разных. Гамбургер → drawer: навигация аккаунта (Дашборд / [Бренды] / Советник / Настройки) + логин-переключатель. Кнопка внизу → лист: плоский переключатель профилей. Это не профильное меню (Студия/Ответы/Статистика живут на уровне профиля).
Режимы (карточки)one_profile · single_brand → карточки профилей; multi_brand → карточки брендов. Один компонент, см. §3.
Read-onlyКарточки и строки — навигация (deep-link); мутирует только Retry на сбое синка и быстрое поле советника.

2Телефонный дашборд

Весь дашборд в контексте, светлая и тёмная: шапка+портфель (2×2) → «Требует тебя» → советник-герой → карточки профилей в столбик (один импортируется, у одного сбой синка), с докнутой кнопкой переключателя профилей над нижним краем.

3ядроАдаптивная модель — один компонент

Три уровня данных, но интерфейс показывает только то, что реально есть. Бренд существует у каждого (минимум один), но становится видимым уровнем навигации лишь с 2+ брендами. Пока бренд один — он невидим, и карточки = профили этого бренда напрямую.

4newШелл · nav-drawer аккаунта · логин

Десктопный сайдбар уровня аккаунта на телефоне уходит за гамбургер в drawer: Дашборд (активен) / Бренды (только при 2+, с бейджем N) / Советник / Настройки аккаунта, плюс отдельная карточка «Добавить бренд». В подвале — логин-переключатель (email + тариф): тап открывает лист логинов (сменить логин/тенант, добавить аккаунт, настройки, выйти). Это не переключение профиля — то делает докнутая кнопка из §5.

Логин ≠ профиль. Drawer-подвал меняет логин/тенант (кого ты залогинен). Докнутая кнопка внизу (§5) меняет профиль внутри текущего логина. Два разных контрола, чтобы ни навигация аккаунта, ни быстрый переход между профилями не мешали друг другу.

5Плоский переключатель профилей + breadcrumb

Два обязательных элемента навигации, не зависящих от числа брендов.

5.1 — Докнутая кнопка → лист профилей (плоский переключатель)

Прямое продолжение сегодняшнего AccountSwitcher: один тап к любому профилю с любого экрана, независимо от бренда. При 2+ брендах профили в листе просто сгруппированы подписями брендов, но это по-прежнему один плоский список — переключение профилей не становится медленнее. Статус-точка справа = синхронизирован / импорт / сбой.

5.2 — Breadcrumb с переменным числом сегментов

Один компонент, столько сегментов, сколько реально есть: «Аккаунт» (этот экран) · «Аккаунт / профиль» (1 бренд) · «Аккаунт / Бренд / профиль» (2+ брендов). Формы марок кодируют уровень; на узком ведущие сегменты ужимаются до марки, текущий сегмент сохраняет подпись — путь не переносится (правило 1).

6Шапка аккаунта + портфельная статистика

Сверху: идентичность аккаунта (марка-квадрат, имя, тариф, масштаб «N профилей [в M брендах] · сети»), затем итоги по всему портфелю сеткой 2×2 (Подписчики +Δ · Просмотры 7д · Посты нед · Ответы [accent]). При 1 бренде это и есть вся статистика. Метки — одно слово, деталь в подписи; числа tabular, nowrap (правило 1).

7опционально — предложеноПолоса «Требует тебя»

Тонкий агрегат дел по всему аккаунту над карточками: строка чипов (сбой синка · ответы · черновики · аудиты) с горизонтальным скроллом и ссылкой «Разобрать всё». Даёт портфельное «что требуется» одним взглядом, не дублируя полную очередь профильного кокпита. Чип сбоя синка — в danger-тоне.

8new · heroСоветник аккаунта

Первый класс на экране. Форма: карточка-сводка — на дашборде нужен взгляд, а не приглашение печатать. Тот же компонент, что профильный советник (/app/advisor), но scope = весь портфель: вердикт + короткий разбор, привязанные data-чипы (grounding, горизонтальный скролл), строка «на основе…», рекомендации поверх брендов/профилей (в столбик), быстрый ввод и кнопка «Открыть советника» в полный чат.

9Карточки — режим «1 бренд» (профили)

Дефолт почти у всех. Карточка профиля: круглый аватар + значок сети + @никнейм + сеть, метрики 2×2 (Подписчики +Δ · Просмотры 7д · Посты нед · Ответы), строка синка и quick-links. Тап → дашборд профиля (Студия).

9.1 — Статусы профиля: importing / sync-error

Профиль в первичной загрузке показывает Phase-0 баннер импорта вместо метрик; сбой синка — приглушённые метрики + «● Сбой синка» и Retry на месте. Сбой также поднимает чип в полосе «Требует тебя».

10Карточки — режим «2+ брендов» (бренды)

Появляется со вторым брендом. Карточка бренда: контурно-квадратная марка + значки сетей + имя бренда + «N профилей · тип», стек аватаров профилей, сводные метрики и строка состояния («Все синхронизированы» / «N импортируется» / «N сбой синка»). Тап → дашборд бренда. Кнопка «Профили» раскрывает профили внутри карточки.

10.1 — Раскрытие бренда: статусы профиля внутри

Развёрнутый бренд показывает свои профили строками — и importing, и sync-error видны прямо здесь (тот же статус, что на прямой карточке профиля в режиме 1 бренда). Доказывает требование «покажи статус и на карточке профиля, и внутри развёрнутого бренда».

11Добавить бренд

Заметная карточка-CTA в конце сетки (пунктир, accent) и дубль-пункт в drawer. Это единственное действие, делающее бренд-уровень видимым: до первого клика по ней пользователь брендов не видит вовсе. После создания второго бренда карточки дашборда переключаются с профилей на бренды.

12Состояния

1 бренд · 1 профиль1 бренд · N профилей2+ брендовimportingsync-errorзагрузканемецкий

Новый пользователь (1 бренд · 1 профиль) — основное состояние (замена прежнего «0 брендов»: бренд создан автоматически, экран «создай первый бренд» не показывается). Один профиль → одна карточка + CTA «Добавить бренд»; советник уже даёт первые шаги. Загрузка — скелет, повторяющий раскладку.

13правила 1–2Проверка раскладки

Доказательство критерия на телефоне: один дашборд при 390 (реф), 360 и 320px, и на немецкой длине. Ни один однострочный элемент не переносится — длинные подписи усекаются, аватары и действия фиксированы, метрики держат сетку 2×2.

13.2 — Немецкая длина (самая длинная локаль)

«Synchronisierung fehlgeschlagen», «Kontoeinstellungen», «Erneut versuchen», «Marke hinzufügen» — самые длинные подписи. Усекаются, не ломая сетку.

15Чек-лист

  • Правило 1: однострочные элементы (метрики, итоги, счётчики, бейджи, @никнеймы, имена брендов, метки кнопок, вердикт) не переносятся и не толкают соседа — на 390/360/320px; усечение, не разрыв строки.
  • Правило 2: текст русский; контейнеры держат немецкую длину (§13, локаль de) без нарушения правила 1.
  • Один компонент, два режима: 1 бренд → карточки профилей (тап → Студия); 2+ → карточки брендов (тап → дашборд бренда). Та же сетка/хром; бренд-уровень невиден до 2-го бренда.
  • Ниже 600px: без сайдбара/таб-бара; топ-бар (гамбургер · «Дашборд» · пилюля «N профилей»); свободный нижний край под докнутую кнопку.
  • Два разных контрола аккаунта: drawer (навигация аккаунта + логин-переключатель) и докнутая кнопка → лист (плоский переключатель профилей). Breadcrumb с переменным числом сегментов.
  • Советник аккаунта первым классом: вердикт + привязанные чипы + рекомендации поверх портфеля + вход в полный чат (scope = аккаунт).
  • Портфельная статистика 2×2 в шапке; суммирует только synced; «+N импортируется».
  • Карточка «Добавить бренд» в сетке (+ дубль в drawer) — единственный вход к бренд-уровню.
  • Статусы importing / sync-error видны и на карточке профиля, и внутри развёрнутого бренда; Retry на месте.
  • Значок сети на каждом профиле (Threads сегодня, нейтральный бейдж под LinkedIn).
  • Корректно в светлой + тёмной; числа tabular. Пустой аккаунт → онбординг, здесь не рисуется.
Конец мобильной спецификации. Парный десктопный документ — Account-Dashboard-SPEC.html. Следом, когда появится пользователь с 2+ брендами: дашборд бренда со своим помощником и 3-уровневые настройки Аккаунт · Бренд · Профиль.
