Pennedly · Mobile spec · per-screen

Replies /app/replies — phone

The manual-reply queue: incoming comments on your posts, each with an AI-drafted reply in your voice that you approve before it publishes. On desktop it’s a two-column master-detail (a left list of posts, a right pane of comments). A phone can’t hold two columns, so the master becomes a horizontal, swipeable post switcher at the top and the selected post’s comments fill the single column below. Same workflow, statuses and translation as the desktop spec; only the layout changes below 600px — on the decided shell (hamburger + left drawer, no tab bar, free bottom edge). Frames are the real component layer at 390px, light and dark.

pennedly-mobile.css replies-app.jsx replies-card.jsx replies-postselect.jsx shell-parts.jsx
What does not change. The new → generating → draft → approved → replied lifecycle, skip/restore, the 500-char reply limit, comment- and reply-translation, the threaded reply block, the autopilot “Auto-replied by Pennedly” signal, and loading/empty/error states are all identical to desktop. Threads’ API still exposes only the commenter’s @username — no avatar, no display name — so the card never invents one. Mobile is a layout pass; the only structural changes are the shared shell and the master → horizontal switcher.

4fixThe post switcher

The desktop master column is a vertical list of posts-with-comments. On a phone that would eat the whole first screen before a single comment shows. Instead the master becomes a horizontal, swipeable row of post chips, sticky under the top bar.

Before (rejected)

A vertical post list pushes the actual comments below the fold; sticky per-post group headers fragment one column into many. Neither was chosen.

After (required)

One sticky horizontal row. Each chip = a 2-line post snippet + its date + an unanswered-count badge; the active chip is accent-tinted. Swipe sideways to change posts; the column below loads that post’s comments. One post’s comments at a time.

Rules. Chips are fixed 220px, scroll-snap-align:start, full-size (never crushed), in an overflow-x:auto row with hidden scrollbar. Snippet clamps to 2 lines. The badge is the unanswered count (“4 to answer”); a fully-answered post reads “All answered”. The active chip carries an accent ring + tint. Below the switcher, a compact context line repeats the selected post’s text + time + “Open in Threads”, so you always know which post you’re replying under.

5fixComment card — @username

Threads’ conversation API returns only the commenter’s @username — no profile photo, no real name. The card head is therefore @username + time only; we never draw a commenter avatar or invent a display name. (The reply block below shows your avatar — that’s you, and it’s available.)

Before

The desktop draft foot lines up Regenerate · Edit · Approve as three equal buttons. On a phone they shrink below a comfortable tap size and labels clip.

After

Two-tier foot: a meta line that wraps, then one action row — one labelled primary per status that grows to 44px, with the rest as 44×44 icon buttons. Draft → Regenerate + Edit icons, Approve grows.

10Web ↔ mobile

Desktop ( > 900 )

  • Fixed sidebar; 960px two-column master-detail.
  • Master = vertical post list; detail = context + filter + comments.
  • Draft foot: Regenerate · Edit · Approve as three buttons.
  • Publish reply = centered modal dialog.

Phone ( ≤ 600 )

  • No sidebar/tab bar; hamburger → drawer + account; free bottom edge.
  • Master → sticky horizontal post switcher; one post’s comments below.
  • Comment head = @username only; foot two-tier (Regenerate + Edit icons + Approve grow).
  • Publish reply = bottom sheet.

11Localization & 360px

Comments arrive in any language (translate inline); the reply UI localizes into 8 locales; DE/RU/UK run ~30–40% longer. On a phone: status tags (“drafted in your voice”, “approved · ready to publish”, “Auto-replied by Pennedly”) wrap under the “You” line; the primary (“Publish reply” / “Generate reply”) wraps rather than clips; the status filter and switcher scroll; the @username truncates with ellipsis; translate toggles wrap. Never bake a label into an image.

360px behavior. No new breakpoint — the gutter stays 14px; switcher chips stay 220px (they scroll regardless of viewport), comment cards just get ~30px narrower. The reply block keeps its left rule; the 16px edit textarea is unchanged so iOS still won’t zoom. Long primaries are a touch more likely to wrap to two lines (still ≥44px). The drawer stays min(82%, 312px) → 82% (≈295px) at 360.

12Checklist

  • Below 600px there is no sidebar and no tab bar — one 52px top bar with a hamburger far-left.
  • Master column → sticky horizontal post switcher; chips show snippet + time + unanswered badge; active is highlighted; swipe to change posts.
  • One post’s comments at a time below the switcher; a context line names the selected post + Open in Threads.
  • Comment head = @username + time only — no commenter avatar, no invented name.
  • Status filter scrolls horizontally with labels kept (All / Needs / Drafts / Replied / Skipped).
  • Two-tier foot; one labelled primary per status; Regenerate/Edit collapse to 44×44 icons; nothing under 44px.
  • All statuses present: new · generating (nib) · draft · approved · replied (success-tinted) · skipped (dimmed).
  • Editing = 16px textarea + char meter; comment & reply translate toggles work and wrap.
  • “Auto-replied by Pennedly” tag shows when autopilot answered a comment.
  • Loading shows switcher + skeleton cards; empty + error reachable; Publish reply confirms in a bottom sheet; toast pins to the bottom edge with Undo.
  • Primary labels wrap on long locales — never clipped or shrunk; sanity-checked at 360px.
  • Correct in light and dark; no hardcoded colour.
