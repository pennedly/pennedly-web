Pennedly · Mobile spec · per-screen

Login /app/login — phone

The single door in — passwordless, where sign-in and sign-up are the same flow (a first-time identity just creates the account). A full-screen public page — no app shell: no sidebar, hamburger, or tab bar — a centered, narrow card. It keeps its own language switcher (a globe, top area). The card is already narrow, so the job on a phone is to seat it comfortably and make the tight bits fit 360–390px — above all the 6-cell code input. Same real flow and copy as the desktop; only the layout adapts. Frames are the real component layer at 390px, light and dark.

pennedly-mobile.css login-app.jsx login-parts.jsx ds/tokens.css
What does not change. Passwordless only: a 6-digit code emailed (with a TTL, limited attempts, and a resend cooldown) OR Google OAuth (a one-time handoff). NO password field, NO social logins other than Google. Sign-in == sign-up. The dev-login drawer is dev-only (off in production). No invented “forgot password”, magic-link entry, or other providers. Mobile is a layout pass; this page has no app shell to adapt.

2The page frame

A slim top row holds only the language switcher; the card centers in the remaining space; the dev drawer (dev builds only) sits collapsed at the very bottom. The card is full-width up to 360px with comfortable side gutters.

3Email form

The resting state: brand + tagline, a full-width “Continue with Google” (a monochrome “G” tile — trademark-safe), an “or” divider, a 16px email input + “Email me a code”, and the consent line with Terms/Privacy links.

4fixCode entry — the 6-cell OTP at 360px

After requesting a code: a 6-cell one-time-code input (auto-advance, paste, focus ring, monospaced), a “Sign in” button, and a 30-second resend cooldown. The cells are the one place a phone can overflow — so they’re sized to fit six across at 360px.

Before

Fixed-width cells (e.g. 56px each) × 6 + gaps overflow a 360px card and clip the last cell or force a horizontal scroll.

After

Cells are flex:1; min-width:0 with a 7px gap and aspect-ratio:1 — six always fit the card width, scaling down on 360 and up on 390 (capped at 56px tall). Mono 22px digits, accent focus ring; a filled cell gets an accent border.

Math. At a 360px device the card is ~328px wide; six flex cells with five 7px gaps → each ≈ (328 − 35) ÷ 6 ≈ 48px — comfortably tappable, never clipped. At 390 they grow to ≈ 53px. Paste fills all six and focuses the last; backspace walks back. Resend is disabled with a live “Resend in 30s” countdown.

5Signing in

During the Google handoff or code consume, the card shows a spinner + status text (“Opening Google…” / “Signing you in…”). The submit buttons also show an inline spinner while busy.

6Errors

Three real failure modes: rate-limited (an alert on the email form), an invalid code (a danger ring on all six cells + a shake nudge), and a Google error (an alert above the email fallback). All use the danger treatment; the user can always retry.

7Dev drawer (dev-only)

A collapsed “Developer mode” drawer sits at the very bottom — dev builds only, hidden in production. Expanded, it shows the gate pill (DEV_LOGIN enabled), an email-only form that skips the code, and the build hash. Shown here for completeness, badged dev-only.

9Localization & 360px

The tagline, button copy, field labels, consent line, resend and error strings all localize into 8 locales; DE/RU/UK run ~30–40% longer. On a phone: the title and sub wrap; “Continue with Google” / “Email me a code” / “Sign in” wrap rather than clip in their full-width buttons; the consent line wraps to multiple lines with its links intact; the language switcher shows the locale code (short in every locale). The OTP digits are locale-neutral.

360px behavior. No new breakpoint — the card stays full-width with 16px gutters. The only width-critical element, the 6-cell OTP, is flex-sized so it always fits six across (≈48px cells at 360, ≈53px at 390) without overflow or horizontal scroll. The Google/email buttons and inputs are already full-width. The dev drawer’s email + button row wraps if a locale is long.

10Checklist

  • No app shell — no sidebar, hamburger, or tab bar. A centered card; the language switcher (globe) is kept, top area.
  • Passwordless: “Continue with Google” (monochrome G tile) + email→code. No password field; no other providers.
  • Google + email input + buttons are full-width; inputs are 16px (no iOS zoom).
  • The 6-cell OTP fits six across at 360px without overflow (flex cells, gap 7, aspect-ratio 1); auto-advance, paste, focus ring, mono.
  • Resend has a 30-second cooldown; “Use a different email” is reachable.
  • Signing-in shows a spinner + status (Google handoff / code consume).
  • Errors: rate-limited alert; invalid code = danger ring on all six cells + shake; Google error alert.
  • Consent line (“Terms and Privacy Policy”) with links is present and wraps.
  • Dev drawer is collapsed at the bottom, badged dev-only (hidden in production); expands to gate pill + email form + build hash.
  • Copy wraps on long locales — never clipped; sanity-checked at 360px; safe-area respected.
  • Correct in light and dark; no hardcoded colour.
