Pennedly · Mobile spec · per-screen

Landing / — phone

The public marketing homepage — “a drafting partner, not automation; you keep the final say.” A full-screen public page — no app shell: it has its own top bar (brand + language switcher + Sign in), no sidebar/hamburger/tab bar. The job on a phone is to reflow the desktop landing so it reads great top-to-bottom at 390px (sanity-checked at 360): the hero product-peek window shrinks but keeps its essence, the bento feature grid collapses to a single column, and the Sign-in CTA stays thumb-reachable. Same tokens and copy as the desktop; only the layout adapts. Frames are the real component layer at 390px, light and dark.

pennedly-mobile.css landing-app.jsx landing-parts.jsx ds/tokens.css
What does not change. It’s a marketing page: the product-peek window is illustrative sample content (English), not live data. “Sign in” goes to /app/login. The honest-positioning copy holds — drafts in your voice, you approve before publishing, multi-account, analytics, opt-in autopilot. The page auto-detects the visitor’s browser language across 8 locales; the switcher changes it. No invented pricing, testimonials, or sections. Mobile is a layout pass; this page has no app shell to adapt.

3Top bar + language

The landing’s own top bar: brand left; language switcher + “Sign in” right. It’s pinned so Sign in is always reachable. The switcher opens a dropdown of the 8 locales (label + code), the current one checked.

Compact. The theme toggle from desktop folds away on a phone (the page respects the system theme); the top bar keeps just brand · language · Sign in so the row never crowds. The language menu drops below the trigger, right-aligned, over the hero.

4fixHero + product-peek

The hero text reflows to full-width: status badge, headline, value-prop, the “you approve every word” line, then a stacked CTA (full-width Sign in + the contact email). Below it, the product-peek window — the rich Studio illustration — is shrunk to fit.

Before

The desktop hero is a two-column grid (text beside a wide product window). At 390px the window’s browser chrome, vertical account rail and composer overflow and the caret line clips.

After

Text stacks above the window. The window keeps its essence — browser dots + URL, the account rail with avatars, the composer drafting in voice with a blinking caret + voice/tone chips + Edit/Approve — but scales down (smaller avatars, tighter padding, text-small body) so it never pushes past the viewport.

Shrink, don’t drop. The window stays a faithful product peek (it’s the proof), just smaller: the rail stays vertical with 26px avatars + the “add” affordance; the composer body steps to text-small; the foot keeps Edit + Approve. It’s an illustration (aria-hidden), English sample text, never wider than the column.

5Bento → single column

The desktop bento (one wide tile, one full-width banner, the rest 1-col) collapses to a single-column stack on a phone — every tile becomes a full-width block: icon + title + description. Order is preserved.

6Footer

The footer stacks: the © brand line over the legal links (Privacy Policy · Terms of Service · Data Deletion), each a full-width tappable row. The contact email lives in the hero CTA.

8Localization & 360px

The status badge, headline, value-prop, CTA, feature titles/descriptions, footer links and language labels all localize into 8 locales; DE/RU/UK run ~30–40% longer. On a phone: the headline uses text-wrap:balance and wraps to as many lines as needed; the value-prop and feature copy wrap freely; “Sign in” stays a full-width button (label wraps rather than clips); the language switcher shows the short code; the window’s sample text is illustrative English (not localized chrome). The footer links stack so long labels never crowd.

360px behavior. No new breakpoint — the gutter stays 16px; the hero, window and tiles get ~30px narrower so copy rewraps. The product-peek window is fluid (its rail + composer are flex), so it shrinks with the column and never overflows. The top bar keeps brand + language + Sign in on one row (Sign in stays a compact pill). The drawer doesn’t exist here.

9Checklist

  • No app shell — the landing’s own top bar (brand + language switcher + Sign in); no sidebar/hamburger/tab bar.
  • Reads top-to-bottom: top bar → hero → product-peek → bento stack → footer.
  • Hero text reflows full-width; the Sign-in CTA is prominent and thumb-reachable (top bar + hero).
  • The product-peek window shrinks but keeps its essence (browser chrome + account rail + composer + blinking caret) and never exceeds the viewport width.
  • The bento collapses to a single-column stack; wide/banner tiles become full-width blocks; order preserved.
  • The “in development” status badge and honest-positioning copy are present, unchanged.
  • Language switcher opens a dropdown of the 8 locales; current is checked.
  • Footer stacks © + Privacy / Terms / Data Deletion; contact email in the hero.
  • Copy wraps on long locales — never clipped; sanity-checked at 360px; safe-area respected.
  • Correct in light and dark; no hardcoded colour; the window is illustrative (sample content).

＊New sections — Voice Test · The difference

The two new landing sections at phone width (≈390–412px), light and dark. Voice Test (after the hero) is a public, no-signup demo. Its input is finalized on numbered post cards: one full-width field + an Add post button; each added post collapses into a compact numbered card above the field (with × remove), and the field clears for the next. Because each post is its own card, a paragraph break inside a post never splits it. Textareas are ≥16px (no iOS zoom); add / remove / run targets are ≥44px; cards + field are full-width. Cap ~5 (“Add post” hidden at the cap); Run is enabled once there is ≥1 post. The difference (after the bento) is the closed-loop coach strip — on a phone the three step cards stack with a down-arrow between them. Same tokens and copy as the desktop spec.

Voice Test — input states (phone)

Every state at 412px. Empty = field + “Add post”, Run off. 1 card = one numbered card above the field. 3 cards = Run on; card 1 keeps an internal paragraph break (proof it stays one post). At cap (5) = “Add post” hidden.

The difference — stacked 3-step loop

Mobile rules. Voice Test column is full-width; textarea ≥16px (no iOS zoom); CTA grows to full width on narrow widths; “No signup” stays in the copy. The difference: cards stack, the → connector rotates to ↓ via the container query. Step copy and the CTA wrap on long locales, never clip.
