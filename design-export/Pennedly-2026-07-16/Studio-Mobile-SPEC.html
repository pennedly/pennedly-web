Pennedly · Mobile spec · per-screen

Studio /app — phone

Studio is the biggest screen in the app, and on a phone the desktop content doesn’t fit — rows overlap and clip. This spec lays it out cleanly at 390px (sanity-checked at 360) with no overlap, using the decided mobile shell: a single slim top bar with a hamburger that opens a left navigation drawer. There is no bottom tab bar, so the bottom edge is free for content. Same tokens, states, flows and copy as the desktop spec — only the layout adapts below 600px. Every frame is the real component layer rendered at 390px, light and dark.

pennedly-mobile.css studio-app.jsx studio-parts.jsx shell-parts.jsx ds/tokens.css
What does not change. The brief → generate → review → approve → publish flow, the 500-char limit, the four status filters (Ready / Drafts / Published / Rejected), per-status card footers, tweak-in-your-voice, on-demand translation into the 8 UI locales, the confirm-before-publish step, and reply-drafts being read-only here — all identical to desktop. Mobile is a layout pass — including the «Строка» composer, whose concept matches desktop and only re-flows its shelf here. The one structural change is the app shell (tab bar → hamburger drawer), shared by every screen.

1Screen identity

Studio is a full app-shell screen. On desktop it renders the 248px sidebar + a 960px content column. On a phone the sidebar collapses behind the hamburger, the nav lives in a left drawer, and the column goes edge-to-edge with a 14px gutter. Nothing is pinned to the bottom — the feed scrolls all the way to the device edge.

2The phone layout

The whole screen in context, light and dark. The top bar carries the hamburger, the title, the voice-state pill and the theme toggle; the filter row sticks directly under it; the feed runs to the free bottom edge.

3shellShell: top bar + drawer

The shell is shared by every screen (see DS · App shell & nav). It is one slim 52px bar; tapping the hamburger slides the drawer in from the left over a scrim. Studio-specific shell values:

Drawer rules. Width min(82%, 312px), full-height, slides from the left over a blurred scrim (tap scrim or ✕ to dismiss). It reuses the shared nav-row styling; the active row gets a left accent rail. The account control at the foot opens the same account sheet used elsewhere — switch account, connect another, Settings, Log out. Nothing about navigation is invented here; the drawer simply re-homes the desktop sidebar.

4fixComposer — «Строка» on a phone

The composer is «Строка» — the one canonical composer (identical concept to desktop): a calm prompt bar (avatar · input · ✨) that discloses a shelf below on focus/typing; the ✨ swaps the shelf for the Ideas palette. Desktop metrics are frozen — only the shelf re-flows so it never overflows at 390 → 320.

The break

At 390 the desktop shelf’s tools row — DRAFTS · 1·2·3·4 · Generate on one line — ran off the right edge and clipped “Generate”. (The old ≤560 CSS still targeted .composer-row, a class «Строка» no longer has.)

The fix

The tools row wraps: DRAFTS + 1·2·3·4 stay on row 1, a seeded note (when present) takes its own row, and Generate is full-width on its own row. Chips stay a scrollable row with a fade. Every single-liner is unwrappable.

Bar rules. Avatar 38 + full-height input (text-h3 19px ≥ 16 → no iOS zoom) + ✨ toggle (44×44). The ⌘↵ hint is dropped on touch (@media (pointer:coarse)) — it means nothing without a keyboard. Busy swaps the whole «Строка» for the nib animation + “Drafting N posts in your voice”.

The ✨ opens the Ideas palette in place of the shelf — loading → results, plus the two real backend outcomes empty and error. Idea cards show Use without hover (touch); the list caps at 56vh and scrolls; the ⟳ / ✕ controls are 44×44.

8First-run · publish sheet · toast

First-run replaces composer+feed with the welcome hero and flips the voice pill to warning. The publish confirm becomes a bottom sheet (stacked full-width actions, primary on top). Toasts pin to the bottom edge — there is no tab bar to clear — with Undo.

10Web ↔ mobile

Desktop ( > 900 )

  • Fixed 248px sidebar; account control at its foot opens upward.
  • 960px centered column; topbar aligned to it.
  • «Строка»: bar (avatar · input · ✨) + shelf (chips · DRAFTS 1·2·3·4 · Generate) in one card; ✨ → Ideas palette.
  • Card foot: meta left, ⋯ + one primary right, single line.
  • Filter bar: 4 tabs in a row; labels always shown.
  • Publish: centered modal dialog.

Phone ( ≤ 600 )

  • No sidebar, no tab bar — one top bar; hamburger → left nav drawer + account.
  • Edge-to-edge column, 14px gutter; free bottom edge.
  • «Строка»: same bar; shelf tools re-flow — DRAFTS·1·2·3·4 on row 1, Generate full-width; ✨ → Ideas palette (incl. empty/error).
  • Card foot: two-tier — meta line, then grow-primary + 44px ⋯.
  • Filter bar: horizontally scrollable, labels kept.
  • Publish: bottom sheet, stacked full-width actions.

11Localization & 360px

All Studio strings localize into 8 locales; DE runs ~1.3–1.5× the RU/EN length. In «Строка» the single-liners never wrap — DRAFTS, the 1·2·3·4 segment, the Generate label and “Seeded from an idea” each sit on a row wide enough to hold them (Generate and the seeded note take their own full-width rows; the chip row scrolls). Elsewhere on the card the per-status primary (Approve / Publish) may still wrap to a 2nd line rather than clip. The title truncates before the pill; drawer nav labels wrap. Never bake a label into an image.

360px behavior. At the narrow end the same rules hold with no new breakpoint — the gutter stays 14px, the composer/cards just get ~30px narrower. In «Строка», DRAFTS + 1·2·3·4 still fit on row 1 (the segment is ~178px, the label ~55–75px), and Generate stays full-width — nothing wraps. The chip row, suggestion row and filter bar already scroll, so they absorb the loss. The drawer stays min(82%, 312px), so on 360 it’s 82% (≈295px) and the scrim shows a sliver of the screen behind it.

12Checklist

  • Below 600px there is no sidebar and no tab bar — one 52px top bar with a hamburger far-left.
  • Hamburger opens the left drawer; drawer holds the full grouped nav (active = Studio) + the account at its foot.
  • Bottom edge is free — content/feed scrolls to the device edge; toast pins to the bottom, not above a bar.
  • Composer is «Строка»: bar (avatar · input · ✨) + a shelf that reveals on focus; chips scroll horizontally with a fade; placeholder never clips.
  • Shelf tools never overflow (390→320): DRAFTS · 1·2·3·4 on row 1, Generate full-width on its own row, seeded note its own row; single-liners never wrap.
  • Input is ≥16px (no iOS zoom); ✨ / count segment / idea ✕ / idea cards are ≥44px; the ⌘↵ hint is hidden on touch.
  • ✨ opens the Ideas palette in place of the shelf: loading → results, plus empty and error (danger, no self-collapse); Use is visible without hover.
  • One state proven with German strings (chips + seeded) at ~1.4× length with no wrap/clip.
  • Every card foot is two-tier; exactly one labelled primary; the ⋯ is 44×44 and holds all secondary actions.
  • Sub-states fit the phone: editing (16px textarea + meter), tweak (input + scrolling suggestions), revising (skeleton), translated (Show original), reply = read-only.
  • Primary labels wrap to a 2nd line on long locales — never clipped or shrunk; sanity-checked at 360px.
  • Filter bar scrolls and sticks under the top bar; counts correct.
  • Loading = 3 skeletons; empty is per-filter; error banner has Retry; all reachable via state.
  • Publish confirm is a bottom sheet; actions stacked full-width; primary on top.
  • Correct in light and dark; no hardcoded colour.
