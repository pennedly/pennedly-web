Stats /app/stats — пиксель-в-пиксель

Дотошная спецификация агрегатного дашборда Stats — и общего app-shell, который Stats переиспользует 1:1 из Studio (<window.Sidebar active="stats"/> + топбар + переключатель аккаунтов). Пользователь выбирает период и видит сводку (тоталы + средние per-post с дельтами против прошлого равного периода), один столбчатый график динамики средних просмотров и распределение постов по viral-тирам. Это аналитика для самоанализа, без действий с контентом; графики нарисованы вручную на CSS/SVG, без сторонних библиотек. Ниже задокументированы АБСОЛЮТНО все состояния: shell (аккаунт-меню откр/закр), селектор периода (6 опций), сводные карточки с дельтами (вверх/вниз/ноль/нет-периода), столбчатый график с пунктирной линией среднего, распределение по тирам, состояния loading/ready/empty, тема и адаптив web↔mobile. Все значения взяты из реального дизайна, без «примерно».

App-shell — общий, 1:1 как в Studio. Stats НЕ собирает каркас заново: рендерится <window.Sidebar active="stats"/> из shell-parts.jsx, а классы .app/.sidebar/.main/.topbar/.account приходят из studio.css + shell.css. Единственное отличие shell от Studio — активный пункт навигации = Stats в группе Insight (nav-item--active, aria-current="page", без badge) и заголовок топбара «Stats». §2.1–2.4 документируют shell так же дотошно, как в Studio-SPEC.
Расхождения с брифом — здесь задокументирован РЕАЛЬНЫЙ дизайн. В коде (а не в брифе):
  • Периоды — backend-enum 1:1: Today · Yesterday · 7 days · Month · 3 months · All time (не «30 days / 90 days»). Гранулярность бакетов: today/yesterday → hour (не «по постам»); 7d → day; month/3mo → week; all → month.
  • Сводных карточек ровно 4: Posts · Views · Likes · Comments. Карточки reposts НЕТ; нет отдельных карточек «per-week». Среднее — это подпись per-post внутри карточки (sub), не отдельная карточка.
  • График один, не два: единственный ColumnChart «Average views per post» с пунктирной линией среднего и столбцами выше/ниже неё. Второго графика «posts / week» нет; вторая панель — это распределение по тирам, не график.
  • Тиры — Viral / Good / Average / Weak (не «Mid / Flop»). Цвета: viral = success, good = accent, average/weak = нейтральная ink-рампа.
  • Состояния — loading / live / empty. Error-состояния и ErrorBanner в этом экране НЕТ. Твик state = только Live / Loading / Empty.
  • Брейкпоинты Stats — 760px (сетка → 2 кол., panel-row → 1 кол.) и 460px (сетка → 1 кол., подписи бакетов скрыты), а не 560. Сайдбар по-прежнему сворачивается в rail на 880 (shell).
  • Empty-блок несёт жёстко заданную мета-строку «1 week so far · 3 posts published» (часть копи EmptyState), без CTA-кнопки.
Состояния одним взглядом. Экран управляется тремя твиками (stats-app.jsx → STATS_TWEAK_DEFAULTS): dark (false), state («Live»), period («7d»). Смена периода или state="Loading" уводит фазу в loading ~700ms → ready; state="Empty" рисует EmptyState и скрывает селектор периода. Данные — из STATS[period] (6 наборов), у каждого свой prev для дельт (null у All time → «no prior period»), бакеты графика и распределение тиров. Форматирование чисел — sfmt() (K/M).

ПериодТвик period + сегмент .range-seg с 6 кнопками. По умолчанию активен 7 days (7d). Смена периода = choosePeriod → setPeriod + setTweak("period", k) + краткий skeleton 700ms.
First-run / densityОтсутствуют в этом экране.
ЛокализацияEnd-user копи локализуется: заголовок, лейблы периода, лейблы/сабы карточек, текст дельт, «avg» на графике + локализованные подписи бакетов (fmtBucket по гранулярности), названия/сабы тиров, empty-копи. Числа — сэмплы (реальные из insights).
Backend-правдаОпции периода — РОВНО backend-enum (без выдуманных кастом-диапазонов). Дельты — против непосредственно предыдущего равного по длине периода; у All time периода-предшественника нет (prev=null). Бакеты/гранулярность — от backend. Insights обновляются ~раз в сутки. Время/бакеты — в локальной TZ зрителя.

  5. Оверлей поверх .app — <TweaksPanel> (диалогов/тостов на этом экране нет).

3Раскладка и адаптив

4.4 — Дельта карточки: вверх / вниз / ноль / нет периода

  • вверх (рост): .delta--up, color success #2c7350, IcArrowUp + «{n}%». В сидах все периоды (кроме All time) дают рост.
  • вниз (падение): .delta--down, color danger #b23b30, IcArrowDown + «{n}%». В текущих сидах не встречается, но логика активна при cur < prev.
  • ноль: |r| < 0.1 → .delta--flat «no change» (subtle, без иконки).
  • нет периода: prev == null (All time) → .delta--flat «no prior period». Все 4 карточки и headline графика показывают этот вариант.

4.5 — График и тиры

ColumnChart (с данными / пустой)

  • Столбцы: высота max(3, v/max*100)%; цвет — accent если v ≥ avg, иначе нейтральный ink (mix text 18%).
  • Пунктирная линия среднего на bottom: avg/max*100% с подписью «avg {sfmt(avg)}» справа.
  • Подписи бакетов снизу через fmtBucket (hour/day/week/month).
  • Число бакетов по периоду: today 3 · yesterday 2 · 7d 7 · month 5 · 3mo 12 · all 8.
  • Hover столбца меняет его цвет (above → темнее accent, below → темнее ink); нативный title = «{bucket}: {value}».
  • «Пустого графика» как отдельного состояния нет — при нехватке данных весь экран уходит в EmptyState.

DistributionBars (тиры)

  • 4 строки: Viral (success) · Good (accent) · Average (ink 30%) · Weak (ink 15%).
  • Каждая: точка-цвет + название + саб (× your average) + «{n} posts» + «{%}%» + бар.
  • Счётчик = round(dist[key]*posts); расхождение прибавляется к крупнейшему тиру (сумма = posts).
  • Ширина бара = count/maxCount*100% (нормировка на макс. тир, не на total).
  • Пример (7d, 7 постов): Viral 1 (14%) · Good 2 (29%) · Average 3 (43%) · Weak 1 (14%).

7Чек-лист

«Убедись, что X = ровно Y». Пройди в светлой и тёмной теме, на вебе и мобайле, по всем 6 периодам.

Shell (1:1 как в Studio)
