Scenarios /app/scenarios · десктоп — четыре явные поверхности

Переработка навигации и информационной архитектуры. Визуальный язык и компоненты — родные (те же токены, карты, Geist, ширина 960). Менялось одно: как человек перемещается и насколько ему понятно, где он находится. Вместо одной страницы, где три вида подменялись на месте без табов и крошек, теперь четыре явные поверхности с общим домом «Мои сценарии» и всегда явным путём назад.

A · стартСтарт / обучениеЧто такое сценарии и зачем. Это же — пустое состояние.
B · домМои сценарииАктивные + на паузе. Центр управления. Один вход «＋».
C · каталогГотовые шаблоныКарточки с примером и пояснением. + «с нуля».
D · конструкторСвой с нуляГибкий билдер: когда · пост и/или ответ · условие.
scenarios-spec.js scenarios.css + scenarios-ia.css + топбар · назад · крошки + A старт/обучение + B активные/на паузе + C каталог с примерами + D конструктор
Что изменилось. Одна страница с тремя видами, подменявшимися на месте (список → каталог → редактор) без табов, без крошек, «назад» мелкой ссылкой → четыре явные поверхности с общим топбаром, кнопкой «← Мои сценарии» и хлебными крошками. Два разных входа в каталог свелись к одному очевидному «＋ Создать сценарий». Дом «Мои сценарии» теперь делит сценарии на Активные и На паузе с количеством — видно и работающие, и выключенные. Каталог — отдельный экран с примером генерации на каждой карточке. Создание «с нуля» — полноценный конструктор (пост и/или ответ).

1Экран и карта навигации

Дом = «Мои сценарии». Из любого места есть явный путь назад к нему. Первый вход (нет сценариев) ведёт в A (старт); возвращающийся попадает в B (дом).

Первый вход / нет сценариев→A старт-обучение
A · старт→«Посмотреть шаблоны» → C«Создать свой» → D
Возвращающийся (есть сценарии)→B Мои сценарии
B · дом→«＋ Создать сценарий» → C«Как это работает» → A
C · каталог→шаблон → редактор (предзаполнен)«с нуля» → D
C / D / редактор→сохранить → B← Мои сценарии всегда
Маршрут/app/scenarios (дом B; пусто → A) · /app/scenarios/catalog (C) · /app/scenarios/new (D) · /app/scenarios/:id (редактор). tester-gated, в группе Voice & automation, перед Autopilot.
ТипПолный app-shell: <window.Sidebar active="scenarios"/> + внутренний топбар поверхности (заголовок / назад / крошки / статус-pill).
Дом / возвратДом — Мои сценарии. На каждой поверхности глубже дома — «← Мои сценарии» слева в топбаре + хлебные крошки + сильный заголовок. «Назад» больше не мелкая ссылка.
Ширина контентаwide = --content-wide 960px.
Статус-pill.status-pill--success «N активны» с живой точкой, если есть включённые; нейтральный «всё выключено» иначе.
НазначениеРутинный автопилот: один раз настраиваешь рутины, они сами постят и отвечают по расписанию. OFF по умолчанию.

2Навигационный каркас wayfinding

Сердце переработки. У дома — топбар с заголовком «Сценарии», статус-pill и одним primary «Создать сценарий». На любой поверхности глубже — «← Мои сценарии» + крошки (Мои сценарии / Каталог / …) + заголовок поверхности. Так человек всегда знает, где он и как вернуться.

2.1 — Элементы топбара

Элемент / классОписание
.sc-topbarВнутренний топбар поверхности: слева заголовок/назад, справа статус-pill + действия. Кровит до краёв фрейма — читается как реальная панель.
.sc-back«← Мои сценарии» — всегда видимый возврат к дому. Кнопка, не мелкая ссылка.
.sc-crumbsХлебные крошки над заголовком: Мои сценарии / Каталог / Редактор. Текущая — жирная.
.sc-howlink«Как это работает» — тихая ссылка в доме, всегда ведёт к A (объяснение).
.status-pill«N активны» (success) / «всё выключено» (нейтральный) — состояние режима одним взглядом.

3A · Старт / обучение entry / empty

Первый вход и пустое состояние. Объясняет простым языком, что такое сценарий (рутина, которая сама постит и/или отвечает по расписанию) и зачем (экономит время, держит аккаунт живым, не пропускает ответы). Ниже — 3 карточки-примера «как это выглядит», блок «Как это работает» в 3 шага и две кнопки: «Посмотреть шаблоны» (→ C) и «Создать свой» (→ D). «Как это работает» доступно из дома всегда.

Блок / классОписание
.sc-teach-hero«Сценарии сами постят и отвечают по расписанию» + объяснение зачем простым языком.
.sc-teach-examples · .sc-teach-ex3 примера «как это выглядит» с реальным сэмплом поста/ответа: утренний пост · акция-сбор-заявок · дежурный по ответам.
.sc-steps · .sc-step«Как это работает»: 1) выбрал шаблон или собрал свой → 2) проверил превью → 3) включил.
.sc-teach-cta«Посмотреть шаблоны» (primary → C) · «Создать свой» (secondary → D) + заметка «создаются выключенными».
.sc-gatenote«Режим виден только тестерам · по умолчанию выключен».

4B · Мои сценарии — дом режима центр управления

Дом и центр управления. Все сценарии с явным разделением: секция «Активные» (работают сейчас) и секция «На паузе» (созданы, но выключены) — отдельными подзаголовками с количеством. Сверху — лимит постов в день. Заметная одна primary «＋ Создать сценарий» (без дублей). Карта: статус, человекочитаемое «что делает», «сработал N×» со ссылкой на Активность, тумблер, редактировать, удалить, «Применить к другим аккаунтам».

4.1 — Пусто → ведёт в A (старт)

Когда сценариев ещё нет, дом показывает стартовый-обучающий экран A — а не пустую таблицу. Так первый вход всегда учит.

4.2 — Карта: активна / на паузе

Активная — недельная полоса Пн–Вс (когда срабатывает), «след. запуск», «сработал N× · Активность» (ссылка). На паузе — приглушена, «— на паузе» + skip-note «почему не сработало». У обеих: тумблер, «Применить к…», редактировать (карандаш), удалить (корзина).

Элемент / классОписание
.sc-sec-head · .sc-sec-countПодзаголовок секции «Активные» / «На паузе» + пилюля количества (active = success-тинт).
.sc-cadence · .fireПолоса Пн–Вс; .fire--evt = reply/реактив (success). Реактивный → строка-событие.
.sc-runlink«сработал N× · Активность» — ссылка на журнал.
.sc-iconbtn · --dangerРедактировать (карандаш) и удалить (корзина) на каждой карте.
.sc-skip«Вчера пропущен» + причина (лимит / условие / gated).

4.3 — Центр управления: лимит/день + стэкинг

Шапка .sc-cc-head: «Неделя · локальное время» + лимит постов в день (степпер). Стэкинг-варнинги называют конкретные жертвы и советуют действие.

4.4 — Стэкинг-варнинги + «автопостинг выключен»

Элемент / классОписание
.sc-warnWarning-баннер, называет конкретные сценарии («3 пост-сценария метят в утро»; «Акция каждый день — ≤2×/нед»).
.sc-warn--autopostDanger-вариант: автопостинг выключен → готовит черновики, но не публикует; «Включить автопостинг».

4.5 — Загрузка / Ошибка

Пустое состояние = старт A (§4.1). Здесь — загрузка (скелетоны) и ошибка (баннер + «Повторить»).

4.6 — Кросс-аккаунт «Применить к…»

Клон сценария на выбранные аккаунты: поповер со списком (тумблер на каждый). Времена пересчитываются в локальную TZ каждого аккаунта.

5C · Каталог готовых шаблонов примеры + пояснения

Отдельный экран с явным возвратом «← Мои сценарии», крошками Мои сценарии / Каталог и заголовком «Готовые шаблоны». Шаблоны сгруппированы по цели/эффекту (рост · вовлечение · удержание · продажи). Каждая карточка показывает имя, 1–2 строки «что это и зачем» простым языком и конкретный пример того, что он сгенерит (пример поста или ответа) — чтобы понять шаблон, не открывая его. Клик → редактор, предзаполненный шаблоном. Заметный вход «Создать свой с нуля» → D.

5.1 — Анатомия карты шаблона

Карта .sc-tcard: глиф + имя + «когда / отвечает людям» + описание + обязательный блок-пример .sc-tcard-ex с реальным сэмплом (пост, опрос или авто-ответ) + «Выбрать шаблон →». Кампании несут риск-бейдж.

Элемент / классОписание
.sc-scratch-ctaЗаметный вход «Создать свой с нуля» → конструктор D, в пунктирном accent-контейнере вверху каталога.
.sc-tcard-exОбязательный пример генерации: «пример поста» / «пример опроса» / «пример ответа» с реальным сэмплом.
.sc-tcard-ex-replyДля reply-шаблонов — строка авто-ответа под примером поста.
.sc-tcard-pick«Выбрать шаблон →» — клик открывает редактор, предзаполненный этим шаблоном.

6D · Конструктор своих сценариев с нуля

Максимально гибкий билдер. Всё на виду, не пугает: подсказки, примеры, хорошие плейсхолдеры. Название · КОГДА (все 5 режимов) · ЧТО ДЕЛАТЬ — гибко: постить (свободная инструкция + подсказка «как написать хорошую инструкцию» с примером) И/ИЛИ отвечать (кому + инструкция ответа). Можно собрать постовый, ответный или оба. (опц.) условие · «что зашьётся» · живое превью + «Прогнать сейчас». «Сохранить» (выключенным) и «Сохранить и включить».

6.1 — Пост и/или ответ

.sc-actpick — две карты-переключателя «Публиковать посты» и «Отвечать на комментарии». Включишь обе — сценарий делает оба. Внизу .sc-compiles честно говорит, во что соберётся (инвариант: один из трёх видов).

Элемент / классОписание
.sc-actpick · .sc-actcardВыбор действия: пост / ответ / оба. Включённая карта — accent-тинт + раскрывает свой подблок.
.sc-subblock (пост)Свободная инструкция поста + .sc-tip «Как написать хорошую инструкцию» с примером.
.sc-subblock (ответ)Кому отвечаем (select) + инструкция ответа.
.sc-compiles«Соберётся в: расписание · пост + ответы» — показывает итоговый вид сценария (инвариант).

7Редактор существующего сценария та же форма

Открытие шаблона из каталога или клик «Редактировать» в доме ведут в ту же форму, предзаполненную. Топбар: «← Мои сценарии» + крошки Мои сценарии / Каталог / Редактор + заголовок-имя. Слева форма, справа липкий предпросмотр + «Прогнать сейчас». Удаление — inline-confirm.

8Предпросмотр + «Прогнать сейчас» run-now

Липкая панель: реальный сэмпл, строка «Грунтован на…», «когда сработает», и «Прогнать сейчас» — создаёт только черновик, никогда не публикует. Справа — результат прогона (баннер «Черновик создан»).

9Доверие · «Что зашьётся» + реактив read-only

«Что зашьётся» — read-only список проверенных правил поверх вашего голоса (доверие). Реактивный «По событию» — read-only строка-событие + единственное редактируемое поле порога.

10Раскладка · Десктоп ↔ телефон

Десктоп-спека. Полная телефонная раскладка — в Scenarios-Mobile-SPEC.html. Ширина --content-wide 960; форма — две колонки (поля + липкий предпросмотр).

Десктоп ( > 880 )

  • Фикс. сайдбар; внутренний топбар поверхности; колонка 960.
  • Дом B: активные + на паузе секциями; полоса недели в ряд.
  • Каталог C: карты 2-в-ряд с примером; «с нуля» вверху.
  • Конструктор/редактор D: 2 колонки — поля + липкий предпросмотр; назад в топбаре.
  • Удаление — inline-confirm; «Применить к…» — поповер.

Телефон ( ≤ 600 )

  • Дом B: активные/на паузе стопкой; карта = предложение + большой статус.
  • Каталог C: карты в 1 колонку с примером.
  • Конструктор/редактор D: поля стопкой, sticky-панель действий снизу.
  • Включение / удаление / «скопировать» — bottom-sheet.
Полный телефонный проход — Scenarios-Mobile-SPEC.html (390px, тот же drill-down, sticky action bar, 360px-проверка).

11Инварианты · backend-контракт

Что нельзя ломать. Сценарий компилируется в ОДНО из трёх: {промо «Акция»} · {дежурный по ответам: политика + инструкция ответа} · {расписание: триггер + что постить + (опц.) как отвечать + (опц.) условие}. Конструктор D собирает любой из этих видов (см. .sc-compiles). Режим виден только тестерам, по умолчанию ВЫКЛ. Включение — через подтверждение; выключение — мгновенно.
Эндпоинт / полеОписание
GET …/scenariosДом B: id, name, enabled, preset, provenance, schedule_summary, cadence_days (bitmap), next_run_at, run_count, last_skip. Группируется на клиенте в active / paused.
GET …/scenarios/templatesКаталог C: goal (growth/engagement/retention/sales), example (post|reply|poll сэмпл), reply, fields[], baked_rules[], gated.
Модель сценарияОдин из трёх видов. schedule (daily / every_n_days / weekly / date_range / event) · post_instruction · reply{audience, instruction} · condition (опц.). Конструктор пишет любой.
Лимит / стэкингdaily_post_cap (per-account) · сервер возвращает warnings[] (named victims) + autopost_enabled.
POST …/scenarios/:id/run-nowСоздаёт только черновик, никогда не публикует.
POST …/scenarios/:id/enableВключение через подтверждение («это начнёт само постить/отвечать»). Выключение — мгновенно, без подтверждения.
POST …/scenarios/:id/clone«Применить к…»: клон на account_ids[]; времена в локальную TZ каждого.

12Чек-лист реализации

  • Четыре явные поверхности: A старт-обучение · B Мои сценарии (дом) · C каталог · D конструктор. Дом = «Мои сценарии».
  • Навигация: внутренний топбар на каждой поверхности; глубже дома — «← Мои сценарии» + хлебные крошки + сильный заголовок. «Назад» не мелкая ссылка.
  • A · старт: что такое сценарий и зачем простым языком; 2–3 карточки-примера «как это выглядит»; «Как это работает» в 3 шага; кнопки «Посмотреть шаблоны» (→C) и «Создать свой» (→D); это же — пустое состояние; «Как это работает» доступно из B всегда.
  • B · дом: секции «Активные» и «На паузе» отдельными подзаголовками с количеством; статус-pill «N активны»/«всё выключено»; лимит/день; стэкинг-варнинги + «автопостинг выключен»; карта (статус · что делает · «сработал N× → Активность» · тумблер · редактировать · удалить · «Применить к…»); один primary «＋ Создать сценарий».
  • C · каталог: отдельный экран, «← Мои сценарии», заголовок «Готовые шаблоны»; группировка по цели (рост/вовлечение/удержание/продажи); каждая карта несёт конкретный пример генерации; клик → редактор предзаполнен; заметный вход «Создать свой с нуля» → D.
  • D · конструктор: Название · КОГДА (5 режимов) · ЧТО ДЕЛАТЬ (пост и/или ответ — свободные инструкции + подсказка с примером) · (опц.) условие · «что зашьётся» · превью + «Прогнать сейчас»; «Сохранить» / «Сохранить и включить».
  • Инварианты: сценарий = одно из трёх видов; конструктор собирает любой (.sc-compiles); режим tester-gated, OFF по умолчанию; включение через подтверждение, выключение мгновенно; «Прогнать сейчас» → только черновик.
  • Все поверхности корректны в светлой и тёмной; только семантические токены; ширина 960; форма collapse на ≤880; проверено на 360px (парный mobile-документ).
Конец спецификации. Источник: scenarios-spec.js, scenarios.css, scenarios-ia.css + общий shell. Парный телефонный документ — Scenarios-Mobile-SPEC.html.
