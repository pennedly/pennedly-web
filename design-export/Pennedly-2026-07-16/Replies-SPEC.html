Replies /app/replies — пиксель-в-пиксель

Спецификация переработанного десктопного экрана Replies — очереди ответов на комментарии (reply-first — ключевое отличие Pennedly). Под постами пользователя собираются комментарии; Pennedly пишет ответ в голосе пользователя, тот ревьюит и одним подтверждением публикует тред-ответ в Threads. Главное изменение: прежний two-column master-detail (узкая колонка-список постов слева, комментарии справа) заменён на горизонтальный post-свитчер сверху — ровно тот же идиом, что уже на мобиле (§4 mobile-spec), только в десктоп-размере, со стрелками/драгом/fade вместо свайпа. Левая вертикальная колонка убирается полностью; комментарии и composer занимают всю ширину одной читаемой колонки. Документ покрывает десктоп одним проходом: живые фреймы (реальные DS-компоненты на replies.css, светлая И тёмная темы, на ширине экрана), пронумерованная анатомия, все состояния, «что не меняется», маппинг Web↔Mobile (теперь это один идиом), локализация в 8 языков и чек-лист. Тон Pennedly — «партнёр по черновикам», спокойная иконография; никаких молний.

replies.css · post-switcher replies-app.jsx replies-parts.jsx replies-postselect.jsx replies-card.jsx replies-data.jsx shell-parts.jsx ds/tokens.css ds/components.css
Десктоп переработан: master-список → горизонтальный свитчер. Прежняя левая колонка .rq-master (300px, вертикальный список постов) убрана полностью. Теперь посты переключаются горизонтальным snap-scroll рядом чипов сверху (.rq-switch), sticky под топбаром; комментарии выбранного поста заполняют единственную full-width колонку (.rq-flow). Единственное структурное изменение десктопа — этот свитчер; всё остальное (контекст поста, фильтр, карточки, диалог) сохранено, просто на полной ширине.
Состояния одним взглядом. Два твика (?demo=1): dark и state. state = Live (свитчер + комментарии) · Loading (skeleton свитчера + 3 SkeletonCard) · Empty (per-tab пусто / нет постов) · Error (ErrorBanner). Статусы карточек уже в сид-данных: new · generating · draft · approved · replied · skipped. Лимит ответа — 500 символов. Публикация — только через confirm-диалог.

1Идентификация экрана

Маршрут, назначение, новая раскладка сверху вниз: sidebar | main(topbar + scroll(content: page-intro + post-switcher(sticky) + flow(context + filter + comments))).

Маршрут/app/replies. Пункт Replies в группе Workspace, tester-gated (badge 3). Демо: ?demo=1 + Tweaks.
ТипПолный app-shell: <window.Sidebar active="replies"/>. Каркас 1:1 из Studio.
НазначениеОчередь ответов на комментарии. На каждый: generate (Pennedly пишет ответ в голосе) → edit/regenerate → approve → publish (тред-ответ в Threads). Цель — «inbox zero» без потери голоса. Лимит ответа 500.
Новая раскладкаОдна колонка. .page-intro → .rq-switch (горизонтальный post-свитчер, sticky) → .rq-flow: <PostContext> + <StatusFilter> + лента комментариев. Левого master-списка нет.
Ширина контентаwide = --content-wide 960px. Топбар выровнен через .topbar-inner.topbar--wide.
ТопбарЗаголовок «Replies» + .status-pill: --accent «N need a reply» (когда есть new) / --success «All caught up». Действия — тема + Settings.
Свитчер постовГоризонтальный ряд чипов (.rq-chip 280px), snap-scroll, sticky под топбаром. Это то, чем меняешь пост — остаётся в досягаемости при прокрутке длинного списка комментов.
Фазы (state)loading (skeleton свитчера + 3 SkeletonCard) · ready · per-tab empty · глобальный empty (нет постов) · error (ErrorBanner).
Backend-правдаThreads-API отдаёт только @username комментатора — без аватара и имени; карточка их не выдумывает. Лайков по ответам API не отдаёт → их нет нигде. Время — в локальной TZ зрителя.

REWORKED2.2 — Post-свитчер .rq-switch / .rq-chip главное

Горизонтальный ряд чипов-постов, snap-scroll, sticky под топбаром (он — то, чем меняешь пост, поэтому остаётся в досягаемости при прокрутке длинного списка комментов). Чип: короткий сниппет поста (clamp 2) + дата + бейдж числа неотвеченных комментов; активный чип — accent-кольцо + tint. Ширина чипа 280px (шире мобильных 220px — видно несколько одновременно). На десктопе нет свайпа, поэтому обязательны мышиные аффордансы:

4Что не меняется What does not change

Это layout-pass. Единственное структурное изменение десктопа — левый master-список → горизонтальный свитчер сверху. Всё прочее идентично прежнему и мобильной спеке:

  • Жизненный цикл new → generating → draft → approved → replied; skip / restore.
  • Лимит ответа 500 символов (REPLY_LIMIT), счётчик «N / 500».
  • Перевод комментария и ответа — инлайн-тогл «Translate from {lang}» ↔ «Show original», независимо, только у комментариев с полем lang.
  • Тред-блок ответа с нитью-веткой и строкой «You».
  • Сигнал автопилота «Auto-replied by Pennedly» на блоке ответа.
  • Состояния loading / empty / error.
  • Threads отдаёт только @username комментатора — без аватара и имени; карточка их не выдумывает.

5Один идиом · Web ↔ Mobile

Теперь свитчер — общий идиом на обоих: десктоп = широкий горизонтальный ряд со стрелками / драгом / fade, мобайл = swipe (Replies-Mobile-SPEC §4). Прежнее описание «left list of posts» в мобильной спеке устарело — десктоп тоже горизонтальный свитчер, просто шире. Брейкпоинты: 880px (shell → icon-rail) · 600px (телефонный слой).

Десктоп ( > 880 )

  • Фикс. сайдбар; одна колонка 960.
  • Master → горизонтальный post-свитчер сверху (sticky); 280px чипы.
  • Аффордансы: стрелки ‹ ›, fade на краях, click-drag + shift+wheel, авто-доскролл активного, ←/→.
  • Комментарии выбранного поста — full-width; деталь публикации = центр. modal.

Телефон ( ≤ 600 )

  • Нет сайдбара/таб-бара; гамбургер → drawer; свободный нижний край.
  • Тот же свитчер, sticky; 220px чипы; swipe вместо стрелок.
  • Шапка карточки = @username + время; футер двухъярусный (иконки 44×44 + grow-primary).
  • Публикация = bottom-sheet (primary сверху).
Единственные отличия десктоп↔мобайл: ширина чипа (280 vs 220), аффорданс прокрутки (стрелки/драг vs swipe) и форма детали публикации (modal vs bottom-sheet). Идиом (горизонтальный свитчер постов), статусы, перевод, тред, @username-шапка — идентичны. Парный документ: Replies-Mobile-SPEC.html.

8Чек-лист реализации

  • Полный app-shell; активный пункт = Replies (Workspace, tester-gated, badge 3); топбар «Replies» + status-pill (accent «N need a reply» / success «All caught up»); ширина --content-wide 960, одна колонка.
  • Левый master-список убран; посты — горизонтальный post-свитчер сверху (.rq-switch), sticky под топбаром; чипы 280px (сниппет clamp-2 + дата + бейдж неотвеченных); активный = accent-кольцо + tint.
  • Десктоп-аффордансы прокрутки: стрелки ‹ › (при overflow) + fade на краях + click-drag + shift+wheel + авто-доскролл активного чипа + клавиатура ←/→ + фокус-кольца.
  • Состояния свитчера: few (стрелки/fade скрыты) · overflow (стрелки + fade) · активный центрируется.
  • Под свитчером (full-width): контекст поста (текст + время + Open in Threads) → фильтр статусов ×5 (All/Needs/Draft/Replied/Skipped, не sticky) → карточки комментариев.
  • Карточка = @username + время (без аватара/имени) + бейдж статусa + ✕ remove; тело (measure ≤72ch) + инлайн-перевод (коммент и ответ независимо).
  • Тред ответа: new → generating (nib) → draft → approved → replied (success / «Auto-replied by Pennedly») + skipped; editing = textarea + «N / 500».
  • Футер по статусу (несколько кнопок — норма); generating скрывает футер.
  • PublishReplyDialog: цитата комментария + превью ответа + Publish reply; тост + Undo.
  • Состояния: Default / Loading (свитчер-скелет + 3 карточки) / per-tab Empty / Error (Retry).
  • Корректно в светлой и тёмной теме; только семантические токены; копи выживает в 8 локалях; клавиатура и фокус доступны.
