Global App Footer /app/* · sidebar + topbar + main

Постоянный, ненавязчивый легал-футер внутри авторизованного приложения. Сегодня ссылки Privacy / Terms / Data Deletion живут только на логине и маркетинговом лендинге — внутри /app/* их нет. Для GDPR и публичного запуска нужны заметные, постоянные легал-ссылки на каждом экране. Решение: тонкая полоса в хвосте скролл-области, которая прижимается ко дну вьюпорта на коротких страницах (sticky-footer, не fixed) и втекает после контента на длинных. Вторичный стиль на существующих токенах, в спокойной эстетике LegalLayout, светлая+тёмная, адаптив, тап-таргеты ≥44px, локализован под 8 локалей. Все состояния — в живых фреймах из реальных DS-классов.

+ app-foot.css studio.css · .scroll shell.css ds/tokens.css /privacy · /terms · /data-deletion mailto:support@pennedly.com
Одним взглядом. Футер — хвост .scroll (не position:fixed, не в сайдбаре): прижат ко дну на короткой странице, втекает после контента на длинной. Состав: © Pennedly {год} · Privacy / Terms / Data deletion (→ /privacy · /terms · /data-deletion, та же вкладка) · support@pennedly.com (mailto:). Стиль вторичный: text-subtle/muted, hairline border-top, surface/bg. Состояния: default · hover (подчёркивание) · focus-visible (accent-ринг 2px) · мобайл (стек, ≥44px). Только семантические токены — корректно в светлой и тёмной. Копи — через footer.*, живёт в 8 локалях.

1Идентификация компонента

Один общий компонент оболочки, рендерится один раз в каркасе и виден на каждом экране /app/*. Не зависит от конкретной страницы; не дублируется в контенте экранов.

ОбластьВсе авторизованные маршруты /app/* (Studio, Feed, Replies, Stats, Scenarios, Settings, Overview …). Один экземпляр на оболочку — НЕ per-screen.
ТипЧасть app-shell. Рендерится как последний потомок .scroll, внутри .main, рядом с .content.
НазначениеПостоянная, заметная юридическая навигация (GDPR / публичный запуск): Privacy, Terms, Data Deletion + копирайт + контакт поддержки.
Тон / стильВторичный, тихий. Заимствует спокойную эстетику .legal-foot из LegalLayout: hairline сверху, приглушённый текст, без фоновых заливок и акцентных плашек.
Чего НЕ делаетНе position:fixed (не ест вьюпорт, не перекрывает контент). Не в сайдбаре (не конкурирует с навигацией и не исчезает на icon-rail ≤880). Не несёт продуктовых ссылок — только легал + поддержка.
ИсточникНовый app-foot.css (компонент) + правка .scroll в studio.css (flex-column для sticky-footer). Без новых зависимостей.

2Размещение — рекомендация хвост .scroll

Бриф предложил три варианта. Рекомендую «хвост скролл-области, прижатый ко дну». Сравнение по требованиям «заметно и постоянно (GDPR)», «не перекрывает короткие страницы», «не конкурирует с основной навигацией»:

★ выбрано — хвост .scroll

Полоса в конце контентной области

  • Постоянно: один экземпляр в каркасе → виден на каждом /app/*.
  • Не перекрывает: sticky-footer — на короткой странице прижат ко дну вьюпорта, на длинной втекает после контента. Никогда не висит поверх.
  • Не конкурирует: отдельно от сайдбара, вторичный тон, низ экрана.
  • Знакомый SaaS-паттерн (низ рабочей области).
отклонено

Ссылки в подвале сайдбара

  • Конкурирует с account-control и основной навигацией.
  • Пропадает на icon-rail ≤880 и на мобайле (drawer закрыт) → не «постоянно заметно» для GDPR.
  • Тесно: подвал уже занят аккаунт-меню.
отклонено

Фиксированная полоса (position:fixed)

  • Перекрывает контент и ест вертикаль на коротких экранах.
  • Конфликтует с мобильным таб-баром / нижним краем.
  • Лишний постоянный «шум» для вторичных ссылок.
частично

Только блок в конце скролла (без прижатия)

  • На длинных страницах — отлично.
  • Но на короткой странице футер повисает в середине вьюпорта (контент не заполняет высоту) — выглядит сломанным.
  • Решается прижатием ко дну → это и есть выбранный вариант.
Итог. Футер = хвост .scroll + .scroll становится flex-колонкой, а .content получает flex:1 0 auto. Контент растёт и прижимает футер ко дну на короткой странице; на длинной — футер естественно идёт после контента. Лучшее из «прижато» и «втекает», без position:fixed.

3В оболочке — контекст live

Реальный каркас (.app → .sidebar + .main(.topbar + .scroll)) с короткой страницей: контент не заполняет высоту, футер прижат ко дну. Светлая и тёмная — фреймы из реальных классов studio.css + shell.css + app-foot.css.

Топбар липкий, сайдбар фиксирован, скроллится только .scroll. Футер — вне .content-колонки по фону (полно-ширинный hairline), но его внутренняя строка .app-foot-in выровнена по той же контентной ширине, что и топбар/контент.

4Контракт размещения sticky-footer

Минимальная правка каркаса: .scroll становится flex-колонкой, .content растёт, футер держит свою высоту. .content с margin:0 auto по-прежнему центрируется по горизонтали (auto-маржины в flex переопределяют stretch).

Что добавить в каркас

СелекторПравило
.scroll+ display:flex; flex-direction:column;
.scroll > .content+ flex:1 0 auto; (растёт → прижимает футер)
.app-footflex:0 0 auto; (держит высоту) — уже в app-foot.css
Замечание по нижнему паддингу. Сейчас .content несёт padding-bottom:96px (зазор под мобильный таб-бар). С футером в хвосте этот зазор остаётся валидным (он отделяет контент от hairline футера) — менять не требуется; футер держит собственный вертикальный паддинг.

5Анатомия и состав band

Слева — копирайт + точка-разделитель + легал-ссылки; .af-sp отталкивает контакт поддержки к правому краю. Крупный план: ширина reading (по умолчанию) и wide (модификатор для data-экранов). Светлая и тёмная:

Элемент / классОписание
.app-footПолоса: flex:0 0 auto, border-top:1px var(--color-border), фон --color-bg. role="contentinfo".
.app-foot-inВнутренняя строка: max-width = контентная ширина, margin:0 auto, flex с flex-wrap, gap:8px 18px. Тон --color-text-subtle, --text-small.
.app-foot--wideМодификатор: .app-foot-in → max-width:--content-wide (960). Для data-экранов (Feed/Stats/Replies/Mentions/Scenarios), как .topbar--wide.
.af-copy«© Pennedly {год}» — footer.copyright, {year} подставляется рантаймом. white-space:nowrap.
.af-dotТонкая точка-разделитель между копирайтом и ссылками. Скрыта на мобайле.
.af-links · .af-link<nav aria-label="Legal"> с тремя ссылками. Цвет --color-text-muted; hover → --color-text + подчёркивание.
.af-spSpacer flex:1 1 auto — отталкивает поддержку вправо (desktop). Скрыт на мобайле.
.af-support · .af-mailMailto-контакт: иконка письма (--color-text-subtle) + e-mail. .af-sr — sr-only префикс «Support:» (footer.support).

6Состояния default · hover · focus

Default — приглушённый. Hover — цвет к --color-text + подчёркивание. Focus-visible — общий ринг приложения: 2px solid var(--color-accent), outline-offset:2px. Слева: hover на «Terms» + focus-ринг на «Privacy». Справа: focus-ринг на mailto (тёмная).

СостояниеЧто рендерится
defaultmuted-ссылки, subtle-копирайт, hairline сверху. Без подчёркиваний.
hovercolor → --color-text; underline 1px, offset 2px, decoration-color 45% текста.
focus-visibleoutline 2px accent, offset 2px, radius-sm. Полностью с клавиатуры (Tab); ссылки в DOM-порядке.
active / visitedбез особого стиля (легал-ссылки нейтральны); active наследует hover-цвет.
мобайлсм. §7 — стек, тап-таргеты ≥44px.

7Адаптив + мобайл ≤640 · ≥44px

На ≤640px (телефон / свёрнутая оболочка) строка переходит в стек, выравнивание по левому краю, .af-sp и .af-dot скрыты. Ссылки и mailto получают min-height:44px — комфортные тап-таргеты. Длинные RU/DE-лейблы оборачиваются, не клипаются.

Десктоп ( > 640 )

  • Одна строка: копирайт · • · легал-ссылки  —  spacer  —  поддержка справа.
  • Ширина .app-foot-in = контентная (reading 720 / wide 960), выровнена с топбаром.
  • Тап-зоны компактные (мышь), focus-ринг 2px.

Мобайл ( ≤ 640 )

  • Стек: копирайт сверху, легал-ссылки строкой (wrap), поддержка снизу.
  • Каждая ссылка/контакт — min-height:44px, выравнивание по центру вертикали.
  • Паддинг 12px 20px 20px; нижний зазор под свободный край.

10Доступність

  • Лендмарк: <footer role="contentinfo"> — единственный contentinfo приложения; легал-ссылки внутри <nav aria-label="Legal">.
  • Клавиатура: все ссылки фокусируемы по Tab, в DOM-порядке (Privacy → Terms → Data deletion → Support); видимый :focus-visible ринг 2px accent.
  • Поддержка для скринридера: .af-sr даёт mailto-ссылке префикс «Support: support@pennedly.com» (footer.support), оставаясь визуально только e-mail.
  • Контраст: idle-ссылки на --color-text-muted ≥ 4.5:1 на --color-bg в обеих темах; hover усиливает до --color-text.
  • Цель тапа: ≥44px на мобайле (min-height:44px); на десктопе компактнее (мышь), но фокус-зона видима.
  • Mailto — реальная ссылка (не onclick), работает без JS и в новой вкладке по среднему клику.

12Чек-лист реализации

  • Один экземпляр в app-shell — последний потомок .scroll, виден на всех /app/*; не position:fixed, не в сайдбаре.
  • .scroll → flex-колонка; .content → flex:1 0 auto; футер прижат ко дну на короткой странице, втекает после контента на длинной.
  • Состав: © Pennedly {год} · Privacy / Terms / Data deletion (→ /privacy · /terms · /data-deletion, та же вкладка) · support@pennedly.com (mailto:).
  • Вторичный стиль на токенах: text-subtle/muted, hairline border-top, фон --color-bg; эстетика LegalLayout. Без хардкод-hex; корректно в светлой и тёмной.
  • Ширина .app-foot-in = контентная; .app-foot--wide для data-экранов (выровнено с топбаром).
  • Состояния: default · hover (underline) · focus-visible (accent-ринг 2px, offset 2px) — полностью с клавиатуры, DOM-порядок.
  • Адаптив: ≤640 → стек, .af-sp/.af-dot скрыты, тап-таргеты ≥44px; длинные RU/DE-лейблы оборачиваются.
  • A11y: role="contentinfo", <nav aria-label="Legal">, sr-only префикс «Support», контраст ≥4.5:1.
  • Копи — через footer.privacy / footer.terms / footer.data_deletion / footer.copyright / footer.support; живёт в 8 локалях; {year} — рантайм-параметр.
  • Без новых зависимостей: новый app-foot.css + одна правка .scroll в studio.css.
