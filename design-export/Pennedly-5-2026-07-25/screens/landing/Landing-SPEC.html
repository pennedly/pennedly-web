Лендинг / — пиксель-в-пиксель

Дотошная спецификация публичной маркетинговой страницы для переноса в живой код (Next.js + Tailwind v4). Это направление «продукт-форвард»: спокойный герой с живым «оконным» превью продукта Studio, бенто-сетка фич, юридический футер. Все значения взяты из канонического дизайна (landing.*) — конкретные px и имена токенов, отдельно для веб- и мобильной версий. По этому документу страница воспроизводится 1-в-1.

landing-app.jsx landing-parts.jsx landing-data.jsx landing-icons.jsx landing.css ds/tokens.css ds/components.css
Критично для пиксель-в-пиксель — переопределение .btn--lg. В ds/components.css §3.6 задано .btn--lg { height:46px; border-radius:var(--radius-lg) }, но landing.css подключается после и переопределяет: .btn--lg { height:48px; padding-inline:22px; font-size:var(--text-body); border-radius:var(--radius-md) }. На Лендинге выигрывает версия из landing.css → CTA-кнопка героя 48px, радиус 10px (--radius-md). Воспроизводить именно так.
Адаптив реализован контейнерными запросами. Корень .land имеет container-type: inline-size; все брейкпоинты — @container (max-width: …), а не @media. На реальном вьюпорте контейнер = ширине окна, поэтому страница перестраивается как обычная адаптивная вёрстка; в демо-режиме «Mobile» та же логика срабатывает внутри узкой рамки. При переносе допустимо заменить на @media с теми же порогами, если демо-рамка не нужна.

1Идентификация экрана

Маршрут, назначение, позиционирование, условия показа и общая раскладка сверху вниз.

Маршрут/ — публичный корень app.pennedly.com. Pre-auth.
ОболочкаНет app-shell, нет сайдбара. Собственная маркетинговая раскладка. Корневой узел — .land (в живом коде; .land-host — только демо-обёртка, см. §6).
НазначениеСпокойно, без хайпа объяснить Pennedly и привести посетителя к Sign in.
ПозиционированиеPennedly — напарник-черновик («drafting partner»): пишет черновики постов и ответов в голосе пользователя, пользователь утверждает каждое слово. Автопилот — опциональная функция (opt-in), никогда не выносится в заголовок. Формулировка «Threads на автопилоте» запрещена.
Статус продуктаIn development · invite-only beta. Публичной регистрации нет — единственный CTA «Sign in» (→ Login.html).
Демо в герое«Оконное» превью Studio и черновик — иллюстративный сэмпл, не живой фид.
ЮридическоеСтраницы Privacy / Terms / Data Deletion существуют и линкуются из футера.
ТемаСветлая и тёмная — обе first-class, переключатель в топбаре + твик.
ЛокализацияВся chrome-копия локализуется в 8 локалей (EN — базовая); переключатель языка в топбаре. Сэмпл-черновик не локализуется.

Раскладка сверху вниз

  1. Топбар .land-top — бренд (лого + «Pennedly») слева; справа: переключатель языка, переключатель темы, кнопка «Sign in».
  2. Герой .hero — две колонки: слева копи (статус-пилюля, заголовок, лид, строка «You approve every word.» + акцентный «Autopilot…», CTA «Sign in» + контактный mailto); справа «оконное» превью Studio .window с черновиком.
  3. Фичи .features — эйбрау + заголовок + бенто-сетка из 6 карточек (две крупнее).
  4. Футер .land-foot — бренд + © год + 3 юридические ссылки.

2Анатомия

Пронумерованный список каждой секции и каждого элемента внутри неё, с классом как в коде. Порядок DOM — сверху вниз.

0. Корень страницы

  • .land — флекс-колонка, min-height:100%, container-type:inline-size, фон = радиальный «бумажный» градиент над --color-bg. Содержит 4 секции ниже.

1. Топбар .land-top

  • .wrap.land-top-row — флекс-ряд, align-items:center, gap:12.
  • .brand — <Logo size=30 radius=9> (класс .bm) + .bn «Pennedly».
  • .sp — гибкий спейсер flex:1 1 auto.
  • .actions — gap:9: LanguageSwitcher .lang → theme .icon-btn → Sign in a.btn.btn--primary (→ Login.html).
  • Под топбаром — border-bottom:1px solid var(--color-border).

Переключатель языка .lang

  • .lang-trigger — <IcGlobe 16> + .lang-code (текущий код, напр. «EN») + <IcChevDown 14> .lang-chev. aria-haspopup="listbox", aria-expanded.
  • .lang-menu (открыт) — role="listbox", абсолютно под триггером справа; 8× .lang-opt (role="option"): .lang-opt-label (эндоним) + .lang-opt-code (моно-код) + у активного <IcCheck 14> .lang-opt-ok.
  • Закрытие: клик вне (mousedown), Esc.

2. Герой .hero

  • .wrap.hero-grid — грид 2 колонки 1fr / 1.02fr. При выключенном сэмпле — .hero-grid--solo (одна центрированная колонка, текст по центру).
  • Левая колонка .hero-text:
    • .status — .sdot (пульсирующая точка, --color-warning) + текст статуса.
    • h1.hero-title — заголовок.
    • p.hero-lead — лид.
    • p.hero-approve — «You approve every word.» + span.emph (акцент) «Autopilot's there…».
    • .hero-cta — a.btn.btn--primary.btn--lg «Sign in» + <IcArrowRight 17>; a.contact (<IcMail 15> + email, mailto:).
  • Правая колонка — «оконное» превью .window (см. ниже). Рендерится только если showSample.

«Оконное» превью Studio .window

  • .winbar — .dots (3× <i> 10×10) + .url «app.pennedly.com» + .url-path «/studio» (по центру, моно).
  • .app — флекс, min-height:280:
    • aside.rail (w58) — 4× .rail-acct (<Avatar 28>; первый .is-active с рамкой --color-text) + .rail-add (<IcPlus 15>, пунктир).
    • .compose — .compose-head (<Avatar 34> + .spec-id: .spec-name/.spec-handle + .badge «Draft» с .bdot warning); p.compose-text (текст черновика) + .caret (мигающая каретка, акцент); .compose-tools (.chip.chip--accent «In your voice» + .chip «Warm, direct»); .compose-foot (.foot-note «Drafting in Mara's voice» + спейсер + .ghost «Edit» + .ink «Approve»).
  • aria-hidden="true" на всём окне (декоративная иллюстрация).

3. Фичи .features

  • .feat-head — .eyebrow «The product» + h2.feat-title «One workspace…».
  • .bento — грид 3 колонки, gap:16; 6× article.feat. Спаны: фича 1 «voice» = .feat--wide (2 кол., крупнее заголовок); фича 6 «accounts» = .feat--full (на всю ширину, горизонтальная, фон --color-surface-2); остальные — 1 колонка.
  • Карточка: .feat-ico (40×40 плитка, иконка 18) + .feat-body (h3.feat-t + p.feat-d).
  • Иконки: voice→IcVoice, replies→IcReplies, audits→IcAudit, analytics→IcChart, autopilot→IcBolt, accounts→IcUsers.

4. Футер .land-foot

  • .wrap.land-foot-row — .foot-brand (<Logo 20 r6> .fm + «© {год} Pennedly») + .foot-sp (спейсер) + nav.foot-links (3× a: Privacy Policy / Terms of Service / Data Deletion).

3Раскладка и адаптив — ВЕБ vs МОБАЙЛ

Контейнер, точки перелома (контейнерные запросы к .land), сетки и что именно меняется. Десктоп / планшет / мобайл.

Контейнер и брейкпоинты

ПараметрЗначение
.wrap max-width1120px
.wrap padding-inline40px (≤560cqi → 20px)
Десктопконтейнер ≥ 881px
Планшет561–880px
Мобайл≤ 560px

ВЕБ (десктоп ≥ 881)

  • Герой: .hero-grid = 1fr / 1.02fr, gap 56, выровнен по центру. Превью окна — справа.
  • .hero padding 52 / 0 / 72.
  • Фичи: .bento = 3 колонки; .feat--wide span 2; .feat--full span 3.
  • Топбар, футер — в один ряд.

ПЛАНШЕТ (561–880) / МОБАЙЛ (≤560)

  • Герой: .hero-grid → 1 колонка, gap 44; превью окна уходит под копи. .hero padding 32 / 0 / 52.
  • Фичи: бенто → 2 колонки (планшет), все спаны = span 2; → 1 колонка (мобайл), спаны = 1; .feat--full становится вертикальной.
  • Мобайл: .wrap padding 20; заголовок героя ужимается (clamp(2rem, 9cqi, 2.4rem)).
  • Превью окна остаётся (это якорь героя); внутри рейл + composer сохраняются.
Демо-рамка «Mobile». В демо (.land-host.is-mobile) .land ужимается до 412px с рамкой-телефоном (radius 34, тень lg); контейнерные запросы срабатывают внутри неё. На живой странице обёртки нет — адаптив идёт от ширины окна.

＊Новые секции — Voice Test · The difference

Две новые секции лендинга, в том же спокойном редакторском стиле. Полноширинные секции с верхним бордером и .wrap; рендер вживую на реальном слое (landing.css + landing-sections.css), светлая и тёмная. Мобайл — в Landing-Mobile-SPEC.html.

1. Voice Test — ввод по постам (нумерованные карточки) после героя · public, no-signup

Эйбрау + H2 + sub + строка No signup остаются без изменений — меняется только ввод. Раньше это была одна textarea, а посты делились по пустой строке (\n\n) — поэтому один пост с абзацом внутри рвался на два. Финальный ввод — Вариант C: одно поле ввода + кнопка Add post. Каждый добавленный пост сворачивается в компактную нумерованную карточку («1», «2», «3»…) над полем с × для удаления; поле очищается для следующего. Абзацный перенос внутри поста его не делит — в этом весь смысл.

Канон. Ниже карточек — кнопка Run («Draft replies in my voice»). Границы явные: каждый пост — отдельная нумерованная карточка. Минимум — 1 пост (Run включается при ≥1), потолок — ~5 в UI (на сервере 10); при потолке «Add post» скрыт. Иконки: IcPlus для «add», IcX для «remove».

Voice Test в контексте страницы (полный лендинг)

Секция на своём месте: топбар → герой с product-peek → Voice Test → The difference → футер. Рендер на реальном слое (тот же .land / landing.css), ширина 1040px (десктоп). Состояние — «3 карточки». Прокрутите кадр вправо, если не влезает.

Состояния ввода — веб, светлая / тёмная

Полноразмерные кадры реального рендера. Кадр «3 карточки» доказывает главное: в карточке 1 — внутренний абзацный перенос, и пост остаётся одним.

Общие состояния — running · results · error (без изменений)

Running — занятая кнопка Run; Results — список карточек «incoming comment → drafted reply in your voice»; Error — danger-строка. Эти состояния и копи секции не меняются.

2. The difference после бенто · closed-loop coach

Faint surface-2 фон; eyebrow «The difference» + H2 + sub. Три нумерованных шага (accent-чип) со стрелкой-коннектором: draft → measure → adjust (шаг 3 = «Adjusts every week»). На узком контейнере карточки становятся стопкой, стрелка — вниз. Честная позиция: петля, вы утверждаете, авто-откат — без оверклейма автономии.
