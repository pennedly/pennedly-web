Audits /app/audits — phone

The weekly audit: once a week Pennedly’s coach reviews how the account did and proposes small refinements to your voice, role-book and style. You accept or reject each one; accepted changes are effect-tracked and auto-rolled-back if they hurt performance. The dense parts on a phone are the before→after diffs and the decision rows. This spec stacks the diff vertically (current above proposed) and lays decisions out full-width, fitting cleanly at 390px (sanity-checked at 360). A reading-width, text-heavy screen — same tokens, content and flow as the desktop spec; only the layout changes below 600px, on the decided shell (hamburger + drawer, no tab bar, free bottom edge). Frames are the real component layer at 390px, light and dark.

pennedly-mobile.css audits-app.jsx audits-change.jsx audits-parts.jsx shell-parts.jsx
What does not change. Audits are generated weekly by a background job — the user can’t trigger one. The only actions are Accept / Reject per suggestion; accepted changes apply to the role-book/style, are effect-tracked, and negative ones auto-roll-back server-side and are surfaced. The WoW delta and the diffs (old_text vs new_text) come from the backend. Read-only otherwise. Mobile is a layout pass; the only structural change is the shared app shell.

5fixSuggestion card + diff

Each suggestion = a kind badge + title + status, a short description, an optional before→after diff, and the decision. The diff is where a phone breaks if you try two columns.

Before

The desktop diff can sit current-vs-proposed side by side. At 390px two text columns shrink to ~150px each, wrap into ragged stacks, and the “−/+” intent gets lost.

After

The diff stacks vertically: a labelled Now block (danger-tinted, “−”) above a Proposed block (success-tinted, “+”), each full-width and wrapping freely. Decisions stack full-width below: Reject + Approve (primary) as equal 44px buttons that wrap on long locales.

Rules. The diff is collapsible behind a “View change” link on dense audits (shown expanded here). “Now” = current role-book/style text; “Proposed” = the new text. An autopilot-config suggestion swaps the diff for proposed posting-hour chips in local time. Add-a-note stays available while undecided. Once decided the card is read-only — no undo (append-only backend).

6Decision states

A suggestion moves through: undecided → applied (then effect-tracked) or rejected. An applied change that hurt metrics is auto-rolled-back server-side and surfaced with a note.

StatePhone treatment
undecided“Needs review” badge; diff + Reject/Approve full-width.
applied“Applied” badge; effect chip — “measuring effect…” then the measured “+N% {metric}”. Read-only.
rejected“Rejected” badge; card dimmed; “You rejected this suggestion”.
rolled back“Rolled back” warning badge; the negative effect chip + an “Auto-rolled-back” note explaining it hurt performance and was reverted — no action needed.

7Past audits (history)

Below the current audit, a list of prior weeks. Each row stacks: the week + a status badge, a 2-line summary, then a meta line (range · decided count · WoW). Tap to open that week’s audit.

10Web ↔ mobile

Desktop ( > 900 )

  • Fixed sidebar; ~720px reading column; coach narrative + cards.
  • Diff can sit current-vs-proposed side by side.
  • Decision actions inline on the card foot; history as a side list.

Phone ( ≤ 600 )

  • No sidebar/tab bar; hamburger → drawer + account; free bottom edge.
  • Diff stacks: Now (−) above Proposed (+), full-width.
  • Decisions stack full-width; history is a column of stacked rows.

11Localization & 360px

Coach copy, kind badges, status badges, the diff labels (“Now” / “Proposed”), decision buttons and the WoW/effect phrases all localize into 8 locales; DE/RU/UK run ~30–40% longer. On a phone: the WoW badge wraps under the week title; the diff blocks grow taller as text wraps (never truncated — the whole point is to read the change); Reject/Approve wrap to two rows rather than shrink below 44px; history summaries clamp to 2 lines. Diffs are live text, never baked into an image.

360px behavior. No new breakpoint — the gutter stays 14px; the reading column just gets ~30px narrower, so diff and body text simply rewrap to more lines. The decision buttons are the only width-sensitive element; on a long locale at 360 they stack to two full-width rows (Approve over Reject), still ≥44px. The drawer stays min(82%, 312px) → 82% (≈295px) at 360.

12Checklist

  • Below 600px there is no sidebar and no tab bar — one 52px top bar with a hamburger far-left.
  • Hamburger opens the left drawer (active = Audits, “needs review” badge) + account; bottom edge free.
  • Audit header shows week + range + posts + WoW delta badge + summary + progress.
  • Diffs stack vertically: “Now” (−, danger) above “Proposed” (+, success), full-width — never two columns.
  • Decisions are full-width (Reject + Approve, primary obvious, 44px) and wrap on long locales.
  • Decided cards are read-only; applied shows the measured effect chip (or “measuring…”).
  • Auto-rolled-back changes show the “Rolled back” badge + a note explaining it hurt metrics and was reverted.
  • Autopilot-config suggestions show proposed posting hours in local time.
  • Past audits are a column of stacked rows (week + badge, 2-line summary, range · decided · WoW); tap to open.
  • Loading = skeleton header + cards; empty = “no audits yet”; error banner has Retry.
  • Long bodies/labels wrap — never clipped; sanity-checked at 360px.
  • Correct in light and dark; no hardcoded colour.
