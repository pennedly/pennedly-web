Pennedly · Spec · Studio — thread chains (multi-part posts)

Thread chains /app — a draft that posts as a chain

A draft can publish as a thread: a line containing only --- splits the body into parts, and the chain posts as a lead post + chained replies. Threads caps each part at 500 characters. This lives on the draft card in two modes. Edit: the body is one textarea (parts separated by --- lines), with a “New part” pill and a row of per-part counters — a single post shows the normal char-meter instead. View: an IcThread “Thread · N” badge over the parts rendered as stacked soft cards. The feature shipped without a design; this is its reference spec. Every state is the real draft card (studio.css + studio-thread.css) over ds/tokens.css, in light and dark.

studio-thread.css StudioParts.tsx studio.css compose-media.css studio-icons.jsx ds/tokens.css
Extend, don’t redesign. A thread is the same draft card when the body has --- parts — the header, footer, tokens and motion are unchanged. The ----on-its-own-line separator is how a thread is authored; the editor shows it literally. Each part is capped at 500 chars and an over-limit part visibly blocks approve/publish (never silently truncated). Media rides the lead part only (see the media spec).

0Where it lives

All of this sits on the draft card, between the header (avatar / meta / status) and the action footer (approve / publish) — the shipped spot. Edit mode shows the editor + tools; view mode shows the badge + stacked parts.

＊New icon needed

IcExternal (the “Open in Threads” link) is reused from the shipped set. But there is no thread glyph in studio-icons.jsx — the “New part” pill and the “Thread · N” badge need one. Add IcThread to icons.tsx in the same 24-grid / 1.8-stroke family: three beads on a thread reads as a chain of parts.

Usage. IcThread — the “New part” pill, the “Thread · N” badge, and the lead-post tag. No new tokens are introduced.

1Edit · single post

A normal single-post draft in edit mode: the editable body, the standard char-meter, and the “New part” pill — tapping it appends a --- separator and turns the draft into a thread. Nothing about the single-post card regresses.

2Edit · thread (2–3 parts)

When the body contains --- lines, the char-meter is replaced by a row of per-part counters (Part 1 · 234/500…), each with tabular figures. The separators read literally in the editor; the “New part” pill appends another.

3Edit · a part over 500

If any part exceeds 500, its counter turns danger + bold and an inline hint appears. Save is disabled, and the card’s downstream Approve / Publish are blocked until it’s trimmed — Pennedly never truncates a part silently.

4View · thread draft

Read mode: an IcThread “Thread · 3” badge, then the parts as stacked soft cards (bg-surface-2 ~55%, rounded, 1px border), chained by a thin connector. The lead part is tagged; the footer is the normal draft foot (⋯ + Approve).

5View · thread published

Once published the same stacked layout reads muted, with the published stats and an “Open in Threads” link that opens the live chain.

6Thread + media (interplay)

When a thread carries media, it rides the lead part only. The lead card shows the media + an “attached to the first post” cue; follow-up parts stay text-only. (The media controls themselves are specced in the Compose-Media spec — here we only show the thread ↔ lead-media relationship.)

＊Guardrails

Limits & integrity

  • Each part ≤ 500. An over-limit part turns its counter danger/bold and blocks Save/Approve/Publish — never silently truncated.
  • Media on the lead only. Follow-up parts never carry media; the lead shows the “attached to the first post” cue.
  • A thread is the same card as a single post with --- parts — the single-post path is not regressed.
  • Authoring stays ----on-its-own-line (client mirror of thread_split); the “New part” pill just inserts it.

Localization (8 locales)

  • Counters use tabular numbers so “234/500” columns don’t jitter as parts change.
  • “Part N” labels and the “Thread · N” badge wrap rather than clip; DE/RU run ~30–40% longer.
  • i18n keys exist: studio.thread_badge (“Thread”), studio.thread_new_part (“New part”), studio.thread_part (“Part”).

✓Checklist

  • Thread lives on the draft card, between header and footer — shipped spot; same card as a single post with --- parts.
  • Edit · single: textarea + “New part” pill + normal char-meter.
  • Edit · thread: --- separators read literally + “New part” pill + per-part counters (tabular).
  • Edit · over 500: that part’s counter danger/bold; Save + downstream Approve/Publish blocked with a hint; never truncates.
  • View · draft: “Thread · N” badge + stacked soft part cards, chained; lead tagged.
  • View · published: same, muted, with “Open in Threads” (IcExternal).
  • Thread + media: media on the lead part only + the “attached to the first post” cue; follow-ups text-only.
  • Counters tabular; “Part N” + badge wrap on long locales.
  • Correct in light and dark; no hardcoded colour. IcThread flagged for icons.tsx.
