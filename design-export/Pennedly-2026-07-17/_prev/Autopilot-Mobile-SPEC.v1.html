Pennedly · Mobile spec · per-screen

Autopilot /app/autopilot — phone

The opt-in automation, off by default: let Pennedly auto-post already-approved drafts at chosen hours (within a daily cap), and/or auto-reply to comments (within an audience filter). It’s framed as a quiet, scheduled helper — the icon is a clock (not a lightning bolt), and auto-replies use a speech bubble. This is a settings/form screen, so the work on a phone is making the controls fit and feel native: one column, labels above full-width controls, 44px targets, 16px fields. Same tokens, options and backend rules as the desktop spec; only the layout changes below 600px, on the decided shell (hamburger + drawer, no tab bar, free bottom edge). Frames are the real component layer at 390px, light and dark.

pennedly-mobile.css autopilot-app.jsx autopilot-parts.jsx shell-parts.jsx ds/tokens.css
What does not change. Autopilot is opt-in and off by default; turn it off anytime. Auto-post publishes only already-approved drafts, at whole-hour slots chosen in local time (stored UTC), up to a daily cap (backend default 5; UI options 10/25/50). Auto-reply answers comments matching the audience filter, in your voice. Exactly-once — no double-posting. Hours render in the viewer’s local timezone. No invented schedules, per-post scheduling, or filters the backend doesn’t have. Mobile is a layout pass; the only structural change is the shared app shell.

4fixForm controls — the fix

Desktop lays label · control out in rows with the control on the right. On a phone that splits the width and the selects shrink. The native form pattern:

Before

Label on the left, a select on the right share one ~360px row — the select ends up ~150px wide and its option text truncates; long locales push it off-screen.

After

Every control is a stacked field: a label above a full-width control. Selects/inputs are 44px tall with 16px text (no iOS zoom). Section on/off toggles stay right-aligned on the section header row.

Pattern. Section card = a header (icon + title + sub + toggle) and, when on, a body of stacked fields. Off sections collapse their body entirely, so the resting screen is short and calm. Toggles are 46×28 with a 44px-tall tap row.

9Web ↔ mobile

Desktop ( > 900 )

  • Fixed sidebar; reading column; sections with label · control rows.
  • Controls sit to the right of their labels.
  • Toggles right-aligned on the section header.

Phone ( ≤ 600 )

  • No sidebar/tab bar; hamburger → drawer + account; free bottom edge.
  • Stacked fields: label above a full-width 44px control.
  • Section toggles stay right-aligned; off sections collapse.

10Localization & 360px

Section titles/subs, field labels, hint lines, the audience/cap options and the status string all localize into 8 locales; DE/RU/UK run ~30–40% longer. On a phone: field labels wrap above their (already full-width) control rather than squeezing it; the hour chips and hint wrap; the audience/cap select shows long option text without truncating (the control is full-width); the section toggle never moves off the row. Hour and “next auto-post” times render in the viewer’s local timezone.

360px behavior. No new breakpoint — the gutter stays 14px; controls are already full-width so they just get ~30px narrower; the hour grid wraps to one more row at most. Toggles, selects and chips keep their 38–44px sizes. The drawer stays min(82%, 312px) → 82% (≈295px) at 360.

11Checklist

  • Below 600px there is no sidebar and no tab bar — one 52px top bar with a hamburger far-left.
  • Hamburger opens the left drawer (active = Autopilot) + account; bottom edge free.
  • Off by default — both toggles off at rest, with the opt-in/reassurance explainer visible.
  • Auto-post uses a clock icon; Auto-reply uses a speech bubble — never a lightning bolt.
  • Every control is a stacked field: label above a full-width 44px control; selects/inputs are 16px (no iOS zoom).
  • Auto-post on → whole-hour chips (local time, UTC±N hint) + daily cap (10/25/50) + “next auto-post” status.
  • Auto-post publishes already-approved drafts only (note shown).
  • Auto-reply on → audience filter select; “in your voice” note.
  • Section toggles right-aligned; off sections collapse their body.
  • Loading = skeleton sections; error banner has Retry.
  • Labels wrap on long locales — never clipped or pushing controls off-screen; sanity-checked at 360px.
  • Correct in light and dark; no hardcoded colour.
