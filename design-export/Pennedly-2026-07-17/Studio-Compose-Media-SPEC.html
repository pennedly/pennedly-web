Compose media /app/studio — toolbar & attachments

The shipped draft composer has an editable text area and a small media row (Add image → thumbnail strip). This spec extends that row into a full media toolbar for all post media — it does not redesign the card. The toolbar sits below the editor; attachments preview between the editor and the action footer (approve / schedule / publish), matching the shipped placement. Threads caps a part at 500 chars; a post can be a thread (split on a --- line) — when it is, media attaches to the lead part only. Every attach type is rendered in all its compose states, on the real product layers (studio.css for web, pennedly-mobile.css for phone) — for the web column and at 390px, in light and dark.

What stays the same. The editing card (head · .edit-area · .charmeter · footer), the chip idiom, tokens and motion are all unchanged. The shipped image idiom (picker → thumbnail strip → per-image remove, up to a carousel) is preserved and polished — drag-reorder and ALT are added on top. Mobile keeps ≥16px inputs and ≥44px targets.

0Where the toolbar & previews go

One region in the editing card, between the editor + char meter and the action footer. The toolbar is a compact row; attachment previews render beneath it. It respects card padding, never overpowers the draft, and stays thumb-reachable on mobile.

＊New icons needed

The toolbar reuses the existing set where it can (IcLink, IcCheck, IcX, IcPlus, IcSearch, IcGlobe, IcSparkle, IcAlert). These are new — add them to icons.tsx in the same 24-grid / 1.8-stroke family. “ALT” and “GIF” tile chips are text labels, not icons.

Usage. IcImage — Image chip + placeholder. IcVideo — Video chip. IcGif — GIF chip. IcPoll — Poll chip. IcDrag — thumbnail reorder grip. IcPlay — video play badge. IcUpload — picker / drop affordance. No new tokens are introduced.

1Toolbar & mutual exclusion

A compact row below the editor: Image · Video · GIF · Poll (line-icon chips). The link card has no button — it auto-appears from a URL. GIF is text-only and exclusive with image/video/carousel: when a GIF is attached the Image/Video chips disable with a hint; when image/video is attached, GIF disables. It never silently fails.

2Image(s)

The shipped idiom, polished: picker → thumbnail strip (1–20, posts as a carousel). Per thumbnail — remove (×), a drag grip to reorder, and an ALT affordance (empty vs filled). States: empty · 1 image · multi/carousel · reordering · uploading · error (JPEG/PNG/WebP, ≤8 MB).

— alt-text sheet

A small per-image/video sheet to add an accessibility description. Empty trigger on the thumbnail (“ALT”); once set, the chip turns success-green with a check.

3Video

Picker → upload progress (to Pennedly) → ready thumbnail with a play badge, duration chip, remove, and an ALT affordance. The inline limit hint sits below: MP4/MOV · ≤5 min · ≤1 GB. States: empty · uploading % · ready · error.

Threads-side processing is a publish-time concern — not designed on this screen. The composer’s job ends at a successful upload to Pennedly.

4GIF GIPHY · exclusive

Tapping GIF opens a GIPHY search picker: search field → results grid → pick → a single looping tile with remove + GIPHY attribution. A GIF is mutually exclusive with image/video/carousel (see §1). States: picker (results) · loading · empty results · attached tile.

5Link card

When the body contains a URL, a preview card auto-appears under the editor (thumbnail + title + domain) with keep/remove — no button. Pennedly builds the preview. States: detecting/loading skeleton · loaded · multiple links (which one previews) · preview unavailable (tidy domain chip, still removable).

6Poll lower priority

2–4 option rows + a duration select. Included for completeness; lower priority than the media attaches above.

7Thread interplay

When the post is split into parts (a --- line), media rides the first part only. The media block sits under Post 1 with an “attached to the first post” cue, and each part keeps its own 500-char budget.

＊Motion & alt-text

Reduced motion

  • The attached GIF tile and GIPHY results don’t auto-animate under prefers-reduced-motion: reduce — they show a still frame with the GIF chip.
  • Upload progress rings/bars and picker skeletons stop animating; the static state remains.
  • No motion is required to understand any state.

Alt text everywhere

  • Every attached image and video exposes an ALT affordance; empty vs filled (success + check) is obvious at a glance.
  • The sheet’s textarea is the accessibility description, saved per attachment and carried to publish.
  • Controls (remove, drag, play) carry aria-label; decorative scrim chips are aria-hidden.
Guardrails. No audio attach anywhere. GIF is text-only and exclusive with image/video/carousel — the toolbar makes that obvious. Video processing (Threads-side) is publish-time, not on this screen. The shipped image idiom is preserved, not regressed.

  • Toolbar (Image · Video · GIF · Poll) sits below the editor; attachments preview between editor and footer — shipped placement.
  • GIF is exclusive with image/video/carousel: chips disable with a hint in both directions; never silently fails.
  • Images: empty · 1 · multi/carousel · reordering (drag) · uploading · error; per-thumb remove · drag · ALT (empty/filled).
  • Video: empty · uploading % · ready (play · duration · ALT) · error; inline MP4/MOV ≤5 min ≤1 GB hint; processing noted as publish-time.
  • GIF: GIPHY picker (search · results · loading · empty) → single looping tile + attribution + remove.
  • Link card auto-appears from a URL: detecting · loaded · multiple · unavailable (tidy chip, still removable).
  • Alt-text sheet: empty trigger + filled (checked); description per image/video.
  • Poll (low priority): 2–4 options + duration.
  • Thread interplay: media rides the first part; an “attached to the first post” cue is shown.
  • No audio attach anywhere on this screen.
  • Rendered for the web column AND phone 390px, light AND dark; mobile inputs ≥16px, targets ≥44px.
  • New icons (image, video, gif, poll, drag, play, upload) noted for icons.tsx; no new tokens.
  • Reduced-motion honored; alt-text available everywhere media is attached.
