Pennedly · Mobile spec · Studio — thread chains

Thread chains /app — phone

The phone version of thread chains on the draft card. A line of only --- splits the body into parts (≤500 each); the chain posts as a lead post + chained replies. Edit mode is the editor + a “New part” pill + per-part counters that wrap; view mode is a “Thread · N” badge over full-width stacked part cards. Everything is thumb-reachable: the pill, counters and footer buttons are ≥44px, the editor is ≥16px. Same states, tokens and copy as the desktop spec — only the layout adapts below 600px. Every frame is the real component layer at 390px (checked at 360), light and dark.

studio-thread.css pennedly-mobile.css StudioParts.tsx studio-icons.jsx ds/tokens.css
What doesn’t change. A thread is the same draft card when the body has --- parts. Each part ≤500; an over-limit part visibly blocks approve/publish (never truncated). Media rides the lead part only. New icon: IcThread (three beads on a thread) — flagged for icons.tsx in the desktop spec.

1Identity & placement

A thread renders on the draft card in the feed, between the header and the action footer. Here it is in full context: top bar, the filter row, and a thread card in view mode with its stacked parts.

2Edit · single post

Single-post edit: the 16px editor, the normal char-meter, and the ≥44px “New part” pill that turns it into a thread.

3Edit · thread (2–3 parts)

With --- parts the counters replace the char-meter and wrap across the narrow width; the “New part” pill sits alongside. Separators read literally in the editor.

4Edit · a part over 500

An over-limit part’s counter goes danger/bold, an inline hint appears, and Save (with downstream Approve/Publish) is blocked until it’s trimmed.

5View · thread draft

Read mode: a “Thread · 3” badge over full-width stacked part cards, chained by a connector; the two-tier foot is ⋯ + Approve.

6View · published

Published reads muted, with stats and an “Open in Threads” link that grows to fill the action row.

7Thread + media (interplay)

Media rides the lead part only — the lead card shows the media + an “attached to the first post” cue; follow-up parts stay text-only.

8Localization & 360px

All copy localizes into 8 locales; DE/RU run ~30–40% longer. Counters use tabular figures and wrap; “Part N” + the “Thread · N” badge never clip. At 360px the same rules hold — the part cards just get ~30px narrower.

✓Checklist

  • Thread renders on the draft card in the feed; same card as a single post with --- parts.
  • Edit · single: 16px editor + normal char-meter + ≥44px “New part” pill.
  • Edit · thread: --- reads literally; per-part counters wrap; pill alongside.
  • Edit · over 500: counter danger/bold + hint; Save + Approve/Publish blocked; never truncates.
  • View · draft: “Thread · N” badge + full-width stacked part cards, chained; lead tagged.
  • View · published: muted + stats + “Open in Threads” (grows).
  • Thread + media: media on the lead only + “attached to the first post” cue; follow-ups text-only.
  • Counters tabular; “Part N” + badge wrap; sanity-checked at 360px.
  • Inputs ≥16px, targets ≥44px; correct in light and dark; no hardcoded colour.
