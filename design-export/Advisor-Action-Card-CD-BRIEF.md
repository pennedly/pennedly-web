## Идея (что строим)

Советник Pennedly превращается в **слой действий «в один клик»** над всей
платформой. Автор пишет естественной фразой совет-или-задание, советник отвечает
прозой И прикладывает **карточку-действие** с превью того, что изменится, и одной
кнопкой **«Применить»**. Клик применяет изменение через уже существующую
операцию платформы.

Нам нужен **ОДИН переиспользуемый паттерн «карточка-действие»** (единый корпус +
типизированное содержимое), а НЕ N разных карточек. Действий будет много и они
будут расти; все должны выглядеть как один компонент с разным наполнением.

## Каталог действий (что рисовать примерами)

Нарисуй общий корпус + покажи его на **5 конкретных типах** (это первый набор,
дальше растёт):

| Тип | Пример фразы автора | Что показывает карточка | Кнопка | Режим/тон |
|---|---|---|---|---|
| `routine` — рутина постинга | «постить 3×/день про рыбалку в разное время» | заголовок + расписание «3 поста/день · ~9:00, 14:00, 20:00» + тема + «в голосе» | «Создать рутину» | на ревью: каждый пост черновиком |
| `auto_replies` — автоответы | «отвечай только на вопросы, но не на смайлики» | «Автоответы: на вопросы · до 10/день · пропускать пустые реакции» | «Включить» | применится сразу, откат в настройках |
| `voice_rule` — правило голоса | «пиши короче и без смайликов» | добавляемое правило одной-двумя строками «Без эмодзи. Держи посты короткими.» | «Применить» | применится сразу, откат в Голосе |
| `schedule_post` — написать+запланировать | «напиши пост про запуск и поставь на вторник 18:00» | превью черновика (2-3 строки) + «во вторник, 18:00» | «Запланировать» | черновик на ревью в Календаре |
| `cadence` — сменить расписание | «перенеси вечерние посты на утро» | «Было: 20:00 → Станет: 9:00» (до/после) | «Применить» | применится сразу |

Одна реплика советника может нести **несколько** действий (задание «настрой мне
автопостинг и автоответы» → две карточки подряд) — паттерн должен чисто
складываться в стопку.

## Корпус карточки (единый для всех типов)

- **Шапка**: иконка типа + короткий тип-чип («Рутина» / «Автоответы» / «Правило
  голоса» / «Пост» / «Расписание») + **заголовок** действия.
- **Тело-превью**: 1–4 строки «что изменится» (иконка + короткий факт), где
  содержимое зависит от типа (расписание, аудитория, правило, время…). Для
  до/после (`cadence`, `voice_rule`) — компактная пара «было → станет».
- **Строка «На основе:»** (опционально) — если действие обосновано данными
  («на основе: просмотры за 7д»), тихая подпись с искрой.
- **Плашка режима** — заметная, но спокойная: для `routine`/`schedule_post` —
  «На ревью: пост идёт черновиком на подтверждение»; для конфиг-действий
  (`auto_replies`/`voice_rule`/`cadence`) — «Применится сразу · откат в
  <разделе>». Тон успокаивающий.
- **Строка профиля** (только ПОРТФЕЛЬНЫЙ советник `/app/account/advisor`): аватар
  сети + `@handle`, какой профиль затронет. В профильном советнике профиль
  очевиден — строку не показывать.
- **Действия**: основная кнопка с **глаголом по типу** («Создать» / «Включить» /
  «Применить» / «Запланировать») + вторичная **«Настроить»** (уводит в
  соответствующий редактор, предзаполненный этим предложением) + тихая «Отмена».

Карточка ВЕСОМЕЕ обычных подсказок «Открыть в Студии» (акцентная кромка/иконка),
потому что применяет реальное изменение, но живёт В ПОТОКЕ чата, НЕ модалка.

## Состояния (все; свет + тьма; десктоп + мобайл)

1. **Предложено** (дефолт) — как выше, кнопки активны.
2. **Применяется** — основная кнопка в загрузку (спиннер + «Применяю…»), карточка
   disabled, лэйаут не дёргается.
3. **Применено** (успех) — карточка сворачивается в тихую строку: галочка +
   «Готово: <что сделали>» + ссылка в нужный раздел («Открыть в Автопилоте» /
   «…в Голосе» / «…в Календаре» / «…в настройках ответов»). Больше не форма.
4. **Ошибка** — инлайн-строка на `--color-danger` + «Повторить»; карточка
   возвращается в «Предложено».
5. **Мягкое предупреждение** (опц.) — тихая подпись под превью, когда применение
   что-то затронет побочно (напр. рутина «поднимет лимит постов до N/день»). Это
   не ошибка, а честность.

## Данные (контракт — рисуй по этим полям)

Советник возвращает опциональный `actions[]` рядом с обычным ответом; каждое:
```json
{
  "type": "routine|auto_replies|voice_rule|schedule_post|cadence",
  "kind_label": "Рутина",
  "icon": "...",
  "title": "Посты про рыбалку",
  "summary": [                       // 1..4 строк «что изменится»
    { "icon": "clock", "text": "3 поста в день · ~9:00, 14:00, 20:00" },
    { "icon": "tag",   "text": "тема: рыбалка" },
    { "icon": "nib",   "text": "в голосе аккаунта" }
  ],
  "change": null,                    // либо {before, after} для до/после
  "grounded": null,                  // либо «на основе: …»
  "mode_note": "На ревью: каждый пост черновиком",
  "apply_label": "Создать рутину",
  "applied_link_label": "Открыть в Автопилоте",
  "configurable": true,              // показывать «Настроить»
  "target_account": { "handle": "field.co", "network": "threads" }  // портфельный; null = единственный профиль
}
```
Правило честности: рисуем только пришедшие поля. Нет `target_account` → строку
профиля не показываем; нет `grounded` → строку «на основе» не показываем; есть
`change` → рисуем до/после вместо/в дополнение к `summary`.

## Правила макета (критерии приёмки)

- ОДИН корпус, типы = наполнение. Несколько карточек в одной реплике складываются
  вертикально, каждая самодостаточна.
- Однострочники (заголовок, строки summary, `@handle`, лейблы кнопок) не
  переносятся ни на какой ширине; усечение многоточием как крайняя мера.
  Доказать 390 / 320.
- Обе темы; реальные логотипы сетей (`networks.tsx`); аватар с монограммой.
- Ревью-копия РУССКАЯ, контейнеры держат 8 локалей (немецкий ~1.3–1.5×); одно
  состояние с немецкими строками. Все строки через i18n-ключи (`adv.*`).
- Мобайл: карточка во всю ширину, кнопки ≥44px, основная приоритетна.

## Чего НЕ делать

- Не модалка/визард — инлайн-карточка в потоке чата.
- Не показывать весь конфиг (триггеры/условия/пороги) — это делает «Настроить»,
  уводя в редактор. Карточка = короткое превью + 1 клик.
- Не выдумывать типы/поля вне контракта. Разрушительное (удалить/дисконнект/
  биллинг) картами НЕ применяется — таких типов в каталоге нет.
- Дефолт для постинга — «на ревью» (ask), НЕ авто-постинг.

Обновлённые `Account-Advisor-SPEC.html` + `Advisor-SPEC.html` (или отдельный

портфельный · локаль · тема), консистентно с эталоном чата, готово к 1:1.

## После возврата CD (не для CD)

Бэкенд строится параллельно (завтра+): каркас `actions[]` в `_parse_reply` +
диспетчер по типам, где каждый тип применяется через СУЩЕСТВУЮЩИЙ защищённый
эндпоинт (рутина=создание сценария, автоответы=политика ответов, правило=правка
голоса, пост=черновик+расписание, расписание=правка сценария). Порядок стройки:
каркас + `routine` → `auto_replies` → `voice_rule` → `schedule_post` → далее.
Каталог + приоритет зафиксированы в auto-memory [[project_advisor_routines]].
