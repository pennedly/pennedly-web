# CD-бриф — «История изменений»: что Pennedly поменял за меня

> Готов к вставке в Claude Design. Вставь всё, что ниже линии. Это НОВЫЙ экран
> в зоне аккаунта (не топ-уровень навигации). Бэкенд уже в проде: единый журнал
> `applied_changes` пишет каждое применённое предложение из всех источников;
> API `GET /accounts/{id}/applied-changes` (постранично, свежие сверху).
> Дизайн-система: `ds/tokens.css` (ink-on-paper, один акцент, обе темы).

---

## Идея (что строим)

Pennedly всё чаще меняет вещи ЗА пользователя в один клик: Агент создаёт
рутины и правила, проверка Голоса применяет фиксы, недельный аудит правит
промпты. Пользователю нужен один ответ на вопрос **«что Pennedly поменял за
меня?»** - единая лента всех применённых изменений с деталями и (позже)
откатом. Сейчас каждая поверхность держит свою мини-историю или не держит
никакой; эта лента становится общим журналом доверия.

## Правда о данных (рисовать под неё)

Каждая запись журнала несёт:
- **источник** - одна из трёх поверхностей (список будет расти):
  `advisor_action` («Агент»), `voice_lint` («Голос»), `audit` («Аудит»);
- **тип** внутри источника (напр. рутина / автоответы / правило голоса /
  запланированный пост / список тем; фикс поля / удаление пункта / интро;
  вид аудит-правки);
- **подпись** - одна человеческая строка («Кухонные истории», «Voice fix:
  set_field → examples», заголовок аудит-правки);
- **payload** - структурные детали применённого (параметры действия, ссылки
  на созданный сценарий / старую и новую версию голоса);
- **кто применил + когда**;
- **статус отката**: сейчас у ВСЕХ записей откат недоступен (фаза отката
  бэкенда ещё впереди), но дизайн должен заложить все три состояния:
  «можно откатить», «откат недоступен + почему», «откачено {дата}».

## Размещение и вход

- Экран живёт в зоне аккаунта. НЕ новый пункт основной навигации (она уже
  плотная). Точки входа: строка-ссылка в «Настройках» аккаунта («История
  изменений») и тихая ссылка с экрана Агента (рядом с местом, где действия
  применяются). Предложи, как красиво дать вход, не раздувая навигацию.

## Анатомия записи

- **Строка-запись** (свёрнутая): чип источника («Агент» / «Голос» / «Аудит»,
  каждый со своей иконкой, но один спокойный тон - без светофора), подпись,
  тип тихим текстом, время («сегодня 14:02» / «3 июля»).
- **Раскрытие** (тап/клик): человеческие детали из payload - для действия
  Агента это параметры («3 поста в день · тема: рыбалка · в голосе»), для
  фикса Голоса «что поменялось» (поле/секция, старая → новая версия голоса),
  для аудита - суть правки. Плюс ссылка «Открыть» на живой объект (рутина в
  Автопилоте, версия Голоса, аудит).
- **Зона отката** в раскрытии: три состояния из «Правды о данных». Откат -
  ДЕСТРУКТИВНОЕ действие: кнопка спокойная, с подтверждением (мини-диалог
  «Откатить {подпись}? Вернётся прежнее состояние»).

## Состояния (нарисовать все)

1. Лента со смешанными источниками (8-10 записей: Агент × несколько типов,
   Голос, Аудит), свежие сверху, группировка по дням.
2. Пустое состояние: журнал ещё пуст («Здесь появится всё, что Pennedly
   применит по твоему клику») + мягкий ход к Агенту.
3. Раскрытая запись каждого источника (3 варианта деталей).
4. Запись «откачено» (приглушённая, с датой отката).
5. Запись «откат недоступен» с причиной («изменение перекрыто более новым» /
   «необратимое действие») + ссылка на текущий объект.
6. Диалог подтверждения отката + busy.
7. Пагинация: кнопка «Показать ещё» внизу.
8. Мобильная версия ленты + раскрытия + диалога.

## Ограничения

- Обе темы (light/dark), только токены из `ds/tokens.css`, один акцент.
- Тон: журнал доверия, не лог для инженера - без JSON на экране, payload
  всегда переведён в человеческие факты.
- Тексты РУ по умолчанию; без длинных тире.
- Фильтры по источнику НЕ рисовать в первой версии (лента короткая); заложи
  место, куда они встанут позже, и упомяни это в SPEC.
- Итог: `Applied-Changes-SPEC.html` + `Applied-Changes-Mobile-SPEC.html`
  (или одним файлом с мобильной секцией, если так чище).
