## Идея (что строим)

Упоминание в Threads — пост постороннего, который тегнул аккаунт. Владелец хочет
автоматизировать реакцию НЕ на «все упоминания подряд», а под конкретную ЦЕЛЬ,
которую он описывает СВОИМИ СЛОВАМИ.

Пример-флагман: бренд генерации детских фото. Кто-то тегает его, прикрепляет фото
мамы и папы и просит прислать фото будущего ребёнка. Владелец создаёт рутину:
«когда меня упоминают с фото и просят показать ребёнка → ответить сгенерированным
фото». Или проще: «на все вопросы про мой марафон отвечать в моём голосе».

Рутина упоминаний = связка **ЦЕЛЬ** (интент словами) + **УСЛОВИЕ** (какие
упоминания) + **ДЕЙСТВИЕ** (что сделать) + **РЕЖИМ** (сам или спросить).
Конструктор должен дать это собрать без технаря, гибко, а не выбором из пресетов.

## Правда о данных (рисовать строго под неё)

Рутина упоминаний — это `on_mention`-сценарий. Что он реально несёт в бэкенде:

- **`trigger_cfg.intent`** — ЦЕЛЬ словами владельца (свободный текст, до 500
  символов). Ядро фичи: движок один раз прогоняет каждое входящее упоминание и сам
  решает, подходит ли оно под эту цель. Пусто = рутина-catch-all («ответить на все
  безопасные упоминания, не подошедшие под другие рутины»).
- **`trigger_cfg.requires_media`** — требование к вложению: `any` (неважно) /
  `image` (только с фото) / `none` (только текст).
- **`publish_mode`** — `auto` (Pennedly сам публикует ответ) или `ask`
  («Спроси меня» → готовит черновик, публикуешь ты). Ровно тот же бейдж режима,
  что уже на карточках рутин постинга.
- **`reply_instruction`** — слоистая подсказка «как отвечать» (свободный текст,
  опционально).
- **overrides** аудитории / лимита / частоты / тихих часов — по умолчанию
  наследуются из «Правила дома» (Layer-3, как у рутины-дежурства).

Жёсткие гарантии движка (заложить в тон, НЕ давать их обойти в UI):

- Авто-ответ возможен только на AUTO-safe упоминания (вопрос / похвала /
  нейтральное). Упоминания из зоны «Требуют вас» (жалоба / лид / провокация /
  конкурент) и спам-семейство рутина НИКОГДА не трогает сама — они остаются
  владельцу в очереди. Даже если цель широкая, бот не полезет отвечать на публичную
  жалобу сам.
- Каждое упоминание уходит максимум в ОДНУ рутину (движок выбирает подходящую по
  цели). Рутина без цели — fallback «ответить на всё остальное безопасное».

Чего в бэкенде ПОКА НЕТ (пометить в UI как «Скоро», НЕ рисовать рабочим):

- **Генерация картинки в ответ** (кейс «прислать фото ребёнка»). Требование «с
  фото» и матч по цели — реальны уже сегодня; само действие «ответить
  сгенерированным изображением» — Фаза 4. В конструкторе покажи это как ВЫБОР
  действия с меткой «Скоро» (заблокирован).

## Структура

### 1. Хаб рутин упоминаний (живёт в «Автопилоте»)

Список рутин упоминаний карточками (в стиле рутин постинга / `Autopilot-Unified`).
Карточка: иконка + название + строка-суть человеческим языком (собранная из цели +
условия, «на что срабатывает»), бейдж режима (авто / спросить, как уже есть),
вкл/выкл, «Изменить». Отдельно — «рутина по умолчанию» (без цели, ловит всё
остальное безопасное), визуально помечена как fallback. Кнопка «+ Новая рутина
упоминаний». Пустой хаб = приглашение создать первую рутину.

### 2. Конструктор (создание/редактирование) — «карточка-рецепт»

Собери связным «рецептом-предложением» (как редактор сценариев), слоями от простого
к глубокому:

- **Триггер (зафиксирован):** «Когда меня упоминают…». Не меняется, это рутина
  упоминаний.
- **Цель (ядро, НОВОЕ):** большое поле «Опиши цель упоминания своими словами» с
  плейсхолдером-примером («прислали фото двух людей и просят показать их будущего
  ребёнка» / «спрашивают про мой марафон и хотят записаться»). Счётчик до 500.
  Микро-подсказка: «Pennedly сам поймёт, какие упоминания под это подходят».
  Чекбокс «Отвечать на любые безопасные упоминания» = цель пустая (catch-all).
- **Условие по медиа:** сегмент «Вложение»: «Неважно» / «Только с фото» /
  «Только текст».
- **Действие:** «Ответить в моём голосе» (реально) + отдельным вариантом «Ответить
  сгенерированным фото» с меткой «Скоро» (заблокирован, с пояснением). Под
  действием — необязательное поле «Как отвечать» (`reply_instruction`).
- **Режим:** бейдж/переключатель авто / «Спроси меня» — переиспользуй
  `Autopilot-Publish-Mode`.
- **Лимиты (свёрнуто, продвинутое):** «Наследовать Правила дома» по умолчанию +
  разворот с override аудитории / лимита / частоты / тихих часов (Layer-3, как у
  дежурства).
- **Живой предпросмотр** строкой: «Когда меня упоминают с фото и просят показать
  ребёнка, Pennedly [сам] ответит [сгенерированным фото · Скоро]».

## Состояния (нарисовать все)

1. Хаб: 2-3 рутины упоминаний + «рутина по умолчанию»; отдельно пустой хаб.
2. Конструктор: базовый вид (только цель + действие + режим), развёрнутый (медиа +
   инструкция + лимиты).
3. Рутина «под интент» (цель заполнена, «только с фото», авто) и рутина-catch-all
   («на все безопасные», без цели).
4. Действие «Ответить сгенерированным фото · Скоро» — заблокированный вид +
   пояснение.
5. Карточка рутины в хабе в трёх режимах: авто / «спросить» / выключена (бейджи как
   на постинге).
6. Мобильная версия хаба + конструктора.

## Ограничения

- Обе темы (light/dark), только токены `ds/tokens.css`, один акцент.
- Это НЕ новый визуальный язык, а сборка из готовых кирпичей под упоминания:
  редактор-рецепт, бейдж режима публикации, «Правила дома» / Layer-3.
- Тон: «собери помощника под конкретную цель» — простое сверху, глубина по желанию.
- Реально сегодня = авто-ответ в голосе / черновик в ask / требование к медиа /
  матч по цели. «Ответить картинкой» — только «Скоро».
- НЕ давать в UI выбрать авто-ответ на жалобу / лид / провокацию — это против
  гарантии движка. Если объясняешь: «на такое Pennedly не отвечает сам, оно ждёт
  вас в очереди».
- Тексты РУ по умолчанию; без длинных тире.
- Итог: `Mention-Routines-SPEC.html` + `Mention-Routines-Mobile-SPEC.html`.
