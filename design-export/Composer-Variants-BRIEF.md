> CD предлагает 5 принципиально разных вариантов, Захар выбирает
> победителя (или гибрид), затем отдельный follow-up бриф на полный
> `Studio-Composer-SPEC.html` + `-Mobile-SPEC.html` по обычному

**Контекст.** Верхний блок Студии («Создать») — точка входа во всю
генерацию: бриф свободным текстом → N черновиков твоим голосом.
Сейчас это карточка: аватар активного Threads-аккаунта + однострочный
autogrow-textarea («О чём написать? Тема, острое мнение, ссылка…»),
под ним скролл-ряд чипов (✨Идеи + 4 подсказки-заготовки), справа
select «N черновиков» + кнопка «Сгенерировать». Работает, но выглядит
как дженерик «инпут с чипами» — основателю не нравится, хочет увидеть
блок, придуманный заново. Это самый главный блок продукта: он должен
читаться как «моё перо», а не как форма.

Дизайн-система остаётся: токены `ds/tokens.css` (ink on paper, один
акцент, никакого нового визуального языка, ни одного хардкод-hex,
дарк = те же токены). Переосмысляется СТРУКТУРА и МЕТАФОРА блока,
не система.

## Задача

**5 вариантов, каждый — отдельный концепт с нуля**, не 5 вариаций
отступов одного макета. У каждого: короткое имя, 2–3 предложения
«почему так» (какую проблему концепт решает), и отрисованные
состояния (список ниже). Различаться должны иерархией и метафорой:
что главное — поле? идеи? действие? Разные ответы = разные варианты.

Оси для размышления (НЕ обязательные, можно свои):
- **Идеи-вперёд**: подсказки/идеи — главный контент блока, поле
  вторично («не знаешь, о чём писать — мы уже знаем»).
- **Лист бумаги**: композер как мини-страница/каретка, письмо как
  физический акт (бренд «ink on paper» буквально).
- **Командная строка / разговор**: одна строка-приглашение, всё
  остальное появляется по мере ввода (progressive disclosure).
- **Компактная планка**: свёрнутый однострочник, разворачивается в
  полноценный композер по фокусу.
- **Станок/пульт**: бриф + настройки (сколько, какие заготовки) как
  единый «пульт генерации» с явным осязаемым CTA.

## Что блок обязан уметь (инварианты — в КАЖДОМ варианте)

1. **Бриф свободным текстом**, autogrow, до ~500 символов полезной
   длины; Cmd/Ctrl+Enter = сгенерировать. Плейсхолдер —
   `studio.composer_placeholder` («О чём написать? Тема, острое
   мнение, ссылка…», можно предложить новый текст).
2. **Идеи** («Идеи твоим голосом»): вызов из блока; приходит до 8 идей
   вида **hook (жирный) + angle (приглушённый)**; тап по идее
   заполняет бриф хуком; есть «Ещё идеи» (refresh) и закрыть;
   подсостояния: загрузка / список / пусто / ошибка+ретрай.
   Это фирменная фича — в текущем виде она прячется в ряду чипов;
   вариантам разрешено (и желательно) дать ей другой вес.
3. **4 быстрые заготовки** (тап = заполнить бриф этим текстом):
   «Урок этой недели» / «Отреагировать на тренд» / «Ответить на
   упоминания» / «Непопулярное мнение». Форму подачи можно менять
   (чипы не обязательны), поведение — нет.
4. **Сколько черновиков**: 1–4, дефолт 3, запоминается. Нативный
   select не обязателен — любой контрол, но одно касание/клик.
5. **Сгенерировать** — главный CTA; disabled при пустом брифе и при
   отсутствии аккаунта. После клика блок переходит в busy.
6. **Busy-состояние**: блок целиком становится «пишу N постов твоим
   голосом» (сейчас: перо-анимация + пульсирующие точки). Можно
   переосмыслить, но состояние обязано жить внутри блока (страница
   не прыгает) и уважать reduced-motion.
7. **Личность**: видно, ОТ КОГО пишем (аватар активного
   Threads-аккаунта; на мобиле сейчас скрыт — решай сам).
8. **`?brief=` от Советника**: бриф может прийти заполненным извне —
   вариант должен нормально выглядеть с длинным готовым текстом.
9. **First-run деградация**: у блока есть выключенная версия-превью
   под hero «настрой голос» (desaturate + opacity, не интерактивна).

## Правила макета (критерии приёмки — нарушение = переделка)

- **ПРАВИЛО 1**: семантически однострочные элементы (лейблы кнопок,
  чипы, счётчики) не переносятся ни на какой ширине; дизайнить так,
  чтобы перенос был невозможен; многоточие — страховка, не дизайн.
  Доказать на узком десктопе / 390 / 320.
- **ПРАВИЛО 2**: ревью-копия русская, контейнеры держат 8 локалей
  (немецкий — стресс-тест, резерв ~1.3–1.5× к русскому); показать
  одно состояние с немецкими строками.
- Все строки — через i18n-ключи (существующие `studio.*` где
  совпадает смысл), EN-фоллбэк, русский не хардкодить.
- Тач-цели ≥44px на мобиле, инпут ≥16px шрифта (iOS-зум).
- Обе темы (light + dark) на каждый вариант.

## Реальные данные (не «рыба»)

Идеи для панели (hook + angle), рисуй эти:
```json
[
  {"hook": "Никто не читает ваш контент-план. И это нормально.", "angle": "почему система важнее календаря"},
  {"hook": "Я удалил половину постов — охваты выросли.", "angle": "личный кейс, цифры до/после"},
  {"hook": "Тренды убивают ваш голос быстрее, чем молчание.", "angle": "непопулярное мнение + чем заменить"}
]
```
Бриф-пример для filled-состояния: «Почему маленькие аккаунты
получают больше ответов, чем большие. Дерзко, без цифр, 2 абзаца».

## Состояния в каждом варианте (все рисуются и подписываются)

Десктоп (~960px «Создать»-колонка): пустой / заполненный / фокус /
busy («пишу 3 поста…») / идеи-открыты (список) / идеи-загрузка /
disabled (нет аккаунта). Мобайл (~390px, держится до 320): ключевые
пустой + заполненный + идеи-открыты. Для победителя полный мобильный
SPEC будет отдельным брифом — здесь достаточно доказать, что концепт
живёт на телефоне.

## Чего НЕ делать

- Не менять ничего вокруг блока (табы черновиков, фильтры, шелл).
- Не добавлять функций, которых нет (медиа-аплоад в композере, выбор
  тона, планирование из композера — этого здесь нет и не будет).
- Не выдумывать новый визуальный язык/цвета/шрифты — только токены.
- Не делать 5 скинов одного макета — 5 концептов или меньше, если
  честно сильных меньше (лучше 4 сильных, чем 5 с филлером).

## Дельверабл

Один файл **`Composer-Variants-SPEC.html`** в стиле остальных SPEC
design-export: 5 секций (V1…V5), в каждой — имя концепта, короткое
«почему», отрисованные состояния из списка выше (десктоп + мобильная
проба), переключатель темы, подписи состояний. Самодостаточный HTML
(как `Studio.html`), токены из `ds/tokens.css`.
