## Что мы делаем

Финальная фаза Pennedly: **визуальный редизайн всего веб-приложения** под новый
«холодный» стиль, который уже сделан в Claude Design. Меняем **только вид**, не
структуру и не логику. Бэкенд/API/флоу не трогаем — приложение полностью рабочее
и в проде.

   Читать перед нетривиальными правками; обновлять §6/§7/§13/§14 в том же коммите.

## Жёсткие правила (НЕ нарушать — иначе ломается работающее)

- **Семантические токены, не хардкод цветов.** Палитра в `src/app/globals.css`
  (`@theme`): `bg-bg`, `bg-surface`, `bg-surface-2`, `text-text`,
  `text-text-muted`, `text-text-subtle`, `border-border`, `bg-primary`/
  `text-primary-foreground`, плюс `success`/`warning`/`danger` (+`-foreground`).
  Тёмная тема = класс `.dark` переопределяет те же токены. **Любой новый цвет —
  только как токен**, иначе тёмная тема сломается.
- **Две темы всегда.** Светлая + тёмная. Проверять обе на каждом экране.
- **8 языков.** Весь текст идёт из i18n-каталога (`src/lib/i18n`), НЕ хардкодить
  строки. RU/DE длиннее EN на ~30% — раскладка не должна ломаться на длинных
  строках. Появится новый текст → новый ключ в `en` + `ru`, остальные 6 — в
  shrink-only baseline (см. ниже про CI-проверку паритета).
- **Общий каркас.** Все `/app/*` экраны живут в одном shell (сайдбар + верхняя
  панель), `src/app/app/layout.tsx` + `Sidebar`. Сверстать каркас ОДИН раз,
  дальше каждый экран — только контентная область.
- **Структуру экранов не менять.** Это рестайл, не переписывание. Те же роуты,
  те же данные, те же состояния (loading/empty/error у каждого экрана — см.
  SCREEN_MAP). Меняется внешний вид, не что экран делает.
- **API-контракты не трогать.** Хуки/клиенты, что ходят на бэкенд, остаются как
  есть — это только presentation-слой.

## Что НЕ входит в редизайн

- Бэкенд (он в `../pennedly-backend`, отдельный репозиторий, готов и в проде).
- Логика, роутинг, флоу данных, авторизация.
- Перевод 6 локалей (uk/de/es/fr/it/pt) — отдельная задача с ревью Захара.
- Новый экран billing/upgrade — его в дизайне пока нет; спроектировать позже.

## Гардрейлы, которые уже есть (не сломать)

- **CI-паритет i18n:** `scripts/check-i18n-parity.mjs` + `.github/workflows/
  i18n-parity.yml`. Падает, если в локали появился непереведённый ключ вне
  shrink-only baseline (`scripts/i18n-parity-baseline.json`). Добавил ключ →
  переведи в en+ru, остальные запиши в baseline (`npm run check:i18n -- --update`).
- **Smoke-тесты экранов:** `tests/pages-smoke.spec.ts` (Playwright) — каждый
  `/app/*` экран должен рендериться без ошибок. После рестайла экрана прогнать.
- **Сборка:** `npm run build` должна проходить. Тесты: `npm run test:e2e`.

## Рабочий ритм (предлагаемый)

1. Сначала каркас: `00-shell` + общие компоненты (сайдбар, AccountSwitcher,
   LanguageSwitcher, модалка публикации, тосты, пустые состояния, спиннеры).
2. Потом экраны по одному, по номерам SCREEN_MAP. Каждый: рестайл → обе темы →
   i18n → smoke-тест зелёный → коммит.
3. В конце: визуально-регрессионные скриншот-тесты (Phase 7 exit-criterion).
